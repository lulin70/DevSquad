## 新功能详解

### P12.3.1 — ModuleFiber 状态机

**模块**: `scripts/collaboration/module_fiber.py` (~250 行)

**核心数据结构**:

```python
from scripts.collaboration.module_fiber import (
    FiberState, ModuleFiber, ModuleFiberRegistry,
    get_call_counter_er,
)

# 6 状态枚举
class FiberState(str, Enum):
    INACTIVE = "inactive"
    ACTIVATING = "activating"
    ACTIVE = "active"
    DEACTIVATING = "deactivating"
    FAILED = "failed"
    DEGRADED = "degraded"

# 状态机注册表
registry = ModuleFiberRegistry()
fiber = registry.register("artifact_store", depends_on=("effect_registry",))
fiber.transition(FiberState.ACTIVATING, reason="dispatcher init")
fiber.transition(FiberState.ACTIVE, reason="init complete")
print(fiber.is_usable())  # True
```

**特性**:
- `ALLOWED_TRANSITIONS` 表驱动 FSM，非法转移被拒绝 + 记录 warning
- 自愈 retry：`ACTIVATING → FAILED` 自动 retry 1 次（100ms backoff），仍失败进入 `DEGRADED` + 写 `last_error` + Prometheus 指标
- `transition_history` 字段记录每次状态转移（from/to/reason/timestamp）用于审计
- `ModuleFiberRegistry` thread-safe（`threading.Lock`）
- Anti-ghost `_call_counter_er` + `get_call_counter_er()` (V4.5.4 命名统一为 `_er` 后缀)

**测试**: 60 单元测试 (5 状态 × 4 转移 × 3 模块 + self-healing + anti-ghost)

### P12.3.2 — Coeffect 协议 + Resolver

**模块**: `scripts/collaboration/coeffect.py` (~280 行)

**Coeffect Provider Protocol**:

```python
from scripts.collaboration.coeffect import CoeffectProvider, with_coeffect

@with_coeffect("artifact_store", depends_on=("effect_registry",))
class ArtifactStore:
    def __init__(self, root: str | Path | None = None) -> None:
        ...  # 现有代码不变（V4.5.3 lesson #5: 零侵入）

store = ArtifactStore()
assert store.depends_on() == ("effect_registry",)
fiber = store.get_fiber()  # ModuleFiber(module_id="artifact_store", ...)
```

**Coeffect Resolver (3 个公共 API)**:

```python
from scripts.collaboration.coeffect import CoeffectResolver, _StaticProvider

resolver = CoeffectResolver()

# 1. 注册模块（静态或装饰器）
resolver.register(_StaticProvider("effect_registry", ()))
resolver.register(_StaticProvider("artifact_store", ("effect_registry",)))
resolver.register(_StaticProvider("artifact_store", ("effect_registry",)))

# 2. 拓扑排序（Kahn）
order = resolver.resolve_activation_order()
# → ["effect_registry", "artifact_store", ...]

# 3. DFS cycle 检测
cycle = resolver.detect_cycle()
# → None 或 ["a", "b", "c", "a"]

# 4. dangling 检测
errors = resolver.validate_dependencies()
```

**关键设计 (V4.5.4 lessons #2 + #4)**:
- Kahn 拓扑排序必须**显式** cycle detection（不能依赖隐式 `len(result) != len(modules)` 推断）
- `@with_coeffect` 装饰器零侵入（不改 `__init__`、不加新依赖）
- 失败降级：dispatcher 捕获 `CoeffectCycleError`/`CoeffectDanglingError` → 标记 `DEGRADED` 而非崩溃

**测试**: 20 单元测试 (topological sort 8 + decorator 6 + failure degradation 6 + anti-ghost 2) — V4.5.4 lesson #4 应用：`_call_counter_er` 真实定义在 `module_fiber.py`，本模块 re-import 保持命名一致

### P12.3.3 — Modules CLI

**模块**: `scripts/cli_modules.py` (~200 行) + `scripts/cli.py` 注册 `modules` 子命令组

**用法**:


### P12.3.4 — Dispatcher 全量改造 (D1)

**模块**: `scripts/collaboration/dispatcher.py` + `dispatcher_base.py` + `dispatcher_config.py`

**改动清单**:
1. `dispatcher_base.py` 增加 3 个类型注解: `module_fiber_registry` + `_coeffect_resolver` + `_modules_cli`
2. `dispatcher_config.py` 新增 `Group 11` 字段: `enable_fiber: bool = True` + `enable_coeffect: bool = True` + `enable_modules_cli: bool = True`
3. `dispatcher.py` `__init__` 末尾嵌入 `_activate_v454_modules()` 调用（try/except 整体包裹）
4. `_activate_v454_modules()` 方法：instantiate 3 新模块 → register 11 模块 → resolve 拓扑序 → 按序 activate each with try/except (V4.5.3 lesson #7 best-effort)

**契约**:
- 任意模块 init 失败 → 标记 `DEGRADED` + `last_error` 填充 + log.warning
- 主流程 dispatch 永不因 Fiber/Coeffect 失败而 crash

## P11 运维保障

### ALERT_RULES.md 新增 3 告警
- `DevSquadV454FiberStuckActivating`: fiber 卡在 `ACTIVATING` 状态 > 30s（warning）
- `DevSquadV454FiberDegradedSpike`: 5m 内 > 5 模块进入 `DEGRADED`（critical）
- `DevSquadV454CoeffectResolutionFailure`: `CoeffectCycleError` 或 `CoeffectDanglingError` 累计 > 0（warning）

### RUNBOOK.md 新增 2 个 incident scenarios
- **SC-11**: Fiber stuck in `ACTIVATING` → 步骤 1 跑 `devsquad modules status` 定位卡死模块 → 步骤 2 跑 `devsquad modules retry <module_id>` 手动重试 → 步骤 3 检查 `last_error`
- **SC-12**: Coeffect cycle detected → 步骤 1 跑 `devsquad modules graph` 找到 cycle 节点 → 步骤 2 在源码 `@with_coeffect(depends_on=...)` 修复依赖 → 步骤 3 重启 dispatcher

### ROLLBACK.md 新增 per-module disable flags
- `enable_fiber=False` 关闭 ModuleFiber 激活路径（保留 import）
- `enable_coeffect=False` 关闭 CoeffectResolver 注册 + 拓扑排序（保留模块）
- `enable_modules_cli=False` 关闭 `devsquad modules` 子命令注册
- 三个 flag 独立可关闭，互不影响；不影响 V4.5.3 Artifacts/Effect

## 升级指南

### 安装
```bash
pip install -U devsquad==4.5.4
# 或
git pull origin main  # 拉取 v4.5.4 tag
```

### 配置变更
无需配置变更。所有新功能 opt-in，向后兼容。
新增 `DispatcherConfig` 字段 `enable_fiber`/`enable_coeffect`/`enable_modules_cli` 默认为 `True`，可通过构造参数覆盖。

### 破坏性变更
**无**。所有新模块默认激活但不阻塞主流程（最佳努力模式）：
- 任意模块 init 失败 → `DEGRADED` 状态而非 dispatcher crash
- 拓扑环 → 标记依赖模块 `DEGRADED` + warning log，主流程继续
- 关闭 Fiber/Coeffect：`MultiAgentDispatcher(enable_fiber=False, enable_coeffect=False, enable_modules_cli=False)`
