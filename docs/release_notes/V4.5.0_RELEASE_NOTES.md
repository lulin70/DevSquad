# DevSquad V4.5.0 Release Notes

**Release Date**: 2026-08-03
**Git Tag**: `v4.5.0` (commit `edc3d1a`)
**Theme**: Cross-Session Continuity + Protocol-Native Skills + Action-First Reports

---

## Highlights

V4.5.0 merges V4.4.3 + V4.4.4 + V4.5.0 development milestones into a single release. **10 new features** inspired by 3 external open-source projects, **8 atomic sub-skills** (6 → 8), **8260+ tests passing**.

This release transforms DevSquad's AI team from "invisible black box" to "transparent, traceable professional collaborators" through three pillars:

1. **Cross-Session Continuity** — Agent identity and Scratchpad history persist across sessions
2. **Protocol-Native Architecture** — Skills are discovered and injected via Protocol, not import
3. **Action-First Transparency** — Reports lead with concrete actions, workflow traces show decision paths

---

## What's New (10 Features)

### Pillar 1: Cross-Session Continuity

| Feature | Description | Inspired By |
|---------|-------------|-------------|
| **ScratchpadHistoryStore** | SQLite-backed Scratchpad persistence. Cross-session search via `scratchpad_history_search()`. Analogous to block/buzz Channel history. | block/buzz |
| **AgentIdentity** | Deterministic agent ID (`agent-{role}-{hash}`) persisted across sessions. Audit trail links Worker outputs to specific agent instances. | block/buzz |
| **SessionResume CLI** | `devsquad sessions list` + `dispatch --resume <session-id>`. CheckpointManager already has the data; now it's user-accessible. | open-code-review |

### Pillar 2: Protocol-Native Architecture

| Feature | Description | Inspired By |
|---------|-------------|-------------|
| **SkillProvider Protocol** | Skills discovered/injected via Protocol interface, not direct import. Builtin + MCP providers implemented. Pluggable architecture for custom providers. | block/buzz |
| **FileBundler** | Deterministic file bundling for review mode. Related files (model + migration + test) grouped into review units. Only activates when `mode="review"` AND file count > 5. | open-code-review |

### Pillar 3: Action-First Transparency

| Feature | Description | Inspired By |
|---------|-------------|-------------|
| **OutputStyle** | `output_style='action_first'` in PromptDials. Reports lead with next actions, cap lists at 5, no preamble/recap/closers. Default remains 'detailed' for backward compatibility. | i-have-adhd |
| **WorkflowTrace** | Dispatch reports include "Workflow Trace" section showing task decomposition → assignment → execution → verification path. Users can see what the agent team decided. | block/buzz |
| **GitContext** | `dispatch(git_context=...)` injects current branch, recent commits, open PRs into dispatch context. Workers can see "which branch are we working on". | block/buzz |

### Pillar 4: Documentation & Onboarding

| Feature | Description | Inspired By |
|---------|-------------|-------------|
| **SKILL.md Modular Split** | 1216 → 282 lines (main) + 3 reference docs (MODULE_REFERENCE, SUB_SKILLS, VERSION_HISTORY). Easier to maintain and review. | Internal |
| **VISION Documents** | 3 new docs: `VISION.md` (product vision), `VISION_ORCHESTRATION.md` (Loop Engineering design rationale), `VISION_AGENT_COLLABORATION.md` (agent-as-team-member philosophy). | block/buzz |

## Upgrade Guide

### Breaking Changes

**None.** V4.5.0 is fully backward compatible with V4.4.x.

### New Optional Parameters

| API | New Parameter | Default | Description |
|-----|---------------|---------|-------------|
| `dispatch()` | `git_context` | `None` | Inject Git branch/commit context |
| `PromptDials` | `output_style` | `'detailed'` | Set to `'action_first'` for action-first reports |
| `SkillRegistry` | `set_provider()` | `BuiltinSkillProvider` | Swap to `MCPSkillProvider` for MCP integration |

### Migration Steps

1. `git pull origin main`
2. `pip install -r requirements.lock` (no new dependencies required)
3. (Optional) Try action-first reports: `PromptDials(output_style='action_first')`
4. (Optional) Try session resume: `devsquad sessions list` → `devsquad dispatch --resume <id>`

## Inspirations & Acknowledgments

V4.5.0 features were inspired by analyzing 3 external open-source projects from DevSquad's product vision ("single AI → multi-role team"):

| Project | Insight | Features Adopted |
|---------|---------|------------------|
| [block/buzz](https://github.com/block/buzz) | "Agent as Team Member" — agents with persistent identity, shared workspace, transparent workflow | ScratchpadHistoryStore, AgentIdentity, WorkflowTrace, GitContext, SkillProvider Protocol, VISION docs |
| [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) | AI output format discipline — action-first, cap lists at 5, no preamble | OutputStyle action_first |
| [alibaba/open-code-review](https://github.com/alibaba/open-code-review) | Deterministic engineering × Agent hybrid — file bundling, session resume | FileBundler, SessionResume CLI |

**Design decisions rejected** (to avoid over-engineering):
- Nostr protocol / crypto signatures — DevSquad is Python tool, not decentralized app
- External reflection module — over-design risk, delayed to V5.0.0+
- Benchmark dataset (50 repos) — project-level workload, delayed to V5.0.0+
- Sub-skill independence (6→8 separate skills) — violates "team" metaphor
