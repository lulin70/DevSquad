# DevSquad V4.5.1 Release Notes

**Release Date**: 2026-08-05
**Git Tag**: `v4.5.1`
**Theme**: Approval Gate + Connector Framework + Anti-Ghost E2E

---

## Highlights

V4.5.1 is a PATCH-level release (SemVer compliant) that introduces **2 new modules** and completes **3 ROADMAP items** for V4.5.x. All new modules default to safe, backward-compatible behavior — no API breaking changes, no required configuration.

This release closes the "ghost feature" gap identified during V4.4.0 retrospective work: every new module now ships with `_call_counter` anti-ghost mechanism + E2E test verifying `_call_counter > 0` after `dispatch()`. A "ghost feature" is code that exists, has unit tests passing, but is never actually activated in the dispatch pipeline — V4.5.1 makes this failure mode impossible.

### Three Pillars

1. **User-Level Approval Gate** — External operations require explicit user approval before execution
2. **Connector Framework** — Protocol-based interface for external system integration (GitHub first)
3. **Anti-Ghost E2E Guarantee** — E2E tests prove new modules are activated in dispatch pipeline

### New Modules

### Module 186: ApprovalGate

User-level approval mechanism that wraps external operations (PR creation, issue state changes, PR reviews) with an explicit user approval step. Designed as an opt-in enhancement: when no `approval_callback` is configured, all operations auto-approve (backward compatible).

**Key Components**:
- `ApprovalCallback` Protocol — `Callable[[ApprovalRequest], ApprovalResult]`
- `ApprovalRequest` dataclass — `operation_type`, `description`, `details`, `timestamp`
- `ApprovalResult` dataclass — `approved: bool`, `reason: str`, `timestamp`
- `ApprovalGate` class — main entry point with `request_approval()` method
- `_call_counter` module-level anti-ghost mechanism

**Behavior**:
- No callback configured → auto-approve (backward compatible, existing workflows unaffected)
- Callback raises exception → **fail-closed** (deny operation, record error reason)
- Callback returns `approved=False` → operation denied, reason recorded
- All approval decisions recorded in `_records` list for audit

**Integration**: `MultiAgentDispatcher._activate_approval_gate()` is called in both `early_return` and normal dispatch paths — anti-ghost guarantee that the gate is always exercised.

### Module 187: ConnectorFramework

Protocol-based interface for integrating external systems (GitHub, Jira, Slack, etc.) into the dispatch pipeline. GitHub is the first concrete implementation (`GitHubConnector`), with three execution modes: `api` (REST API with token), `cli` (gh CLI subprocess), and `simulation` (no network, records operations only).

**Key Components**:
- `Connector` Protocol — `create_pr_comment()`, `update_issue_state()`, `submit_pr_review()`, `get_operations()`, `export_markdown()`
- `GitHubConnector` — concrete implementation with api/cli/simulation modes
- `ConnectorOperation` dataclass — `operation`, `target`, `success`, `details`, `timestamp`
- `_call_counter` module-level anti-ghost mechanism

**Mode Selection** (priority order):
1. `simulation=True` parameter → simulation mode (forced; safe)
2. `GITHUB_TOKEN` env var or `token` parameter → api mode
3. `gh` CLI available on PATH → cli mode
4. Fallback → simulation mode

**Safety**: Dispatch pipeline always passes `simulation=True` — no real GitHub API calls during normal dispatch. Users must explicitly instantiate `GitHubConnector(simulation=False)` for live operations.

**Integration**: `MultiAgentDispatcher._activate_connector()` is called in both `early_return` and normal dispatch paths. The connector performs a single simulation-mode probe operation (`create_pr_comment` with `pr_number=0`) to prove the pipeline wiring is alive, then attaches operations to `DispatchResult.connector_operations`.

`DispatchResult` gained 4 new fields:
- `approval_records: list[dict[str, Any]]` — audit trail of approval decisions
- `approval_gate_md: str` — pre-rendered Markdown section

## Anti-Ghost Guarantee

Every new module ships with:

1. **Module-level `_call_counter`** — incremented on every public method call
2. **E2E test asserting `_call_counter > 0`** after `dispatch()` — proves pipeline wiring is alive
3. **CI gate** via `check_module_activation.py` reference (now `test_e2e_dispatch_increments_all_five_counters`)

This prevents the "ghost feature" anti-pattern where code exists, unit tests pass, but the module is never actually called during dispatch. V4.5.1 extends this pattern from V4.4.0 (RiskRegister / ViewpointRegistry / ErrorBudgetTracker / GapAnalyzer / DoraMetricsCollector) to V4.5.1 (ApprovalGate / ConnectorFramework).

## Upgrade Guide

V4.5.1 is a drop-in replacement for V4.5.0 — no migration required.

### Activating New Features (Optional)

**Approval Gate** (user-level approval for external operations):

```python
from scripts.collaboration.approval_gate import (
    ApprovalGate, ApprovalRequest, ApprovalResult,
)

def my_callback(request: ApprovalRequest) -> ApprovalResult:
    # Show UI dialog, return user decision
    user_says_yes = show_dialog(request.description)
    return ApprovalResult(approved=user_says_yes, reason="user decision")

gate = ApprovalGate(approval_callback=my_callback)
result = gate.request_approval(
    operation_type="pr_comment",
    description="Post review comment to PR #42",
    details={"repo": "myorg/myrepo", "pr_number": 42},
)
if result.approved:
    # Proceed with operation
    ...
```

**Connector Framework** (GitHub integration):

```python
from scripts.collaboration.connector_framework import GitHubConnector

# Simulation mode (safe, no network)
connector = GitHubConnector(simulation=True)
connector.create_pr_comment(repo="myorg/myrepo", pr_number=42, body="LGTM")
print(connector.export_markdown())

# Live mode (requires GITHUB_TOKEN env var or token parameter)
import os
connector = GitHubConnector(token=os.environ["GITHUB_TOKEN"])
op = connector.create_pr_comment(repo="myorg/myrepo", pr_number=42, body="LGTM")
if op.success:
    print(f"Comment posted: {op.details}")
```
