# DevSquad V4.5.3 — Release Notes

> **Release date**: 2026-08-22
> **Version**: 4.5.3 (MINOR SemVer compliant — opt-in backward compatible)
> **Iteration**: P12.2 (Artifacts + Effect)
> **PRD**: [docs/prd/V4.5.3_ARTIFACTS_EFFECT_PRD.md](../prd/V4.5.3_ARTIFACTS_EFFECT_PRD.md)

## TL;DR

V4.5.3 引入 5 个新模块，实现 worker 产出持久化、可回滚副作用、审计日志独立查询：

- **ArtifactStore** (P12.2.1)：持久化 7 角色 worker 产出至 `artifacts/{session_id}/{role_id}/{filename}`
- **DispatchEffect Protocol** (P12.2.3)：抽象可回滚副作用协议 + 3 个 filesystem effect 类型
- **EffectRegistry** (P12.2.4)：LIFO 栈管理已应用 effects；dispatch 失败时自动 revert
- **Artifact↔Effect 绑定** (P12.2.5)：每次 artifact 写入自动注册 effect，dispatch 失败时文件系统自动清理
- **Audit CLI** (P12.2.6)：暴露 `devsquad audit` 子命令，支持 SHA-256 链式哈希验证 + 敏感字段自动脱敏

## 新功能详解

### P12.2.1 — ArtifactStore

**模块**: `scripts/collaboration/artifact_store.py` (~480 行)

**API**:
```python
from scripts.collaboration.artifact_store import ArtifactStore

store = ArtifactStore()
artifact = store.write(
    session_id="dispatch-2026-08-22-001",
    role_id="architect",
    filename="prd.md",
    content="# Hello World",
)
# Artifact(artifact_id, session_id, role_id, filename, sha256, size, kind, path, created_at)
content = store.read(artifact.artifact_id)
artifacts = store.list(session_id="dispatch-2026-08-22-001")
deleted = store.delete(artifact.artifact_id)
```

**特性**:
- 命名空间: `artifacts/{session_id}/{role_id}/{filename}` + JSON manifest
- SHA-256 + size + kind (text/binary) 跟踪
- 原子 manifest rewrite (write-then-rename)，并发安全
- 路径穿越防护（拒绝包含分隔符的 filename）
- Binary payload 支持（base64 编码）
- Anti-ghost `_call_counter` + `get_call_counter()`

**测试**: 29 单元测试 (Happy/Error/Boundary/Integration)

### P12.2.2 — Worker 改造

**模块**: `scripts/collaboration/worker.py` 增量修改

**变更**:
- `Worker.execute()` 在 `write_finding()` 后 best-effort 调 `ArtifactStore.write()` 持久化产出
- 新增 `_session_id` slot（无 session 时 fallback `task.task_id`）
- try/except 包裹保证 artifact 失败不破坏 worker 成功状态

**测试**: 3 集成测试覆盖 artifact 存在 + best-effort 失败容忍

### P12.2.3 — DispatchEffect Protocol

**模块**: `scripts/collaboration/dispatch_effect.py`

**协议**:
```python
from scripts.collaboration.dispatch_effect import (
    DispatchEffect,
    EffectContext,
    EffectOutcome,
    WriteFileEffect,
    DeleteFileEffect,
    RenameFileEffect,
)

class DispatchEffect(Protocol):
    def apply(self, ctx: EffectContext) -> EffectOutcome: ...
    def revert(self, ctx: EffectContext) -> EffectOutcome: ...
```

**3 Effect 类型**:
- `WriteFileEffect`: 写入文件，revert 时删除或恢复原内容
- `DeleteFileEffect`: 删除文件，revert 时恢复原内容（需要 pre-existing snapshot）
- `RenameFileEffect`: 重命名，revert 时 rename 回原路径

**特性**:
- 幂等语义（多次调用安全）
- 失败返回 `EffectOutcome(success=False, error=...)` 而非 raise
- Binary content 用 base64 编码

### P12.2.4 — EffectRegistry

**模块**: `scripts/collaboration/effect_registry.py`

**API**:
```python
from scripts.collaboration.effect_registry import EffectRegistry
from scripts.collaboration.dispatch_effect import WriteFileEffect, EffectContext

registry = EffectRegistry()
ctx = EffectContext(effect_id="...", effect_type="write_file", payload={...})
outcome = registry.apply(WriteFileEffect(), ctx)
outcomes = registry.revert_all()  # LIFO order
count = registry.pending_count()
```

**特性**:
- LIFO 栈管理已应用 effects
- Thread-safe with lock
- Revert 失败捕获但不阻塞其他 effect revert
- Anti-ghost `_call_count` + `get_call_count()`

**测试**: 22 单元测试覆盖 LIFO 顺序 + 失败容忍

### P12.2.5 — Artifact↔Effect 绑定

**核心**: 每次 `ArtifactStore.write()` 自动注册 `WriteFileEffect` 到全局 `EffectRegistry`；dispatch 失败时 `EffectRegistry.revert_all()` 自动清理磁盘。

**绑定策略**:
- Write 路径：写文件 + 注册 effect（带 original_content snapshot）
- Delete 路径：删除文件 + 注册 effect（带 deleted_content）
- 测试隔离：`set_global_registry()` setter 供测试覆盖全局 registry

**测试**: 5 binding 测试验证 dispatch 失败时文件被自动清理 + 独立 registry 互不影响

### P12.2.6 — Audit CLI

**模块**: `scripts/cli_audit.py` + `scripts/cli.py` 注册 `audit` 子命令

**用法**:
```bash
devsquad audit                       # 最近 20 条
devsquad audit --limit 100           # 指定条数
devsquad audit --format json         # JSON 输出
devsquad audit --event-type dispatch_start  # 按类型过滤
devsquad audit --verify              # 验证 SHA-256 链完整性
devsquad audit --db-path audit.db    # 自定义 DB 路径
```

**特性**:
- SHA-256 链式哈希完整性验证（prev_hash + len-prefixed fields）
- 敏感字段自动脱敏（api_key/password/secret/token/private_key 大小写不敏感递归）
- Text/JSON 双输出格式
- Anti-ghost `_call_counter` + `get_call_counter()`

**测试**: 17 单元测试覆盖命令解析 + 红action + verify 篡改检测

## P11 运维保障

### ALERT_RULES.md 新增
- `DevSquadV453ArtifactStoreFull`: artifact 目录占用 > 80% 磁盘容量（warning 30s）
- `DevSquadV453EffectRevertFailure`: effect revert 失败率 > 5%（critical 1m）
- `DevSquadV453AuditChainTamper`: audit log 哈希链 verify 失败（critical 立即）

### RUNBOOK.md 新增 3 个 incident scenarios
- **SC-08**: ArtifactStore 磁盘满 → 清理 archive + 调整 rotation
- **SC-09**: Effect revert 失败导致残留文件 → 手动调用 `EffectRegistry.revert_all()`
- **SC-10**: Audit chain 被篡改 → 立即 rollback + 触发安全审查

### ROLLBACK.md 新增
- 单模块回退：ArtifactStore / EffectRegistry / Audit CLI 可独立 git revert
- 不需要全版本回退（向后兼容）
