## V4.5.2 Addendum — P12.1 体验打磨 (2026-08-22)

V4.5.2 P12.1 extends the base V4.5.2 with 5 opt-in user-experience modules, all backward-compatible and disabled by default until explicitly enabled.

### P12.1.1 — MokaAIBackend (`scripts/collaboration/moka_backend.py`)

Explicit MOKA AI provider backend (no longer an OpenAIBackend alias).

- **Default base URL**: `https://api.moka-ai.com/v1`
- **Default model**: `moka-gpt-5.5`
- **Retries**: 3 with exponential backoff (0.5s → 1s → 2s, cap 8s)
- **Env vars**: `MOKA_API_KEY` (required) + `MOKA_BASE_URL` (preferred) / `MOKA_API_BASE` (legacy alias) + `MOKA_MODEL`
- **Path**: `A` (direct API)
- **Anti-ghost**: `_call_counter` + 35 unit tests

### P12.1.2 — Metrics CLI (`scripts/cli_metrics.py`)

Live inspection of V4.5.2 Prometheus metrics via CLI.

```bash
devsquad metrics                # human-readable text table
devsquad metrics --format json  # JSON for dashboards
devsquad metrics --format text | less
```

- **V452_METRICS inventory**: 8 metrics with metadata (name/type/description/label_keys) + live samples from the Prometheus registry.
- **Use case**: ad-hoc debugging when Prometheus server is unavailable.
- **Tests**: 16 unit tests.

### P12.1.3 — GitLabConnector (`scripts/collaboration/gitlab_connector.py`)

Second Connector implementation mirroring GitHubConnector design (V4.5.1).

- **Operations**: `create_mr_comment`, `update_issue_state`, `submit_mr_review` (APPROVE/REQUEST_CHANGES/COMMENT)
- **Modes**: `api` (GITLAB_TOKEN) → `cli` (glab CLI) → `simulation` (default for dispatch)
- **Env vars**: `GITLAB_TOKEN`, `GITLAB_BASE_URL` (default `https://gitlab.com`)
- **Anti-ghost**: `_call_counter` + 39 unit tests

### P12.1.4 — Doctor CLI (`scripts/cli_doctor.py`)

Provider connectivity self-check, the first stop when "dispatch returned an error".

```bash
devsquad doctor                          # all providers
devsquad doctor --provider moka          # MOKA only
devsquad doctor --provider openai        # OpenAI only
devsquad doctor --format json            # JSON output
devsquad doctor --timeout 10             # custom timeout (default 5s)
```

- **PROVIDERS registry**: moka, openai, anthropic (env-driven detection)
- **Diagnostic**: lightweight `/models` API call → reachability + latency + model list
- **Exit code**: 0 if all OK, 1 if any configured provider is unreachable
- **Tests**: 23 unit tests.

### P12.1.5 — BackendConfig (`scripts/collaboration/backend_config.py` + `scripts/cli_backend.py`)

Persistent LLM backend selection via `~/.devsquad/config.yaml`.

```bash
devsquad backend set moka                # user-level
devsquad backend set openai --project    # project-level
devsquad backend get                     # print current effective
devsquad backend list                    # list all valid backends
```

- **Priority order**: project config > user config > `DEVSQUAD_LLM_BACKEND` env var > `"auto"`
- **9 valid backends**: auto, auto-fallback, mock, host, trae, openai, anthropic, moka, fallback
- **Schema version**: 1 (forward-compatible)
- **Anti-ghost**: `_call_counter` + 27 unit tests.

## V4.5.2 Core Release (2026-08-21)

---

## Highlights

V4.5.2 is a PATCH-level release (SemVer compliant) that adds **5 new modules** and **8 new test files** to close the B/A/C execution-path gap. This release introduces explicit **route ordering** (Host Bridge → Direct API → Mock), **fuse-skip logic** on consecutive failures, **task scale gating** (S/M/L), **strong-order chain detection** for single-role forcing, and a **CI-blocking performance baseline**.

The release makes the dispatch pipeline's runtime routing explicit, observable, and auditable.

---

## What's New (5 Modules + 8 Test Files + 3 CI Workflows)

### New Modules

| # | Module | File | Path | Purpose |
|---|--------|------|------|---------|
| 188 | **BackendPath** | `scripts/collaboration/backend_paths.py` | — | B/A/C path enum, error classification, fuse-skip constants |
| 189 | **HostLLMBridge** | `scripts/collaboration/host_llm_bridge.py` | B | File-protocol bridge to programming AI host (Trae/ClaudeCode) |
| 190 | **TaskScaleGate** | `scripts/collaboration/task_scale_gate.py` | — | S/M/L scale gate, decides role-array caps and orchestrator |
| 191 | **OrderChainDetector** | `scripts/collaboration/order_chain_detector.py` | — | Heuristic detector forcing single-role chain for debug/derivation |
| 192 | **PerfBaseline** | `scripts/collaboration/perf_baseline.py` | — | p95 regression CI gate with per-path thresholds |

### Module 188: BackendPath

Single source of truth for the **B → A → C** execution-path resolution.

**Key Components**:
- `BackendPath` enum (`B_HOST_BRIDGE`, `A_DIRECT_API`, `C_MOCK`)
- `RESOLVE_ORDER = (B_HOST_BRIDGE, A_DIRECT_API, C_MOCK)`
- `BackendErrorReason` enum + `classify_error()` for fuse counting
- `FUSE_SKIP_AFTER_CONSECUTIVE = 2`

### Module 189: HostLLMBridge

**Path: B** — direct connection to programming AI host (Trae / ClaudeCode / Cursor) **without API key**.

**Key Components**:
- File-protocol bridge with atomic writes + marker files
- `HostBridgeBackend` adapter implementing `LLMBackend.generate()`
- Platform auto-detection (`host_llm` / `claude_code` / `unknown`)
- Anti-Ghost `_call_counter` on every `create_request()`
- Consecutive-same-reason failure → fuse-skip

### Module 190: TaskScaleGate

**Architecture §3** — first-pass routing decision based on task complexity.

**Logic** (priority order):
1. Explicit override: `scale_override ∈ {S, M, L}`
2. L triggers: ≥3 modules / ≥5 files / `--full` / `all_roles=True`
3. M triggers: 2 modules / 3-4 files / integration-test keywords
4. S triggers: 1 file / bug-fix / what-is keywords
5. **Default fallback → M** (never miss verification)

### Module 191: OrderChainDetector

**Architecture §4** — second-pass routing; forces single-role chain for debug/derivation.

**Logic** (priority order):
1. User flag: `sequential=True` / `no_parallel=True` / `mode=sequential`
2. Role metadata: role with `sequential_only=True` (e.g. `solo-coder`)
3. Heuristic score ≥ 3: debug/根因/prove/推导/分步
4. Counter-example: explicit multi-role (`X + Y`) overrides heuristic
5. Default: allow multi-role parallel

### Module 192: PerfBaseline

**Architecture §6** — p95 regression CI gate with per-path thresholds.

| Path | Sample Size | Threshold (regression) |
|------|-------------|------------------------|
| C Mock | 50 | +10% blocks PR |
| B Host Bridge | 50 | +10% blocks release tag |
| A Direct API | 20 | +20% blocks release tag |
| A→C Fallback | 10 | diagnostic only |

**Three-not-receive principle** (沿用上游):
- No Mock-substitute as baseline representative
- No first-cold-start samples (前 5 丢弃)
- No failure/timeout samples (计入 `excluded_count`)

## Migration Guide

**No migration required.** To opt into V4.5.2 features:

```bash
# Install
pip install --upgrade devsquad==4.5.2

# Use B path (Host Bridge)
export TRAE_ENV=1  # or CLAUDE_CODE_ENV=1
devsquad run "your task"

# Use A path (Direct API)
export DEVSQUAD_OPENAI_API_KEY=sk-...
devsquad run "your task"

# Use auto-fallback (B→A→C with fuse skip)
devsquad run "your task" --backend auto-fallback
```
