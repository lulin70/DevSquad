## 1. 架构概述

### 1.1 设计原则（评审共识）

| 原则 | 来源 | 实现 |
|------|------|------|
| 薄切片先行 | C2（7/7 一致） | Gate 0（~50 行）+ Slice 1（~200 行） |
| 不修改现有代码 | C5（7/7 一致） | 新增独立模块，冻结 MockBackend |
| 不集成 dispatch | C3（7/7 一致） | 仅 scripts/ 入口，不修改 dispatcher.py |
| 仪器校准前置 | C1（7/7 一致） | Gate 0 是 Slice 1 的前置门禁 |
| n=3 重复采样 | C4（7/7 一致） | LLM 是随机过程，需多次采样 |

### 1.3 三臂数据流

```
任务集 (3 个固定任务)
    │
    ├──→ Arm 1: frozen_mock (MockBackend，冻结基线)
    │        │
    │        └──→ ConfidenceScorer.score() + FiveAxis.evaluate()
    │                │
    │                └──→ [score_1, score_2, score_3] (n=3)
    │
    ├──→ Arm 2: role_specific_mock (RoleSpecificMockBackend，新类)
    │        │
    │        └──→ ConfidenceScorer.score() + FiveAxis.evaluate()
    │                │
    │                └──→ [score_1, score_2, score_3] (n=3)
    │
    └──→ Arm 3: llm (MOKA AI，需 API key)
             │
             └──→ ConfidenceScorer.score() + FiveAxis.evaluate()
                     │
                     └──→ [score_1, score_2, score_3] (n=3)

聚合: mean ± stddev per arm per task
判定: signal_strength (significant / marginal / noise / calibration_failed)
```

## 3. 数据模型

### 3.1 CalibrationGateResult

```python
@dataclass
class CalibrationGateResult:
    """Gate 0 仪器校准门结果."""

    passed: bool
    """门是否通过（排序正确 AND gold-filler 间距 ≥ 0.2）."""

    scores: dict[str, dict[str, float]]
    """所有输出在所有评分维度的得分.
    格式: {output_id: {dimension_id: score}}
    output_id ∈ {"gold", "llm", "filler", "empty"}
    dimension_id ∈ {"completeness", "certainty", "specificity",
                     "consistency", "model_quality",
                     "correctness", "readability", "architecture",
                     "security", "performance"}
    """

    ordering_correct: bool
    """4 个输出是否按 gold > llm > filler > empty 排序."""

    gap_gold_filler: float
    """gold 均分 - filler 均分（间距）."""

    diagnostics: list[str]
    """失败诊断信息列表（空列表表示无诊断）."""

    def to_markdown(self) -> str:
        """渲染 Markdown 诊断报告."""
```

### 3.2 ProbeSliceReport

```python
@dataclass
class ProbeSliceReport:
    """Slice 1 薄切片探针报告."""

    gate_passed: bool
    """Gate 0 是否通过（False 时其余字段无意义）."""

    task_results: dict[str, dict[str, list[float]]]
    """每任务每臂的 n=3 采样得分.
    格式: {task_id: {arm_id: [score_1, score_2, score_3]}}
    task_id ∈ {"simple", "medium", "complex"}
    arm_id ∈ {"frozen_mock", "role_specific_mock", "llm"}
    """

    mean_stddev: dict[str, dict[str, tuple[float, float]]]
    """每任务每臂的 (mean, stddev) 聚合."""

    signal_strength: str
    """信号强度判定.
    ∈ {"significant", "marginal", "noise", "calibration_failed"}
    """

    conclusion: str
    """人类可读结论（一段话）."""

    def to_markdown(self) -> str:
        """渲染 Markdown 决策报告."""
```

### 3.3 信号强度判定算法

```python
def _determine_signal_strength(
    mean_stddev: dict[str, dict[str, tuple[float, float]]],
    gate_passed: bool,
) -> str:
    """判定信号强度.

    规则:
    - gate_passed=False → "calibration_failed"
    - 对每个任务，计算 delta = llm_mean - max(frozen_mock_mean, role_specific_mock_mean)
    - 对 3 个任务的 delta 取中位数
    - median_delta > 0.15 → "significant"
    - 0.05 < median_delta ≤ 0.15 → "marginal"
    - |median_delta| ≤ 0.05 → "noise"
    """
```

## 4. API 契约

### 4.1 quality_calibration_gate.py

```python
def run_calibration_gate() -> CalibrationGateResult:
    """运行仪器校准门.

    Returns:
        CalibrationGateResult: 含 passed/scores/ordering/gap/diagnostics.

    Side effects:
        读取 data/calibration/gold_outputs.json.
        不调用 LLM API（使用缓存的 LLM 输出）.
    """
```

### 4.2 quality_probe_slice.py

```python
def run_probe_slice(
    llm_backend: LLMBackend | None = None,
    n_samples: int = 3,
) -> ProbeSliceReport:
    """运行薄切片探针.

    Args:
        llm_backend: LLM 后端实例. None 时跳过 LLM 臂（仅对比 2 臂）.
        n_samples: 每臂采样次数. 默认 3.

    Returns:
        ProbeSliceReport: 含 gate_passed/task_results/mean_stddev/signal_strength.

    Side effects:
        调用 llm_backend.generate() n_samples × 3 tasks 次.
        调用 ConfidenceScorer.score() + FiveAxisConsensusEngine.evaluate().
    """
```

### 4.3 role_specific_mock_backend.py

```python
class RoleSpecificMockBackend(LLMBackend):
    """角色特定 Mock 后端（独立类，不修改 MockBackend）.

    默认 role_specific=False 时行为与 MockBackend 完全一致.
    role_specific=True 时使用角色特定模板.
    """

    def __init__(self, role_specific: bool = False) -> None:
        """初始化.

        Args:
            role_specific: True 使用角色特定模板, False 兼容 MockBackend.
        """

    def generate(self, prompt: str, **kwargs: Any) -> str:
        """生成 Mock 输出.

        Args:
            prompt: 用户提示.
            **kwargs: role_name, task_description 等.

        Returns:
            Mock 输出字符串.
        """
```

### 4.4 generate_quality_decision_report.py

```python
def main() -> int:

        0 成功, 1 失败.

    Output:
        docs/analysis/YYYY-MM-DD_LLM_vs_Mock_Quality_Report.md
```

## 6. 安全考量（评审安全专家建议）

| # | 建议 | 实现 |
|---|------|------|
| S1 | Judge prompt 结构化隔离 | 薄切片不使用 LLM-as-judge，仅 heuristic 评分，无需隔离 |
| S2 | 注入检测 | 薄切片不使用 LLM-as-judge，任务集为固定内容，无注入风险 |
| S3 | tasks.json schema 校验 | `data/calibration/gold_outputs.json` 由开发者手写，无需 schema 校验 |
| S4 | 出口管控 | 薄切片不向 LLM 发送用户数据，仅发送固定任务提示 |
| S5 | 审计日志 | 薄切片产出 Markdown 报告，含完整得分和采样数据 |

**结论**: 薄切片阶段不涉及 LLM-as-judge，安全专家 5 项建议中 S1/S2/S4 不适用。S3/S5 已通过设计保证。
