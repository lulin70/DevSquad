## 4. V4.6.0 — Cordis 动态组合能力（planned minor）

**目标**: 让 dispatch pipeline 从"单向执行"进化为"可追踪、可撤销、可协调"的动态组合系统，为 Self-Evolving Agent（自进化 Agent）打基础。当前 dispatch 产生副作用（Connector 操作、审批记录、Scratchpad 写入）但失败时不回滚；模块只有 `_call_counter` 无生命周期状态；依赖关系硬编码在 dispatcher。

**灵感来源**: Cordis 论文《A Programming Paradigm for Spatiotemporal Composability》+ DeepSeek Harness 自进化 Agent 方向 — 让软件在运行时安全地动态增删替换组件。

### 4.1 概念映射（Cordis → DevSquad）

| Cordis 概念 | DevSquad 现状 | 差距 |
|-------------|---------------|------|
| Effect / Revertible Effect | dispatch 副作用无撤销机制 | 失败时副作用残留 |
| Fiber 状态机 | 模块只有 `_call_counter`，无生命周期状态 | 激活失败静默跳过 |
| Coeffect（依赖声明） | 模块依赖硬编码在 dispatcher | 新增模块需手动接线 |
| Commit View / Target View | Worker 失败靠 `return_exceptions` 兜底 | 无系统级事务 |
| Component Loader | 模块启动时全量加载 | 无法按任务需求动态加载 |

### 4.2 特性清单（6 项）

| ID | 项目 | 优先级 | Cordis 概念 | 说明 |
|----|------|--------|------------|------|
| V460-1 | **DispatchEffect 回滚注册表** | P0 | Effect / RevertibleEffect | 每个副作用操作注册时同时携带撤销方法（如 PR 评论注册删除方法）。`DispatchResult` 新增 `effects: list[Effect]` 字段，dispatch 失败时遍历调用 `revert()` 自动恢复环境。与 V4.5.1 的 `connector_operations`/`approval_records` 字段天然契合 |
| V460-2 | **Module Fiber 状态机** | P1 | Fiber state machine | 模块生命周期管理：`Inactive → Activating → Active → Deactivating → Failed`。dispatcher 维护 `module_state: dict[str, FiberState]`，激活失败显式进入 `Failed` 状态（不再静默降级），Failed 模块在 dispatch 报告中显式标注。`check_module_activation.py` 升级为同时检查状态 |
| V460-3 | **Module Coeffect 依赖声明** | P2 | Coeffect | 模块声明所需依赖（如 Connector 声明依赖 approval_gate）。类属性 `coeffects: list[Coeffect]`，dispatcher 激活前检查依赖模块是否 `Active`，不满足则进入 `Failed` 而非静默降级。消除 dispatcher 中的硬编码依赖 |
| V460-4 | **Dispatch 事务模式（atomic）** | P3 | Commit View / Target View | dispatch 增加可选 `atomic: bool` 参数。`atomic=True` 时任一关键 worker 失败则回滚所有 Effect（触发 V460-1 revert 链）；`atomic=False`（默认）保持现有 `return_exceptions=True` 行为，向后兼容 |
| V460-5 | **Component Loader 按意图加载** | P4 | Component Loader | 基于 IntentWorkflowMapper 已识别的任务意图（6 种）决定激活哪些 enhancement modules。如"代码审查"意图只激活 ReviewSkill + ConsensusEngine，不激活 DORA Metrics。`_activate_v4XX_modules()` 改为按 intent 过滤 |
| V460-6 | **自进化闭环** | 长期 | Self-Evolving Agent | RetrospectiveEngine 发现能力不足 → Skillifier 生成新组件（如新 concern pack）→ SkillRegistry 热加载 → 下次 dispatch 自动激活。依赖 V460-5，目标版本 V5.0.0+ |

### 4.3 V4.5.1 遗留项处置

| ID | 处置 | 理由 |
|----|------|------|
| V451-3 Artifacts | 纳入 V4.6.0 一起评估 | 与 Effect 回滚有交互（artifact 文件也是副作用，需要撤销） |
| V451-4/5/6 性能项 | 独立推进，不阻塞 V4.6.0 | 与动态组合无依赖关系 |

### 4.4 实施顺序与依赖链（7-Role 共识 2026-08-05）

```
V460-1 (Effect, P0)  ←—— 一切的地基：Fiber 的 Deactivating 需要 revert；atomic 需要 revert
    ├── V460-2 (Fiber, P1)     ←—— Coeffect 解析需要知道模块状态
    │       └── V460-3 (Coeffect, P2)
    │               └── V460-5 (Loader, P4)  ←—— 需要状态 + 依赖解析
    └── V460-4 (atomic, P3)    ←—— 仅依赖 V460-1，可与 V460-2/3 并行
                                    V460-6 (自进化, 长期) ←—— 需要 V460-5
```

### 4.5 出口条件

- V460-1: dispatch 失败场景 E2E 测试验证副作用已回滚（`effects` 列表为空或全部 reverted）
- V460-2: 所有 enhancement modules 有明确 Fiber 状态，CI 检查 `Active` 而非仅 `_call_counter > 0`
- V460-3: Connector 的 approval_gate 依赖由声明解析而非硬编码
- V460-4: `atomic=True` 模式下多 worker 失败回滚 E2E PASS；默认模式行为与 V4.5.1 完全一致（回归）
- 反幽灵验证：新模块 `_call_counter > 0` + 报告用户可见章节
- 全量回归：8392+ 测试无回归，ruff/mypy/doc_consistency 全绿

### 4.6 设计约束

| 约束 | 说明 |
|------|------|
| Effect 回滚默认开启但幂等 | `revert()` 失败不抛异常（记录警告），不阻塞后续回滚 |
| Fiber 状态向后兼容 | 不改变现有 `_call_counter` 机制，状态机是增量信息 |
| Coeffect 声明可选 | 未声明 `coeffects` 的模块视为无依赖，行为不变 |
| atomic 默认 False | 不开启时行为与 V4.5.1 完全一致 |
| Loader 保守起步 | 第一版仅"过滤掉明显无关模块"，不做激进的按需加载 |
| 拒绝引入外部依赖 | Effect/Fiber/Coeffect 全部纯 Python 实现，不引入新第三方库 |

## 7. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Connector 需 GitHub API token | V451-2 已交付 | ✅ 已支持 api/cli/simulation 三模式，dispatch 强制 simulation 安全 |
| Approval Gate 阻塞 dispatch | 用户体验下降 | ✅ 已交付：默认自动批准（向后兼容），仅显式配置回调时生效 |
| Artifacts 文件路径冲突 | 文件覆盖 | `artifacts/{session_id}/{role}/{filename}` 命名规则 |
| Effect revert 链部分失败 | 回滚不完整 | revert() 幂等设计：失败记录警告不阻塞，E2E 覆盖部分失败场景 |
| Fiber 状态机引入回归风险 | 现有模块激活路径破坏 | 增量设计：不改 `_call_counter`，状态机是附加信息；全量回归 8392+ |
| Loader 误过滤必要模块 | 功能缺失（新形态幽灵） | 保守起步 + 反幽灵 E2E 扩展（验证被过滤模块确实非必要） |
| atomic 回滚与 Scratchpad 交互 | 共享状态不一致 | Scratchpad 写入设计为 append-only 日志，回滚以"标记废弃"而非删除实现 |
| mutation testing 10-50x 慢 | CI 时间膨胀 | 仅核心模块试点，不进 CI 主路径 |
| 真实 LLM E2E 需 API key | V500-5 延期 | CI secrets + 仅 release tag 触发 |
