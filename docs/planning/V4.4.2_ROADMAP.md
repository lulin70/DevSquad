## 0. 初心与定位（用户 2026-08-05 澄清）

> **DevSquad 不是给终端用户的创意 Agent，而是协助 TRAE / ClaudeCode / Codex 等编程 AI，对软件开发的「框架、流程、文档、架构、质量、安全、部署」进行「管控」的工具。**

本初心贯穿所有后续决策：
- **管控对象**：软件开发全生命周期的 7 个维度 —— 框架 / 流程 / 文档 / 架构 / 质量 / 安全 / 部署
- **服务方式**：作为管控/治理层，叠加在编程 AI 之上，对 AI 产出的开发过程与成果做检查、审批、门禁、质量管控
- **不过度设计**：一切功能价值排序以「是否直接支撑对软件开发全周期管控、是否让 DevSquad 真正被使用」为标准
- **用户决策 2026-08-05**：永久砍掉 ITSM（V500-4）、插件市场（V500-9）、目录重组（V500-7），其余项全部收拢至 4.5.x 迭代序列最终并入 4.6.0

## 6. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 真实 LLM E2E 需 API key | V4.5.2 延误 | CI secrets + 仅 release tag 触发；mock 为不变量 |
| 一次收拢批次过多 | 迭代失控 | 4.5.x 小步迭代，每批独立过门禁 |
| Effect revert 链部分失败 | 回滚不完整 | revert() 幂等，失败记录警告不阻塞 |
| Fiber 状态机回归 | 激活路径破坏 | 增量设计不改 `_call_counter`，全量回归 |
| Loader 误过滤 | 功能缺失（新幽灵） | 保守起步 + 反幽灵 E2E 扩展 |
| mutation testing 慢 | CI 时间膨胀 | 仅核心模块，不进主路径 |
