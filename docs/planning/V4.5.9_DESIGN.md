## 1. 总体架构

### 1.1 目标状态 vs 现状

```
【现状：双轨】
dispatch() [sync] ──> Coordinator._execute_parallel ──> ThreadPoolExecutor(10) ──> worker.execute [sync thread]
async_dispatch() ──> AsyncCoordinator._execute_parallel_async ──> asyncio.gather ──> AsyncWorkerWrapper
                                                                     └─ run_in_executor(worker.execute)  ← 假异步

【目标：单轨 gather 核 + 真异步】
dispatch() [sync bridge: asyncio.run] ─┐
                                        ├──> execute_batch_gather (共享核，单一来源)
async_dispatch() [native] ─────────────┘         │
                                                  ├── asyncio.Semaphore(max_concurrency)
                                                  ├── asyncio.gather(*, return_exceptions=True)
                                                  └── BaseException 防御 → WorkerResult
                                                  │
                              run_one(task) 回调（各 Coordinator 注入）：
                                                  ├── Worker.aexecute ──> await backend.generate  [async 后端：真异步，无线程]
                                                  └── run_in_executor(worker.execute) [sync 后端：Mock/HostBridge 线程桥]
```

## 2. gather_core.py（共享核）设计

```python
"""Shared asyncio.gather execution core (V4.5.9).

Single source of truth for parallel batch execution. Both the sync
Coordinator (via asyncio.run bridge) and AsyncCoordinator (native)
delegate here. Do NOT reimplement gather semantics elsewhere.
"""

async def execute_batch_gather(
    tasks: list[TaskDefinition],
    run_one: Callable[[TaskDefinition], Awaitable[WorkerResult]],
    max_concurrency: int,
) -> list[WorkerResult]:
    """gather 核语义（唯一实现）：
    1. Semaphore(max_concurrency) 并发上限
    2. asyncio.gather(..., return_exceptions=True) —— 单 Worker 失败不丢其余结果（硬约束）
    3. BaseException（KeyboardInterrupt/SystemExit）防御 → WorkerResult(success=False)
    4. 结果保持提交序（batch.tasks 顺序），与旧 ThreadPool 版完成序不同（PRD R1，行为变更已登记）
    """
```

**run_one 回调注入点**：两个 Coordinator 各自实现 `run_one`，共享核只管 gather 机制（Semaphore/容错/顺序），不管 worker 路由、briefing、timeout、retry——避免共享核膨胀。

## 3. Coordinator 同步桥设计

```python
# coordinator.py
def _execute_parallel(self, batch: TaskBatch) -> list[WorkerResult]:
    # L-V457-002 模式：running loop 检测，快速失败 informative error
    try:
        asyncio.get_running_loop()
    except RuntimeError:
        pass
    else:
        raise RuntimeError(
            "Coordinator._execute_parallel cannot run inside a running event loop; "
            "use AsyncCoordinator / async_dispatch in async context."
        )
    max_workers = min(batch.max_concurrency or len(batch.tasks), len(batch.tasks))
    if max_workers <= 0 or not batch.tasks:
        return []
    return asyncio.run(self._aexecute_parallel(batch, max_workers))

async def _aexecute_parallel(self, batch, max_workers) -> list[WorkerResult]:
    async def run_one(task: TaskDefinition) -> WorkerResult:
        worker = self._get_worker_for_task(task)
        if not worker:
            return WorkerResult(worker_id="unknown", task_id=task.task_id,
                                success=False, error="No worker found for task")
        loop = asyncio.get_running_loop()
        if hasattr(worker, "aexecute"):
            return await worker.aexecute(task)          # 真异步（async 后端）
        return await loop.run_in_executor(None, worker.execute, task)  # sync 后端桥
    return await execute_batch_gather(batch.tasks, run_one, max_workers)
```

**失败语义对齐（AC-C3）**：worker 内异常被 `worker.execute` 顶层兜底捕获（worker.py L233-253 返回 success=False），与旧线程池 `future.result()` 抛出 → `worker_id="unknown"` 的路径不同。为逐字保持旧行为，`run_one` 外再包一层 try/except → `WorkerResult(worker_id="unknown", ...)`，与 AsyncCoordinator 现有 `_execute_with_semaphore` 的 per-task catch 对齐。

**shutdown 契约（R2）**：`self._executor` 与 `shutdown(wait=False)` 中的 executor 关闭逻辑移除；`shutdown()` 其余职责不变。`tests/test_performance_benchmarks.py::test_thread_pool_reuse` 按 PRD §3.3 改写为 `test_gather_concurrency_reuse`（断言并发 dispatch 稳定性 + 无线程泄漏），修改理由登记于 CHANGELOG。

## 4. Worker.aexecute 设计（R4 防漂移）

```python
# worker.py
async def aexecute(self, task: TaskDefinition) -> WorkerResult:
    """Async twin of execute(): identical semantics, native await for async backends."""
    start_time = time.time()
    try:
        context = self._build_execution_context(task)          # 与 execute 共享
        finding = await self._ado_work(context)
        result = self._finalize_finding(task, finding, start_time)  # 提取的共享辅助
        track_usage(...)
        return result
    except Exception as e:
        return self._failure_result(task, e, start_time)       # 提取的共享辅助
```

**结构性去重（AC-W1）**：`execute()` 与 `aexecute()` 共享三个提取的私有方法：
- `_build_execution_context`（已存在，不动）
- `_finalize_finding(task, finding, start_time)`：Scratchpad 写入 + ArtifactStore 持久化 + WorkerResult 组装（从 execute() L183-232 提取，execute() 改为调用它——行为零变化由核心 56 测试锁定）
- `_failure_result(task, e, start_time)`：异常兜底 WorkerResult（从 execute() L233-253 提取）

```python
async def _ado_work(self, context) -> str:
    # 缓存查/写与 _do_work 共享辅助；LLM 调用分流：
    if self.stream and isinstance(self.backend, AsyncLLMBackendInterface):
        chunks = [c async for c in self.backend.generate_stream(instruction)]
        finding = "".join(chunks)
    elif isinstance(self.backend, AsyncLLMBackendInterface):
        finding = await self.backend.generate(instruction)   # 真异步（httpx.AsyncClient 内核）
    else:
        finding = await asyncio.get_running_loop().run_in_executor(
            None, self._do_work, context)                    # sync 后端（Mock/HostBridge）线程桥
    return finding
```

> 注：async 后端的缓存查询/使用统计与 `_do_work` 共享同一批辅助方法；`_do_work` 内部其余逻辑（prompt 构建）为纯 CPU 计算，直接在协程内同步执行。

## 5. AsyncWorkerWrapper 升级（AC-W4）

```python
# async_coordinator.py
class AsyncWorkerWrapper:
    async def execute(self, task) -> WorkerResult:
        if hasattr(self.worker, "aexecute"):
            coro = self.worker.aexecute(task)                # 原生路径：无线程
        else:
            loop = asyncio.get_event_loop()
            coro = loop.run_in_executor(None, self.worker.execute, task)  # 旧桥兜底
        if self.timeout:
            return await asyncio.wait_for(coro, timeout=self.timeout)
        return await coro
```

`AsyncCoordinator._execute_parallel_async` 重构：保留其 timeout/retry/briefing 的 `_execute_with_semaphore` 外壳，gather 机制（L490-515）替换为 `execute_batch_gather` 调用——行为不变，71 个既有测试零修改通过即为重构正确性证明。
