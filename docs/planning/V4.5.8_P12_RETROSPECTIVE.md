## 4. 7-Role Consensus (6.5/10) — 拆分决策

P1 共识 6.5/10（P1+P2 三项入选；7-Role 评分拆分）：
- **P0 async 迁移被拆出**：架构师 5.5/10 — `AsyncWorkerWrapper` 仍经
  `run_in_executor`，默认把 `Coordinator._execute_parallel` 换成
  `asyncio.gather` 会破坏同步调用边界与 11-Phase 生命周期。V4.5.8 只交付
  风险域三项，async 迁移独立成 V4.5.9/V4.5.10，风险隔离。
- **JSON 而非 SQLite**：≤10000 风险条目场景 JSON 文件足够，避免引入
  sqlite3 schema 迁移负担（SQLite 列入 V4.5.9+ 候选）。
- **fail-closed 契约统一**：安全角色坚持 "审批不可用 ≠ 审批通过"，
  `close`/`clear` 统一 exit 2，消灭 V4.5.5 auto-approve fallback 的静默放行。

## 7. Lessons Learned (L-V458)

1. **L-V458-001 (Trae sandbox 前台挂起)**: Trae 终端沙箱里前台运行长命令
   （pytest 等）会停在 `T`（stopped）状态且无输出。所有测试/门禁命令必须用
   `nohup <cmd> > /tmp/xxx.log 2>&1 & disown; sleep N; tail /tmp/xxx.log`
   后台模式运行。教训：沙箱的 TTY/分页行为不可假设，输出重定向 + 轮询是
   唯一可靠模式。
2. **L-V458-002 (DEFAULT_ROOT 默认参数绑定陷阱)**: `DEFAULT_ROOT` 作为
   默认参数在模块导入时绑定一次 `Path`，所有未显式传 root 的调用共享同一
   目录 — V4.5.7 的 `add_risk()` 默认写进真实 `.devsquad_data`，测试与
   实际数据互相污染。教训：默认 root 这类可变上下文必须每次调用时解析，
   测试用 `tmp_path` + `--root` 显式隔离。
3. **L-V458-003 (fail-closed 契约统一)**: "要求审批但审批不可用" 的语义
   必须全 CLI 统一（exit 2 + 一行 ERROR + store 保留），不能每个命令各自
   解释。auto-approve fallback 看似友好，实际是静默侵蚀 human-in-the-loop
   保证 — 契约变更要在 CHANGELOG 显式标注破坏性。
4. **L-V458-004 (monkeypatch 需运行时名字查找)**: `monkeypatch.setattr`
   在 patch 时绑定名字；如果被测代码在函数体内 `from x import y` 或捕获
   局部引用，patch 模块属性无效。必须 patch 被测代码运行时查找的那个名字
   （模块属性），而不是测试侧捕获的引用。
