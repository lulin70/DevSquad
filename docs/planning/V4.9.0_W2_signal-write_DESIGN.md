## 1. 设计目标

1. W1 的信号引用（`audit:event=<N>&finding=<i>` / `&failure=<class>`）在**真实 dispatch run** 中可解析——写入端把 findings 与 failure_class 落进 audit 事件的 `details`。
2. signal_type 按 PRD §4.2 映射表细化：`review:break-vuln:<ID>` / `review:spec:<类别>` / `failure:<class>`；`environment_blocked` 显式排除。
3. 修复既有 C19 管道断链：`result.details["failure_class"]` 有 5 个读取方、零写入方。
4. 纯标准库、零新依赖、零 LLM（确定性侧资产）。

## 2. 关键裁定

| 裁定项 | 决定 | 理由 |
|---|---|---|
| findings 承载事件 | **`dispatch_end` 单事件扩展**（不新增事件类型） | W1 close 的 `_verify_run_ref`（[defect_ledger.py:298-322](../../scripts/collaboration/defect_ledger.py#L298-L322)）**只读单事件 details**；failure_class 与 findings 必须同事件，close 才能一次核对完毕。dispatch_end 语义即"run 终态"，findings / failure_class 恰为 run 结束时可知的终态信号 |
| 可解析产物清单（PRD §4.2 锁定项） | **v1 = dispatch audit DB 单源**；不实现 W1 §11 预留的 `review:` 前缀 ref 格式 | 三类信号（FailureClass / BV / Stage 1 spec）全部经 dispatch_end 事件承载，无第二信号源需求；`audit:` 前缀扩展位继续保留 |
| findings dict shape | **`ReviewFinding.to_dict()` 原样**（[two_stage_review_gate.py:131-140](../../scripts/collaboration/two_stage_review_gate.py#L131-L140)） | 已含消费端全部所需字段：`severity`（close 核对）、`category`（BV 检查直接装 BV ID，[review_checkers.py:362-374](../../scripts/collaboration/review_checkers.py#L362-L374)）、`stage`（备用）。不发明新 schema |
| `environment_blocked` 立案 | **add 拒绝**（product refusal，exit 1），拒绝信息注明 PRD §4.2 显式排除 | 环境阻断非缺陷；先验证信号真实、后执行排除（排除逻辑只对真实信号生效） |
| 异常路径 audit（[dispatcher.py:506](../../scripts/collaboration/dispatcher.py#L506)） | **v1 不接新参数** | 异常路径无 DispatchResult，findings 必然不存在；failure_class 判定与 CLI 层 `exit_code_for_exception` 重复；既有 `log_error` 事件（error_type）已可追溯。无立案需求实证，不加面 |
| C19 终态重算归类 | **bug fix**（disclosure 诚实性，非行为变更） | 组装时刻值在 review gate 翻转 success 后过时（失败 run 披露 "none"）；终态重算让披露与终态一致。worker 失败 run 两值相同（重算幂等），退出码语义不变 |
| 映射表事实源 | `defect_ledger.py` 定义常量，`BV_CATEGORIES`/`BV_CRITICAL` 从 [review_taxonomy.py](../../scripts/collaboration/review_taxonomy.py) 导入 | 单一事实源优先；review_taxonomy 本身纯 stdlib 确定性模块，不违反 W1"零新依赖"约束。映射常量同时是 W3 登记闸强制分级的消费面 |

## 3. 写入端设计

### 3.1 C19 终态重算：failure_class 与 run 终态对齐

> **勘误（2026-10-26，实现期证据修正）**：本节初版主张"`details["failure_class"]` 写入方为零、`failure_class_for_dispatch()` 零生产调用"——该结论源于一次被 `head_limit` 截断的 grep（假阴性），实现期核实推翻。真实写入点在 [dispatch_result_assembler.py:105-126](../../scripts/collaboration/dispatch_result_assembler.py#L105-L126)（组装时刻，Step 17 内经 [dispatch_steps.py:547](../../scripts/collaboration/dispatch_steps.py#L547) 调用）。本节按修正后事实改写；§8 评审记录附 erratum。

**真实断链（2026-10-26 复核）**：`ResultAssembler.assemble` 在 Step 17 组装时刻判定并写入 `details["failure_class"]`（成功强制 `"none"`，失败调 `failure_class_for_dispatch(worker_results, errors)`）。但 Step 21 review gate 可在组装**之后**追加 errors 并翻转 `result.success=False`（[dispatch_steps.py:636-646](../../scripts/collaboration/dispatch_steps.py#L636-L646)）——此时 failure_class 停留在组装时刻值：

- **review-gate 失败 run**（worker 全成功、组装时 errors 空）：终态 `success=False` 但 `failure_class=="none"`。退出码碰巧正确（`dispatch_exit_code` 对非 environment_blocked 返回 1），但 disclosure 面诚实性破口：报告渲染器（dispatch_models.py:402-403 对 `"none"` 直接不渲染 failure-class 章节）、CLI/MCP/API JSON 的 `failure_class:"none"` 与 `success:false` 自相矛盾。
- **worker 失败 run**：组装时刻已可判定，两值一致（既有 4 个传播测试全走此路径，因此一直绿——review-gate 路径无断言覆盖，正是断链得以存身的原因）。

**修复**：post_dispatch 尾部（Step 23 judge 之后、return 之前）按**终态**重算（作用域内 `worker_results`/`errors` 均可见）：

```python
# Step 24 (V4.9.0 W2): C19 — recompute the failure class at the terminal state.
result.details["failure_class"] = failure_class_for_dispatch(worker_results, errors).value
```

- **始终重算**（含成功 run 的 `"none"`，幂等）；review-gate blocking 文本经 `classify_error_text` 无环境标记 → `product_failed`（review 失败即产品失败，语义正确）。
- 行为影响收窄为 disclosure 诚实性：退出码语义不变（worker 失败 run 两值相同）；review-gate 失败 run 的报告/JSON 从此如实披露 `product_failed`。

### 3.2 audit logger 扩展：log_dispatch_end 可选参数

```python
def log_dispatch_end(
    self,
    user_id: str,
    success: bool,
    duration: float,
    *,
    findings: list[dict] | None = None,
    failure_class: str | None = None,
) -> str:
    details = {"success": success, "duration": duration}
    if findings is not None:
        details["findings"] = list(findings)
    if failure_class is not None:
        details["failure_class"] = failure_class
    return self._append_entry("dispatch_end", user_id, details)
```

- 新参数全部 keyword-only 可选；**不传时 details 与 4.8.x 逐 key 一致**（负向测试断言，PRD §7.6）。
- details 变化只影响**新条目**的 entry_hash；哈希链对旧条目零影响（链式哈希按条目计算，`verify_chain` 语义不变）。

## 4. 消费端：signal_type 映射表（PRD §4.2 实现化）

### 4.1 映射规则（`_resolve_signal` finding/failure 分支细化）

| 信号源（audit details 内） | 判别条件 | signal_type | 登记闸强制（W3 消费） |
|---|---|---|---|
| BV finding（十类） | `finding["category"]` ∈ `BV_CATEGORIES.code` | `review:break-vuln:<category>` | category ∈ `BV_CRITICAL` 四项（BREAK-1/BREAK-5/VULN-1/VULN-4）强制；其余 warning 不强制 |
| Stage 1 规格发现 | `finding["category"]` ∉ BV codes | `review:spec:<category>` | 不强制 |
| FailureClass.product_failed | `failure_class == "product_failed"` | `failure:product_failed` | 强制 |
| FailureClass.environment_blocked | `failure_class == "environment_blocked"` | **add 拒绝**（显式排除） | — |

- 判别规则刻意不依赖 `stage` 字段（"非 BV 即 spec"），避免与 ReviewStage 枚举耦合；`stage` 保留在 details 内供人工追溯。
- failure 分支：先匹配 audit 记录（真实性），后拒绝排除项——拒绝信息注明 "environment_blocked is excluded from filing (PRD §4.2: environment blocks are not defects)"。

### 4.2 常量面（defect_ledger.py，W3 单一消费源）

```python
from .review_taxonomy import BV_CATEGORIES, BV_CRITICAL

BV_SIGNAL_PREFIX = "review:break-vuln"
SPEC_SIGNAL_PREFIX = "review:spec"
MANDATORY_FAILURE_TYPES = frozenset({"failure:product_failed"})


def mandatory_signal_types() -> frozenset[str]:
    """Mandatory filing scope (PRD §4.2): product_failed + BV critical."""
    return MANDATORY_FAILURE_TYPES | {f"{BV_SIGNAL_PREFIX}:{code}" for code in BV_CRITICAL}
```

## 6. 测试设计（铁律：真实组件、无 skip、负向先行）

- **写入↔消费 round-trip（核心）**：真实 `sqlite3` audit DB → `log_dispatch_end(..., findings=[真实 ReviewFinding.to_dict()], failure_class="product_failed")` → `DefectLedger.add` / `close` 反向消费解析成功。一个夹具验证两端。
- **向后兼容（负向）**：`log_dispatch_end` 不传新参 → details 恰为 `{success, duration}`，无 findings/failure_class key（逐 key 断言）。
- **C19 终态重算**：review-gate 失败 run（worker 全成功、gate 注入 blocking）→ 终态 `details["failure_class"]=="product_failed"` 且 `success==False`；worker 失败 run 重算幂等（与组装时刻值一致，既有传播测试即回归面）；成功 run `"none"`。
- **映射细化**：category=BREAK-2（warning）→ `review:break-vuln:BREAK-2`；category=missing_file → `review:spec:missing_file`；BV critical → `mandatory_signal_types()` 覆盖断言。
- **environment_blocked 拒绝（负向）**：audit 事件 `failure_class=environment_blocked` → `add --signal-ref ...&failure=environment_blocked` → exit 1 + 拒绝信息含排除依据。
- **既有断言更新（契约演进，非迁就 bug）**：[test_defect_ledger.py:100](../../tests/unit/test_defect_ledger.py#L100) `review:finding` → 按夹具 category 的细化值；W1 其余 38 测不动。
- **gate 未运行路径**：dispatch run 无 two_stage_review → end 事件无 findings key（断言不炸、不静默塞空表）。
