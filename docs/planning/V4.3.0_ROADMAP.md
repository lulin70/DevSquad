## 1. 合并背景

### 1.1 两线整合

V4.3.0 原有两条独立推进线，用户决策"合并为 V4.3.0 统一 PRD"（2026-07-25）：

| 推进线 | 来源 | 范围 | 共识状态 |
|--------|------|------|---------|
| **A 线 — 技术债+上游升级** | [V43_ROADMAP_PROPOSAL.md](./V43_ROADMAP_PROPOSAL.md) v1.2 | 9 项需求（P0-1/P0-2/P1-1/P1-4/P1-5/P1-6/P2-1/P2-2/P2-4） | 用户已确认 v1.2 |
| **B 线 — SDLC 用户故事** | [SDLC 评审共识](../analysis/2026-07-25_user_stories_review_consensus.md) | 4 个新模块（P0-3/P0-4/P1-7/P1-8） | 7 角色共识 0.9625 |

### 1.2 合并原则

1. **两条线并行不冲突**：A 线 9 项需求与 B 线 4 个新模块无代码冲突，可并行推进
2. **A 线保持原节奏**：A 线已用户确认 v1.2，按原 P0→P1→P2 顺序推进
3. **B 线按 Phase 0-4 稳扎稳打**：每 Phase 通过门禁才进入下一 Phase
4. **共享发布窗口**：两线在 V4.2.9 预发布 + V4.3.0 正式版统一发布
5. **防幽灵功能是 B 线硬约束**：每个新模块必须明确 Skill 调用链集成点

### 1.3 核心约束（来自用户）

| 约束 | 来源 | 落实方式 |
|------|------|---------|
| 防幽灵功能 | 用户 2026-07-25 指示 | Skill 调用链集成矩阵 + CI 模块活跃度检查 |
| 稳扎稳打 | 用户 2026-07-25 指示 | Phase 0-4 渐进推进，每 Phase 门禁 |
| 测试骨架先行 | 用户 2026-07-25 认可 | Phase 0 先建 8 个 E2E 骨架（xfail） |
| 文档先行 | project_memory Iron Rule | 本 Roadmap + PRD + 架构 + 测试方案先行 |
| 发布前 E2E + 真实用户模拟测试 | 用户规则 3 | V4.2.9 预发布前必做 |
