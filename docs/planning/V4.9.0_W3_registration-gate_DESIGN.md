## 1. 设计目标

1. **信号不许蒸发**（PRD 第一原则）：台账启用后，dispatch run 的强制范围信号（`failure:product_failed` + BV critical 四类）无 live 工单 → finalize FAIL。run 结束即蒸发的信号从此被闸门拦下。
2. **fail-closed**：gate 自身无法证明（台账损坏/不可读/内部错误）= FAIL，无静默放行。
3. **默认关闭**：未启用时 dispatch 全链路行为与 4.8.x 逐 key 一致（负向测试保证，PRD §4.3 启用条件）。
4. **advisory 面**：非强制范围信号（BV warning + spec 发现）不入闸，但 `defect audit` 输出未立案清单（PRD §4.2 表 + §9 开放点①裁定；W2 未认领，本文落地）。
5. 纯标准库、零新依赖、零 LLM（确定性侧资产）。

## 3. gate 语义

### 3.1 信号提取（RegistrationGate.evaluate 输入侧）

Step 23.6 时刻、从 post_dispatch 作用域直接取（D2）：

1. `failure_class_for_dispatch(worker_results, errors).value == "product_failed"` → 信号 `failure:product_failed`。
2. `two_stage_review_result.findings` 中 `finding.category ∈ BV_CRITICAL`（BREAK-1/BREAK-5/VULN-1/VULN-4）→ 信号 `review:break-vuln:<category>`；warning/spec 发现**不产生**强制信号。
3. 去重 + 排序（确定性输出）。

提取复用 W2 的常量面（`mandatory_signal_types()` 是强制分级单一事实源）；提取逻辑本身不复制映射表——只做"run 信号类型集合 ∩ 强制集合"。

### 3.2 台账核对（evaluate 核心）

```python
live_types = {e.signal["type"] for e in entries if e.state.value in ("open", "fixed")}
closed_types = {e.signal["type"] for e in entries if e.state.value == "closed"}
```

- 台账读取经 `DefectLedger(ledger_path).list_defects()`（fail-closed 加载校验随行，[defect_ledger.py:472-478](../../scripts/collaboration/defect_ledger.py#L472-L478)）；`DefectLedgerError` 上抛给 mixin → internal_error FAIL（D7）。
- 每个 run 强制信号类型三态归类：
  - ∈ live_types → `tracked`（附 tracked_by DEF 列表）；
  - ∉ live ∧ ∈ closed_types → `regressed`（violation："reopen required"）；
  - 两边皆无 → `unregistered`（violation）。
- **verdict = pass 当且仅当全部信号 tracked**（无信号 → 空集合通过，D7）。

### 3.4 v1 边界（诚实披露）

- **类型级匹配**（D3）：一个 live `failure:product_failed` 工单覆盖后续所有 product_failed run 的登记需求——同类型的新根因出现（occurrence）在既有 live 工单存续期间不会被闸门区分。闸门保证"该类型信号正被追踪"，不保证"每个 occurrence 都有独立工单"；区分根因是人工 triage 的职责（gate 红了以后人来判定：同缺陷→已有工单即出口，新缺陷→立案）。
- **review diff 通道不接**（PRD §4.3 接线点第二项）：lifecycle review 的 findings 只进 `result.details["lifecycle_findings"]`（[cli_lifecycle.py:409](../../scripts/cli_lifecycle.py#L409)），不写 audit DB、无 dispatch_end 事件——W2 §2 已裁定 v1 信号源=audit DB 单源，`add` 无法解析 diff 通道信号（无 ref 可指向），无立案面即无门禁面。PRD 该句在 W2 单源裁定后收窄为 dispatch finalize 单挂点；diff 通道若未来入库（W1 §5.1 `audit:` 前缀扩展位），gate 消费面不变（类型集合来自台账比对，与信号源解耦）。

### 4.2 dispatch_steps_mixins.py（`_run_registration_gate`，W4 mixin 先例）

```python
def _run_registration_gate(
    self,
    worker_results: list[dict[str, Any]],
    errors: list[str],
    review_result: TwoStageReviewResult | None,
) -> RegistrationGateResult | None:
    """Run the registration gate — mandatory signals need live tickets (Step 23.6).

    Returns ``None`` when the gate is disabled (zero trace — 4.8.x
    behavior, negative test ①). Fail-closed semantics (design D7): a
    corrupt/unreadable ledger or a gate-internal error still FAILs the
    run — inability to prove registration is a failure, never a silent
    pass (same discipline as the feature gate, W4 §4.2).
    """
    if not self.enable_registration_gate:
        return None
    findings = list(review_result.findings) if review_result is not None else []
    try:
        gate = RegistrationGate()
        result = gate.evaluate(worker_results=worker_results, errors=errors, findings=findings)
    except Exception as gate_err:  # noqa: BLE001 — fail-closed: gate crash = FAIL
        logger.warning("Registration gate failed: %s", gate_err)
        return RegistrationGateResult.internal_error(str(gate_err))
    if self.usage_tracker:
        self.usage_tracker.tick("registration_gate")
    return result
```

## 6. `defect audit` advisory 未立案提示（D11）

`registration_gate.py` 内 `unfiled_signal_report(ledger_path, audit_db_path)`：

1. 只读扫描 audit DB `dispatch_end` 事件 details 的 `findings`（W2 写入侧）→ 非强制类型集合（`category ∈ BV_CATEGORIES 但 ∉ BV_CRITICAL` → `review:break-vuln:<code>`；`category ∉ BV codes` → `review:spec:<category>`）；`failure_class` 不参与（非强制范围内无 failure 信号类型——none/环境阻断皆非缺陷信号）。
2. 台账 live 工单类型集合（`list_defects()`，state ∈ {open, fixed}）。
3. **advisory = 非强制已见类型 − live 类型**，逐项 `{"type", "seen_count", "last_event_id"}`。
4. audit DB 不可读 → 返回空 advisory + 警告行（advisory 是尽力披露，不劫持 invariant 部分的退出码语义）。

CLI（[cli_defect.py:145-157](../../scripts/cli_defect.py#L145-L157) `cmd_defect_audit`）：invariant issues 照旧（stderr FAIL: 行、exit 1）；advisory 追加 stdout `ADVISORY: unfiled <type> (seen N times, last event E)` 行；`--json` 输出增 `"unfiled_advisory": [...]` key。退出码只由 invariant 决定（D11）。
