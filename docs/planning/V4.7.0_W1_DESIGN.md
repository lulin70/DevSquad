## 3. 模块设计：`scripts/collaboration/review_taxonomy.py`（新，约 320 行）

### 3.1 公开接口

> 内部分发结构（共识修订 R-A1）：`check()` 是唯一公开入口；内部按类目**每类一个独立小函数**
> （`_check_break1` … `_check_vuln5`，与 `review_checkers` 既有风格一致），经模块级注册表
> `_RULE_TABLE: tuple[tuple[BVCategory, Callable], ...]` 分发——radon cc 单函数复杂度可控
> （A8/R3 风险缓解），且"删类目"必须同时动枚举与注册表两处（W2 C20 反向守护的两道靶）。

```python
BV_CRITICAL: frozenset[str]  # {"BREAK-1", "BREAK-5", "VULN-1", "VULN-4"}

@dataclass(frozen=True)
class BVCategory:
    code: str            # "BREAK-1" … "VULN-5"
    name: str            # "entry_point_break"
    severity: str        # "critical" | "warning"
    description_zh: str
    description_en: str

BV_CATEGORIES: tuple[BVCategory, ...]   # 恰好 10 项，顺序 BREAK-1..VULN-5

def classify_input(files: list[tuple[str, str]]) -> str
    """输入三分判定（共识修订 R-S1，禁止"未检查"伪装成"不适用"）：
    - "applicable"   —— 命中可检测对象，跑十类检查
    - "empty"        —— files 为空或全部内容为空 → 真 N/A（诚实披露 not_applicable）
    - "unparseable"  —— files 非空但无有效 (path, content) 元组（意外形态，如实测
       `_iter_file_contents` 对 str 形态静默返回 []）→ 披露 "unparseable_input"，
       绝不输出 not_applicable。委托层据此区分三种 scope info。"""

def check(files: list[tuple[str, str]], line_no_of: Callable) -> list[tuple[str, str, int, str]]
    """返回 (category_code, rule_id, line_number, description) 四元组列表。
    纯函数、零 IO、零 LLM；severity 由 BVCategory 查表，不由调用方决定。
    line_number 为 int，由委托层（持有文件上下文）的逐行扫描回调提供（共识修订 R-C1）。"""
```

设计约束：

1. `BV_CATEGORIES` 长度断言 = 10，编号连续（W2 契约 C20 的反向守护基础：删类目 → 单测红）。
2. severity **只**由查表产生（Q2 裁定固化在代码里，调用方无法覆盖）。
3. 行号 = int，写入 `ReviewFinding.line_range`（现有字段，judge_agent 已消费）——见 §6.1 行号策略（共识修订 R-A2）。

## 4. 十类规则定稿（V1）

> 通用误报控制：所有比对仅在**同文件**或**同 changeset** 可见范围内进行；跨文件/既有路由表不可见时该类自动降级为不适用（计入 scope 披露，不报发现）。

### 4.1 适用性判定（applicability）

任一文件命中以下任一模式即 applicable：

- 路由装饰器：`@(?:app|router|bp|blueprint|api)\.(?:get|post|put|delete|patch|route|api_route)\s*\(`
- Django URLconf：`urlpatterns\s*=` 或 `path\s*\(\s*['"]` 或 `re_path\s*\(`
- 导航配置字面量：`url_for\(|reverse\(|redirect\(|router\.push\(|href=["']/`

### 4.2 十类规则

| 编号 | severity | rule_id | 检测逻辑 | 误报控制 |
|---|---|---|---|---|
| BREAK-1 | critical | `BV-BREAK1-route-without-handler` | 路由装饰器块的下一非空行不是 `def`/`async def`（装饰器叠加视为同一块） | 仅检查**新增文件**与 diff 上下文内的装饰器；name= 引用式注册不检（无函数体可比） |
| BREAK-2 | warning | `BV-BREAK2-handler-no-return` | 路由 handler 函数体（至下一同缩进 def/装饰器）内无 `return` 语句且体非空 | 函数体 <3 行跳过；含 `yield`/`response` 参数名跳过（streaming 类） |
| BREAK-3 | warning | `BV-BREAK3-write-endpoint-unguarded` | 同文件写方法（post/put/patch/delete）handler ≥2 个时，其余都有守卫模式（`Depends(get_current_user)`/`require_auth`/`login_required`/`permission`/`token` 装饰器或参数），唯独该 handler 全无 | 只在"同文件存在已守卫的同类 handler"作对比时才报；孤立 handler 不报 |
| BREAK-4 | warning | `BV-BREAK4-undefined-call-in-handler` | handler 函数体内 `Name(` 调用，Name ∉ 同文件 def/class/赋值/import 集合 ∪ 内置白名单（~120 名）∪ 框架常见名（request/response/HTTPException/JSONResponse…） | 仅同文件比对（跨文件 import 走 from-import 集合）；白名单未覆盖的内置名靠 `builtins` 模块动态取集 |
| BREAK-5 | critical | `BV-BREAK5-nav-target-missing` | 导航/跳转字面量目标（`url_for("name")`、`redirect("/path")`、`router.push("/path")`、`href="/path"`）在**changeset 全部路由注册集合**中无匹配（名称或路径比对） | 仅当 changeset 内存在 ≥1 个路由注册才启用；`http(s)://` 外链与 `#` 锚点跳过 |
| VULN-1 | critical | `BV-VULN1-orm-object-returned` | `return` 语句直接链式 ORM 调用：`return\s+(?:await\s+)?(?:db|session|query|q)\.(?:query|all|first|get|scalar|scalars|execute|fetchall|fetchone)\s*\(` | 只报此保守模式；模型变量直传不报（无法确证类型） |
| VULN-2 | warning | `BV-VULN2-writes-without-commit` | 同一函数体内写调用（`.add(`/`.delete(`/`.update(`/`.save(`/`.execute(`（写 SQL 关键词））≥2 且函数体无 `commit`/`transaction`/`atomic` 上下文 | 函数体内出现任一 commit/atomic 词即整体跳过 |
| VULN-3 | warning | `BV-VULN3-endpoint-unreferenced` | changeset 内新增端点的路径字符串在整个 changeset 非注册行内容中零出现 | 与 BREAK-5 对偶；仅同 changeset 比对，既有调用方不可见时不报（改为 scope 披露）——**实现即"changeset 内引用集合为空且 changeset 无路由注册以外的引用"** |
| VULN-4 | critical | `BV-VULN4-write-endpoint-no-validation` | 写方法 handler 的参数含 body 模型迹象（`data:`/`payload`/`Body(`/`schema` 类型注解）且函数体内无任何校验迹象（`validate`/`check_`/`if not`/`raise.*HTTPException\(4`） | 完全无校验迹象才报；GET/HEAD 不适用 |
| VULN-5 | warning | `BV-VULN5-route-prefix-inconsistent` | 同文件路由路径 ≥3 个时，最长公共前缀（按 `/` 段聚类）占比 ≥70% 而该端点不在众数前缀簇 | 前缀簇 <2 段（如仅 `/`）不报；健康检查类路径（`/health`、`/metrics`、`/ping`）白名单 |

## 6. 关键设计决策与权衡

### 6.1 行号：写入现有 `line_range` 字段（共识修订 R-A2，推翻初版方案）

初版方案（`file_path="path:line"`）基于"A3：`ReviewFinding` 无行号字段"的断言——**团队评审的结构探针推翻了该断言**：`line_range: str = ""` 字段已存在（`two_stage_review_gate.py:122`），`to_dict` 已序列化（`:138`），且 `judge_agent.py:433,551` 有真实消费。因此：

- **选定**：行号写入 `line_range`（单行发现为 `"N"`），`file_path` 保持纯路径。语义正确、消费方现成，与初版方案同等侵入性（零 dataclass 改动）。
- 否决（初版）：`file_path` 携带行号——污染字段语义，且丢弃了现成的结构化行号通道。
- 性能（共识修订 R-C1）：行号由委托层**一次 `enumerate(content.splitlines())` 逐行扫描**提供（`check(files)` 接受逐行上下文），不采用 per-match `content[:pos].count("\n")`（每次匹配 O(size)，大 changeset 上退化）。

### 6.2 N/A 披露用 info finding 而非新 result 字段

`TwoStageReviewResult` 无 scope/dict 附加通道；新字段 = 改 dataclass + 渲染 + 测试三处。info finding 走现有 Informational 渲染（A4），零结构改动即达 G2。category 固定 `break_vuln_scope`，W2 契约可锁定其存在性。

### 6.3 severity 只能查表产生（Q2 裁定固化）

`check()` 返回四元组，severity 由 `review_checkers` 委托层查 `BV_CATEGORIES`——调用方（含未来其他 checker）无法传 severity 覆盖。分级裁定（critical = BREAK-1/5 + VULN-1/4）在代码中不可变。

### 6.4 保守性声明（诚实边界，入 C20 文本）

- 所有"引用/注册"比对仅限 changeset 可见范围——**跨文件既有路由表不可见**，因此 BREAK-5/VULN-3 在独立小 changeset 上可能漏报（宁漏勿误的代价，如实披露）；
- 纯 regex 对动态注册（循环注册、装饰器工厂）不敏感——此类归 LLM 角色判定；
- 本分类学是**设计产物质量**检查，与 `FailureClass`（运行时失败分类学）职责不重叠。
