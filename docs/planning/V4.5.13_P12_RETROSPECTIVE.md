## 2. 教训（Lessons Learned）

- **L-V4513-001（技能重复 = 多层注册，缺失 = 未进索引）**: "/" 面板重复的根因是同一技能在 4 层（`~/.trae-cn`、`~/.trae`、工作区 `.trae`、项目 `.trae`）各注册一份；不显示的根因是技能未进 `skills-index.json` 注册索引（磁盘有文件 ≠ 已注册）。治理顺序：先收敛副本数，再核对注册索引。
- **L-V4513-002（counter 命名要对齐 exposition 归一化）**: prometheus_client 对 Counter 暴露时自动追加 `_total`；直接用裸名注册会让 ALERT_RULES 表达式查不到序列（4 处测试失败暴露）。指标命名必须以最终 exposition 样本名为准。
- **L-V4513-003（monkeypatch 目标决定埋点是否被测到）**: 测试 patch `store._open_lock` 本身导致其内部的信号埋点永远不执行（assert 0 >= 1）；正确做法是 patch 更底层的 `_acquire_lock`，让被测埋点路径真实运行。
- **L-V4513-004（沙箱 python3 解析不稳定）**: 同一终端会话中 `python3` 在 CommandLineTools 3.9 与 pyenv 3.12 之间漂移（conftest 的 `list[str] | str` 在 3.9 下崩溃）。长命令一律显式 `/Users/lin/.pyenv/versions/3.12.13/bin/python3`。
- **L-V4513-005（时序性失败要跑"单点 + 全文件"双重复核）**: `test_concurrent_dispatch_stability` 全量回归失败但与本迭代改动零调用关系——单跑 passed + 全文件 6/6 passed 才能定性为时序性；只跑单点不足以下结论。
- **L-V4513-006（诚实三态契约防伪造 PASS）**: 采集脚本强制 `success | timeout | fail_closed` 三态且 timeout 使进程 exit 1——外部依赖型验证（真实 IDE 监听方）必须让"没验证到"不可伪装成"验证通过"。
