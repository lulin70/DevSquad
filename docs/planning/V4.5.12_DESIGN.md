## 2. 组件变更

### 2.1 `scripts/collaboration/file_risk_store.py`（新增 Stats 维度）

- 新增 `RiskStoreStats` dataclass：
  - `capacity: int`（最近一次 `load` 的 `len(items)`）
  - `concurrent_writes_1m: int`（滑动窗口 60s 内的写次数）
  - `cross_host_lock_signals: int`（跨主机锁信号计数，初始化 0）
  - `slow_query_signals: int`（复杂查询慢信号计数，初始化 0）
  - `last_updated: float`（stats 上次更新时间，`time.monotonic`）
- `FileRiskStore.__init__` 后：`self.stats = RiskStoreStats(...)`
- `load/save/transaction` 每次执行：
  - 维护 `capacity`（`len(payload.get("items", []))`）
  - 维护 `concurrent_writes_1m`（`threading.Lock` + 滑动窗口 deque，过期弹出）
- 新增 `record_cross_host_signal()` 方法：在 `flock` 失败 + `errno == ESTALE` 或 `lock_path` 路径主机名不匹配时调用
- 新增 `record_slow_query(duration_ms)` 方法：`_filter_risks` 中涉及扫描 + 排序耗时 > 50ms 时调用
- 抗并发：`stats` 更新用 `threading.Lock`，不阻塞主 IO 路径
- 不引入 Prometheus client 依赖：`RiskStoreStats` 仅是 dataclass；Prometheus metric 在 `cli_metrics.py` 单独暴露

### 2.2 `scripts/cli_risks.py`（`risks stats` 子命令 + `--severity` 删除）

- 新增 `cmd_risks_stats(args)` 子命令：
  - 接受 `--register-id` / `--root` / `--format text|json`
  - 输出 4 项 stats + last_updated
- `_format_stats(stats, fmt)` 输出文本/JSON（文本用 tabular，JSON 单行 dict）
- 注册 `p_stats` argparse：
  - 与 `p_list/p_show/p_add/p_clear/p_export/p_assess/p_mitigate/p_close` 并列
- `--severity` 删除：
  - `_filter_risks` 删除 `severity = getattr(args, "severity", None)` + `elif severity:` 分支 + WARNING 打印
  - `_looks_numeric` helper 删除（仅 `severity` 字符串模式分支用到）
  - `p_list/p_show/p_export` argparse 不再注册 `--severity`
  - `p_add` 无 `--severity`（原本就没有）
  - `_validate_probability` 保留（`--min-exposure` 仍用）

### 2.3 `scripts/cli_metrics.py`（新增 4 metric）

- `V452_METRICS` 列表新增：
  - `devsquad_v4512_risk_store_capacity`（gauge，label_keys=["register_id"]）
  - `devsquad_v4512_risk_store_concurrent_writes`（counter，label_keys=["register_id"]）
  - `devsquad_v4512_risk_store_cross_host_signals`（counter，无 label）
  - `devsquad_v4512_risk_store_slow_queries`（counter，label_keys=["register_id"]）
- `V4512_METRICS` 列表独立维护（与 `V452_METRICS` 风格对齐）
- `_collect_metric_samples(metric_name)` 扩展支持 `v4512_risk_store_*` 采集：从 `FileRiskStore.stats` 实例读
- 若 prometheus_client 不可用：仅输出 stub summary（与 V4.5.2 行为一致）

### 2.4 文档（ALERT_RULES + RUNBOOK + ROLLBACK）

- `docs/operations/ALERT_RULES.md`：
  - 新增 V4.5.12 章节，4 条规则：
    - `SQL-1 RiskStoreCapacityHigh`：`devsquad_v4512_risk_store_capacity > 10000` for 1h → critical（V4.5.10 §6 触发条件 1）
    - `SQL-2 RiskStoreConcurrentWriteHigh`：`rate(devsquad_v4512_risk_store_concurrent_writes[5m]) > 100/分钟` for 30m → warning（触发条件 4）
    - `SQL-3 RiskStoreCrossHostSignal`：`increase(devsquad_v4512_risk_store_cross_host_signals[1h]) > 0` for 5m → critical（触发条件 3）
    - `SQL-4 RiskStoreSlowQueryHigh`：`rate(devsquad_v4512_risk_store_slow_queries[1h]) > 10` for 30m → warning（触发条件 2）

## 4. 已知行为变化（Breaking / Notice）

1. **`risks list/show/export --severity` 移除**：直接 argparse error exit 2，迁移到 `--min-exposure`（数值过滤）或 `--category`（字符串过滤）。
2. **`FileRiskStore` 暴露 `stats` 属性**：新增 4 个只读字段，对外只读；不影响持久化 schema。
3. **TRAE IDE 真实联调证据归档**：v2 adapter 在真实场景下行为字节级与 V4.5.10 fake host runner 一致。
4. **ALERT_RULES 新增 4 条规则**：SQL-1 ~ SQL-4，监控 SQLite 重立项触发条件。
