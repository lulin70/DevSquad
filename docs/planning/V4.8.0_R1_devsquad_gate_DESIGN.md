## 1. 设计目标

外部仓库一行接入后，每个 PR 自动获得一次确定性 review（零 LLM、零 key、零 secrets 默认）：
结构化评论（协议 v1）+ fail-closed 退出。检查能力全部来自既有资产，不新增检查逻辑。

**硬约束**：

- 评论协议复用 V4.6.0 P2-b 形态（4 字段 + run URL + 幂等 `--edit-last`），字段集适配 review 场景（§4）。
- 权限最小集：`contents: read` + `pull-requests: write`。
- secrets 不回显；judge（可选）沿用 `DEVSQUAD_JUDGE_*` 隔离。
- reusable workflow 在**调用方工作区**运行：步骤不得引用本仓文件，全部自含于 YAML + PyPI 安装的 CLI + runner 预装 `gh`。
- Action 引用全部 pin 到完整 commit SHA（V4.5.23 供应链规则）。

## 2. 分发形态

### 2.1 本仓新增（唯一代码物）

`.github/workflows/devsquad-gate.yml` —— `on: workflow_call` 可复用工作流：

```yaml
name: devsquad-gate
on:
  workflow_call:
    inputs:
      devsquad-version:  { type: string, default: "4.7.2" }   # 发布时意识性 bump
      task:              { type: string, default: "devsquad-gate: deterministic PR review" }
      include:           { type: string, default: "" }        # 逗号分隔路径过滤，空=不过滤
      exclude:           { type: string, default: "" }
      fail-on:           { type: string, default: "break" }   # break | any
      preview-only:      { type: boolean, default: false }     # 定价模式：只跑 --preview，exit 0
permissions:
  contents: read
  pull-requests: write
```

### 2.2 消费方 wrapper（文档交付物，随 R2 写入 QUICKSTART；本设计附模板）

```yaml
name: devsquad-gate
on:
  pull_request:
jobs:
  devsquad-gate:
    uses: lulin70/DevSquad/.github/workflows/devsquad-gate.yml@v4
    permissions:
      contents: read
      pull-requests: write
    secrets: inherit
```

- ref 策略：消费方 pin 主版本 tag（`@v4`）；本仓发布流程为当前主版本维护该 tag（RELEASE_CHECKLIST 增一步）。
- `secrets: inherit`：把调用方 `GITHUB_TOKEN` 传入被调工作流（`gh pr comment` 所需）。judge 为可选项：消费方自配 `DEVSQUAD_JUDGE_*` secrets 时才启用语义断言；缺省确定性层独立运行。

### 2.3 试装仓（锁定）

**zeroclaw**（lulin70/zeroclaw）。理由：最小（1069KB）；私有（试装 PR 评论噪音无害）；2026-08 后休眠（不干扰在途开发）；Rust 仓（证明 gate 的 diff 面向不依赖 Python 目标语言）。PRD §8 开放点就此关闭。

## 3. Gate 作业流程（单一 job `gate`，ubuntu-latest）

```
checkout(PR merge ref, 消费方代码)            [actions/checkout@SHA]
setup-python 3.11 + pip install devsquad==$INPUT(devsquad-version)
curl ${{ github.event.pull_request.diff_url }} -o /tmp/pr.diff
devsquad review --diff-file /tmp/pr.diff --task "$INPUT(task)" \
       --format json [--include ... --exclude ...] > /tmp/gate.json ; GATE_EXIT=$?
（preview-only=true 时改为 review --preview，只评论定价摘要，exit 0）
python 内联脚本（YAML here-doc，约 40 行）:
    解析 gate.json → 判定 verdict（§5）→ 组装 4 字段评论（§4）
gh pr comment $PR --body-file /tmp/comment.md --edit-last --create-if-none   [continue-on-error]
exit 按 verdict（§5 矩阵）
```

要点：

- diff 来源 = `github.event.pull_request.diff_url`（GitHub 生成的权威 diff，避免本地 diff 策略分歧）。
- 双通道判定：**verdict 由 JSON findings 驱动**。V-1 已验证（2026-10-21，§7.1）：零 key 下 `review --diff-file` 退出码恒 0，diff 中的模式命中当前不产出结构化 findings——需先按 §7.1 接线既有模式扫描，verdict 判定才有效；退出码仅作 blocked 兜底信号。
- `concurrency: cancel-in-progress` 按 PR 分组，PR 连续 push 不重复烧 runner。
- `timeout-minutes: 15`。
- 评论失败 `continue-on-error: true`——评论是披露面，不改变判定结果；失败在日志可见。

## 4. 评论协议 v1

形态沿用 V4.6.0（4 结构化字段 + run URL + 幂等），字段集适配 review：

```markdown
## devsquad-gate 审查结果
<!-- devsquad-gate v1 -->

Run: <run URL>

- verdict: pass | fail | blocked
- findings: BREAK x / VULN y / total z
- failure_class: product_failed | environment_blocked | n/a
- coverage: <reviewed files> reviewed / <dropped> dropped (by gate)
```

- `<!-- devsquad-gate v1 -->` HTML 锚点同时承担协议版本标识与幂等目标定位（配合 `--edit-last`）。
- 无自由 LLM 文本；字段值全部来自 gate.json 白名单键，杜绝 secrets 泄入评论。
- pass 也评论（消费者可见"gate 跑了且干净"），同样幂等更新。

## 5. fail-closed 判定矩阵

| 场景 | verdict | 退出 | 评论 |
|---|---|---|---|
| findings 计数 > 0 且命中 fail-on（break：BREAK 类；any：任意 finding） | fail | **1** | 四字段 |
| findings = 0 | pass | 0 | 四字段 |
| gate.json 未产出 / JSON 解析失败 | blocked | **2** | blocked 披露（不谎报绿） |
| pip install 失败 / CLI 崩溃 | blocked | **2** | best-effort blocked |
| diff 为空 | pass | 0 | coverage 0/0 |
| judge secrets 缺失（消费者启用 judge 时） | 确定性层结论照常 | 按上表 | judge=blocked 单列披露 |
| 评论 API 失败 | 判定不变 | 按上表 | 日志披露 |

## 6. 安全设计（Security 评审）

| 面害 | 处置 |
|---|---|
| secrets 回显 | 评论组装只读 gate.json 白名单键；workflow `set +x` 不用于含 secrets 段（本 workflow 默认无 secrets 段）；GitHub 自动 mask 双保险 |
| 权限提升 | 被调工作流声明与消费方 wrapper 同为最小集；被调方无法越权（GitHub 语义：被调权限 ≤ 调用方授予） |
| 供应链 | checkout / setup-python pin 完整 SHA；devsquad 从官方 PyPI 按 `==` 精确版本安装 |
| judge 注入 | `DEVSQUAD_JUDGE_*` 独立命名空间，绝不回落；缺省时 judge 完全不运行 |
| diff_url 伪造 | diff_url 由 GitHub 事件提供，TLS 传输；非用户可控输入 |

### 7.1 实现期验证结果与设计修正（2026-10-21，rev2）

**V-1 探针证据**（keyless 探针，凭据五变量置空——与 acceptance_local.sh 同法；首次探针曾误用本地 `moka_ai.json` 走真实后端 60s，作废重跑，教训：CLI 行为探针必须凭据置空）：

| 探针 | 输入 | 结果 |
|---|---|---|
| keyless（正确） | `/tmp/sample.diff`（含 TODO 注释与 `print(` 调试调用各一处） | `lifecycle_findings=[]`，退出码 0 |
| 对照（真实 Moka 后端） | 同输入 | `lifecycle_findings=[]`，退出码 0（与后端无关） |

**结论**：`review --diff-file` 当前不把 diff 中的模式命中转为结构化 findings，退出码恒 0——§5 矩阵的"findings > 0"行在现状下永不触发，T-4 失败注入不可实现。

**根因**：确定性反模式正则已存在于生产代码 [review_checkers.py:52-82](../../scripts/collaboration/review_checkers.py#L52-L82)（`_ANTI_PATTERN_REGEXES`：todo_left `\b(?:TODO|FIXME|XXX|HACK)\b`、print_debug `\bprint\s*\(`；另有 `_SECRET_PATTERNS`、`_SQL_INJECTION_PATTERNS`），但 review 的 diff 输入通道未接线这些检查器——模式扫描在其他路径运行，diff review 路径漏接。

**设计修正（接线既有模式扫描，零新检查逻辑）**：在 review 的 diff 处理路径接入 ReviewCheckers 既有三类正则，命中产出结构化 findings（severity 沿用 ReviewCheckers 既有分类）写入 `lifecycle_findings`。依据：

- PRD §4.1 已确认范围为"打包 review_checkers"（既有能力的 diff 面接线），本修正是其原义实现，非范围变更，不需重新裁定（2026-10-21 用户跳过处置提问，按推荐项执行；执行计划 §10 补记随本批合并链追加）。
- 设计 §1 硬约束"检查能力全部来自既有资产，不新增检查逻辑"完全保持——接线不新增任何正则或检查规则。
- 修正后 §5 判定矩阵语义成立（findings > 0 → fail；exit 仅兜底 blocked）；T-4 失败注入可行（diff 注入 TODO/print 命中 → findings > 0 → verdict=fail）。

### 7.2 T-3 第一段试装发现与修正（2026-10-22，两段式裁定之发布前机制段）

按执行计划 §10 两段式裁定执行发布前机制性试装（zeroclaw，显式 `devsquad-version: 4.7.2` + `@main` ref）。发现并修正两处缺陷：

| # | 发现 | 根因 | 修正 |
|---|---|---|---|
| F-1 | caller 不授予 `permissions: pull-requests: write` 时 run 以 startup_failure 结束（无 job 创建，GitHub 拒绝被调方权限超过调用方 token） | QUICKSTART 通道 C 示例转写设计 §2.2 模板时丢失 `permissions` 块（设计本身正确） | QUICKSTART 通道 C 示例补 `permissions: contents: read, pull-requests: write` + 失败说明注释；zeroclaw wrapper 同步修复后试装跑通 |
| F-2 | 私有消费仓 diff 拉取恒 blocked：`curl ${{ github.event.pull_request.diff_url }}` 匿名请求对私有仓 404 → fetch-failed → 诚实 blocked（fail-closed 行为正确但 pass 路径不可达） | 设计 §3 假定 diff_url 可匿名拉取（公开仓成立，私有仓不成立） | gate fetch 步骤改认证拉取：token 走 env（`GH_TOKEN`），`-H "Authorization: Bearer $GH_TOKEN"`；token 不入 shell 内插（沿 §6 注入防护约定） |

**机制面验证记录**（试装 run 39733914040）：workflow_call 触发 ✓；评论协议 v1 完整（4 字段 + 锚点 + blocked_reason）✓；fail-closed 语义 ✓（blocked → exit 2）；幂等性验证见试装证据目录 `docs/e2e_evidence/V4.8.0_devsquad_gate_trial/`。
