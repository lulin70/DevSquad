## 7. Lessons Learned (6 条)

1. **L-V459-001 (aexecute 桥接目标偏离 DESIGN 的权衡)**：DESIGN 草案写的是
   `await backend.generate`，实施时发现契约接口为 `AsyncLLMBackendInterface` 的
   execute 语义。为满足「核心 56 测试零修改」（AC-C2 硬约束）选择了 execute 入口 +
   接口 duck-type 检测。教训：当行为兼容硬门槛与设计理想冲突时，兼容门槛优先，
   偏离必须在复盘显式登记，不允许静默替换。
2. **L-V459-002 (CPython bpo-32528)**：真 E2E 发现 `gather(return_exceptions=True)`
   不捕获子任务 `KeyboardInterrupt`/`SystemExit`——官方语义如此而非 bug。防御必须
   放在任务包装层（BaseException → `WorkerResult(success=False)`），gather 核保持
   纯粹。教训：CPython 标准库的边界语义要靠真实 E2E 而非单元 mock 暴露；文档化的
   "return_exceptions 捕获一切异常"是误解。
3. **L-V459-003 (全局 LLM cache 跨测试污染)**：gather 并发测试共享全局 LLM cache
   导致断言互相污染（前序测试的缓存命中让后续断言失真）。用唯一任务描述
   （每测试独立 prompt 文案）隔离。教训：全局单例缓存的测试必须键空间隔离，
   monkeypatch 模块级状态不如让输入天然唯一。
4. **L-V459-004 (Worker `__slots__` 阻止实例级 monkeypatch)**：Worker 使用
   `__slots__`，测试无法实例级 patch 方法。改用子类覆盖或类级 patch。教训：
   `__slots__` 是性能优化也是测试约束，新增 slots 类要预留测试注入面（子类化路径）。
5. **L-V459-005 (PRD 措辞与实际开关不符)**：PRD/E2E 写 `--async` CLI 旗标，实际
   异步路径开关是 `DEVSQUAD_USE_ASYNC=1` 环境变量。旅程 B 落地前先验证了 CLI 真实
   行为再执行。教训：PRD 中的 CLI 语法必须与实现核对（grep 参数注册表），
   文档措辞不能当作接口契约。
6. **L-V459-006 (R3 风险真实兑现：async 宿主内调 sync 入口的存量缺陷显形)**：
   全量回归发现 `tests/e2e/test_api_user_journey_e2e.py` 失败——API `dispatch_task`
   async 端点直接在 uvicorn 事件循环内调用同步 `dispatcher.dispatch()`，被 V4.5.9
   running-loop 快速失败 raise 拦截（PRD R3 预测的风险）。修复：端点内
   `run_in_executor` 把阻塞调用移出事件循环（`scripts/api/routes/dispatch.py`），
   同时消除旧版阻塞事件循环的隐患。修复后 7/7 通过。教训：fail-fast 桥接的 raise
   不是回归而是让错误用法显形；异步化改造前必须盘点所有 "async 宿主内调 sync
   入口" 的调用点，并把 "现有 E2E 全部跑通" 作为发布门禁而非可选验证。
