## 5. Lessons Learned (5 Lessons, 0 Unknown)

#### L-V456-001: Counter Rename Requires Manual `global` Fix

When bulk-renaming `_call_counter` → `_call_counter_er` across 74 files:

```python
# BEFORE (works):
global _call_counter
_call_counter += 1

# AFTER (if sed only replaces identifier, NOT `global` statement):
global _call_counter  # ← UnboundLocalError
_call_counter_er += 1  # ← creates NEW local
```

**Fix**: per-module grep for `global _call_counter\b` and manually update.
A second sed pass for `global _call_counter_er` caught 14 missed instances.

**Lesson**: bulk rename tools (sed, pyupgrade, rope) handle identifiers
but NOT language keywords like `global`. Always grep for the keyword
context after a rename.

#### L-V456-002: noqa Suppression Needs Multi-Line Window

When the detector (`test_quality_guard.py`) flags a test that uses
`AntiPatternDetector` to test itself, the fixture string often spans
multiple lines:

```python
code = (
    "@lru_cache\n"
    "def get_config():\n"
    "    return load_config()"  # noqa: test-quality ← but detector flags line 1
)
```

**Original behavior**: `_is_noqa_suppressed(source, 1)` only checks line 1,
which has no noqa → not suppressed → false positive MAJOR.

**Fix**: extended to 8-line window:
```python
for offset in range(0, 8):
    idx = line_no - 1 + offset
    if 0 <= idx < len(lines) and "# noqa: test-quality" in lines[idx]:
        return True
```

**Lesson**: Detectors that test themselves need either (a) noqa on the
EXACT matched line, or (b) a multi-line window for multi-line fixtures.

#### L-V456-003: Real-LLM Smoke Tests Need Opt-In Skip

When `MOKA_API_KEY` is set but invalid (e.g., rotated key still in `.env`),
real-LLM smoke tests previously failed with `AuthenticationError: 401` in CI.
This produced noisy failures unrelated to actual code changes.

**Fix**: Added `DEVSQUAD_SKIP_INVALID_LLM_KEY=1` (default) with HEAD
validation to `/models` endpoint + autouse fixture `_skip_if_invalid_key`.

**Lesson**: Smoke tests with real-API dependencies should be opt-in by
default; environment-driven skip-with-explicit-reason is cleaner than
hard `skipif` on key presence alone.

#### L-V456-004: Anti-Pattern Detector False-Positive Rate

Initial `anti-status-code-only` rule had **66 false positives** because
it didn't distinguish:

```python
# REAL anti-pattern: status_code alone
assert response.status_code == 200  # ← 0/66 of actual anti-patterns

# LEGITIMATE: status_code + side-effect within 5 lines
assert response.status_code == 200
body = response.json()
msg = body.get("message", "")
assert "Invalid" in msg  # ← 64/66 are this pattern
```

**Fix**: Added `_has_side_effect_check(lines, idx)` with extended
side_effect_patterns list (body=, data=, msg=, json(), assertIn, in
headers, location=, etc.).

**Lesson**: Anti-pattern detectors need 5-line context for legitimate
assertions, not single-line matching. False positive rate went from
66 → 0 with the same semantic intent preserved.

#### L-V456-005: PATCH Releases Need Full P1-P12 Lifecycle

Even "pure maintenance" releases should go through:
- P1-P3: PRD/Consensus/Design (even if brief — 1-line summary is fine)
- P4-P5: Implementation
- P6: Validation gates
- P7: Doc sync (CHANGELOG, RELEASE_NOTES, retrospective)
- P8: Version sync across all files + caches
- P9: commit + tag + push
- P10: Ops (skip if no new modules)
- P11: CarryMem retrospective
- P12: Closure review

**Lesson**: Skipping any phase for a "minor" release creates tech debt
that compounds. The 1-hour investment in full lifecycle pays back in
release quality.
