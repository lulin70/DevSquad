## 1. 设计决策

### 1.1 范围

本版只交付三项主功能：

1. File-backed Risk Store：解决 `cli_risks.py` 模块级 `_RISK_STORE` 仅进程内共享的问题。
2. 风险 CLI 增量命令：补齐 `add/assess/mitigate/close`。
3. Exposure 过滤：新增 `--min-exposure`，保留 `--severity` 兼容路径，并提供 `--category`。

`Coordinator._execute_parallel` 默认迁移到 `asyncio.gather` 不在本版范围，推迟到 V4.5.9；`Worker.execute` 原生 async 化推迟到 V4.5.10。

### 1.2 分层

```text
RiskRegister             领域模型、状态转换、7-role weighted assessment
        │
FileRiskStore             JSON schema、路径校验、锁、原子写、load/save/transaction
        │
cli_risks.py              argparse、命令处理、输出格式、exit code
        │
scripts/cli.py           主 CLI 注册与路由
```

不让 CLI 直接操作文件，也不让 RiskRegister 依赖 argparse。纯内存 `RiskRegister()` 用法继续有效。

## 2. FileRiskStore 设计

### 2.1 文件布局

```text
.devSquad_data/
└── risks/
    ├── default.json
    └── default.lock
```

默认路径：项目当前工作目录 `.devsquad_data/risks`。允许通过 CLI `--register-id` 选择逻辑 register，但根目录固定在 `.devsquad_data/risks`，不接受任意用户路径。

JSON schema v1：

```json
{
  "version": 1,
  "register_id": "default",
  "items": [
    {
      "id": "R-...",
      "description": "...",
      "probability": 0.7,
      "impact": 0.9,
      "response_strategy": "accept",
      "owner": "",
      "status": "open",
      "category": "technical"
    }
  ]
}
```

`exposure` 是派生字段，不作为持久化真相；读取后由 `RiskItem.exposure` 计算。

### 2.2 安全与一致性

- `register_id` 使用 `^[A-Za-z0-9_-]{1,64}$`，拒绝空值、`..`、路径分隔符、控制字符和 symlink 目标。
- 所有目标路径使用 `Path.resolve()` 与风险根目录 `commonpath` 校验。
- 根目录自动创建；目标文件若已是 symlink 直接拒绝。
- 写入流程：同目录临时文件 → `json.dump` → flush + fsync → `os.replace`。
- Unix 使用 `fcntl.flock(LOCK_EX | LOCK_NB)` 重试至 `lock_timeout`；Windows 使用 `msvcrt` 等价实现。
- `transaction()` 在锁内完成 load → 调用方修改 → save，避免 read-modify-write 丢失更新。
- JSON 损坏抛出明确 `RiskStoreError`，CLI 返回 exit code 3，不静默清空风险。

### 2.3 RiskRegister 集成

保持既有 API 默认行为：

```python
register = RiskRegister()                         # 纯内存，兼容
register = RiskRegister.from_store(store, "default")  # 文件加载
```

推荐实现方式是 FileRiskStore 负责 dict/list 序列化，RiskRegister 增加：

- `from_items(items)`：从 `RiskItem` 集合建立内存 register。
- `items()`：返回当前风险项快照。
- `to_dict()` / `from_dict()`：只处理领域模型，不处理路径和锁。

状态变更由 CLI 在 `transaction()` 上下文中执行，避免给每个已有方法增加 store 参数导致 API 扩散。

## 3. CLI 设计

### 3.1 公共参数

所有 risks 子命令支持：

```text
--register-id ID       default: default
--root PATH             仅测试/高级调用使用；生产 CLI 默认固定项目数据目录
```

### 3.2 命令映射

| 命令 | RiskRegister API | 审批 |
|---|---|---|
| `add` | `add(...)` | 否 |
| `assess` | `assess(id, votes)` | 否 |
| `mitigate` | `mitigate(id, strategy, owner, plan)` | 否 |
| `close` | `track(id, RiskStatus.CLOSED)` | 默认需要显式 `--require-approval` 才触发；触发但不可用时 fail-closed |
| `clear` | 删除全部 | 既有 `--require-approval` 语义改为不可用时 fail-closed |

`close` 不新增 RiskRegister.close()，避免产生两套状态转换语义。

### 3.3 输出与错误码

- list/show/export 的 JSON 字段继续使用 V4.5.7 schema。
- add/assess/mitigate/close 成功输出 JSON 单对象或 Markdown 单行摘要。
- 参数错误：argparse exit 2；领域错误：exit 1；存储损坏/锁超时：exit 3；审批拒绝/不可用：exit 2。
- 所有命令错误输出一行 `ERROR: ...`，不输出 traceback。

### 3.4 Exposure 过滤

- `--min-exposure FLOAT` 为规范参数，范围 `[0.0, 1.0]`，拒绝 NaN/Inf。
- `--severity FLOAT` 接受数值并等价于 `--min-exposure`。
- `--severity P0/P1/P2/P3` 保留旧 category 行为并输出 deprecation warning。
- `--category STRING` 是新的明确类别过滤参数。
- 数值过滤为包含边界：`risk.exposure >= threshold`。
- 默认阈值引用 `risk_register.EXPOSURE_THRESHOLD`，但 list 默认不隐式过滤，只有传参时过滤。

## 4. ApprovalGate 设计

V4.5.5 `ApprovalGate(approval_callback=None)` 默认 auto-approve 是历史兼容语义；本版仅在用户显式要求 `--require-approval` 的 destructive CLI 路径上采用 fail-closed：

```text
callback 可用且批准       → 执行
callback 可用但拒绝       → exit 2，不写状态
callback 不可用           → exit 2，不写状态
未要求审批               → 保留既有默认行为
```

不改变其他 dispatch 调用方的默认 ApprovalGate 语义。

## 7. 回滚策略

- FileRiskStore 通过单独模块实现；如 Wave 1 失败，恢复 cli_risks 的 `_RISK_STORE` 适配层，不改 RiskRegister 核心领域 API。
- JSON schema v1 保留版本字段，未来可迁移，不直接覆盖未知版本。
- `--min-exposure` 为新增参数；旧 `--severity` 保留，降低脚本回滚风险。
- P0 async Coordinator 不在本版改动，sync 主链路无行为变化。
