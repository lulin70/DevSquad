## 1. 设计目标

1. **声明 ≠ 覆盖**：finalize 从 gate 自身的真实执行结果现算「验收清单 × PASS」矩阵，不信任任何 worker/LLM 输出中的覆盖声明（anti-ghost 同源）。
2. **防移动球门**：清单哈希在加载时刻锚定，评估时刻重算比对；执行期篡改清单 → FAIL。
3. **豁免必须留痕**：未覆盖项整体 FAIL，除非清单内书面 `waive_reason`；waived 溯源与缺口清单渲染进 summary 与 audit。
4. **默认关闭**：未启用时 dispatch 全链路行为与 4.8.x 逐 key 一致（负向测试保证）；启用后 fail-closed。
5. 纯标准库、零新依赖、零 LLM（确定性侧资产）。

## 3. 清单契约（schema v1）

```json
{
  "schema_version": 1,
  "items": [
    {
      "id": "AC-001",
      "description": "login endpoint returns 200 for valid credentials",
      "verify": { "kind": "command", "command": "python -m pytest tests/test_login.py -q" },
      "waive_reason": null
    },
    {
      "id": "AC-002",
      "description": "manual UI walkthrough documented",
      "verify": { "kind": "command", "command": "python -c \"exit 1\"" },
      "waive_reason": "UI not yet automated; manual sign-off attached in PR #TBD"
    }
  ]
}
```

- 落点：`.devsquad/acceptance_checklist.json`（与 `defects.json` 同目录惯例，W1 §2）。
- `id`：清单内唯一（重复 → FAIL，D10）；`AC-` 前缀非强制（v1 校验唯一性，不锁前缀）。
- `verify.kind`：v1 仅 `"command"`（D3）；其他值 → FAIL（fail-closed，不静默跳过该条目）。
- `waive_reason`：非空字符串 = 该条目豁免（不执行命令，矩阵记 `waived`）；空/缺省 = 强制执行。
- 加载校验 fail-closed：不识别的 `schema_version` → 拒绝（提示升级，模式同 W1 §2 台账版本协商）。
- 工具不强制清单入库；本仓 dogfood 启用时提交入库（证据链），外部项目自便（口径同 W1 §2）。

## 4. gate 执行设计（Step 23.5）

### 4.1 评估流程（FeatureGate.evaluate）

1. **重读清单文件**，重算 SHA256（`computed_sha256`）；文件缺失/不可解析 → FAIL（checklist_missing / checklist_invalid）。
2. **比对锚定**：`computed_sha256 != anchored_sha256` → FAIL（checklist_tampered）——清单在锚定后被改写，移动球门。
3. **逐条执行**：无 `waive_reason` 的条目 → `subprocess.run`（D11 纪律）：
   - exit 0 → `pass`；exit 非 0 → `fail`（附 exit_code + 输出截尾）；
   - 超时 → `fail`（附 `timed_out: true`）；命令无法启动（OSError）→ `fail`（附错误串）。
   - 有 `waive_reason` → `waived`（不执行，留痕）。
4. **矩阵聚合**：verdict = `pass` 当且仅当全部条目 ∈ {pass, waived}；任一 fail/missing/invalid/tamper → `FAIL`。
5. **结果落盘**（见 4.3）。

### 4.2 挂点接线（dispatch_steps.py）

- **pre-steps**（enabled 才走）：读清单文件 → `anchored_sha256`（文件字节）→ 存入 `pre_result`（新字段 `feature_gate_anchor: dict | None`，含 sha256 + path + 加载错误标记）。文件缺失也锚定（记录 missing），Step 23.5 出 FAIL——锚定失败不短路 dispatch（错误在 gate 处统一终态化，避免"加载失败=静默全过"）。
- **Step 23.5**（enabled 才走）：`self._run_feature_gate(pre_result, result)` → 矩阵 + verdict 写 `result.details["feature_gate"]`；FAIL → errors 追加 + `result.success = False`（Step 21 模式）。
- **Step 24 不动**：C19 终态重算在 Step 23.5 之后自然吃到 feature gate errors → `product_failed`（D5/D6）。
- mixin 吞异常降级语义与 Step 21 对齐（评估器内部错误 → warning + 该次 FAIL 记 errors，**不静默放行**——fail-closed：gate 自身崩 = 无法证明 = FAIL，区别于 review gate 的 graceful None）。

### 4.3 run 元数据写入（W2 同位扩展）

- `DispatchResult.details["feature_gate"] = result.to_dict()`（矩阵、双哈希、verdict、缺口/豁免清单）。
- `to_markdown` 渲染新增 feature-gate 段（仅 enabled 且有结果时出现；waived 逐条溯源 + 缺口清单——PRD §4.4 豁免留痕渲染要求）。
- audit 链：`log_dispatch_end` 增 keyword-only 参数 `feature_gate: dict | None = None`（省略时事件 details 与 W2 形态逐 key 一致——W2 §3.2 先例）；`dispatcher.py:581` 调用处传 `feature_gate=result.details.get("feature_gate")`。dispatch_end 事件持久化双哈希 + verdict，审计链哈希链提供跨 run 防改证据。

## 5. 配置与默认关闭

```yaml
# .devsquad.yaml
feature_gate:
  enabled: false            # default off — 4.8.x behavior when off
  checklist: .devsquad/acceptance_checklist.json
  command_timeout_seconds: 120
```

- `FeatureGateConfig`（pydantic 子模型）：`enabled: bool = False`、`checklist: str = ".devsquad/acceptance_checklist.json"`、`command_timeout_seconds: int = 120 (ge=1)`；挂 `DevSquadConfig.feature_gate`（默认工厂 False——旧配置文件无此 key → 关闭，`extra="ignore"` 向后兼容）。
- 启用路径：CLI `dispatch` 读 `ConfigManager().config.feature_gate` → `MultiAgentDispatcher(enable_feature_gate=True, ...)`；Python API 直接传构造参数。构造参数 > 配置文件（调用方显式意图优先）。
- **默认关闭负向保证**：关闭时 pre-steps 不加载、Step 23.5 不执行、`details` 无 `feature_gate` key、audit 事件无该 key、`to_markdown` 无该段——五面零痕迹，行为与 4.8.x 一致（负向测试①断言，§7）。
- 本仓 dogfood：v4.9.0 发布前不启用本仓清单（默认关闭原则）；发布后验证阶段启用（PRD §8 发布后 dogfood 口径，与台账同批）。

## 6. 与 review 自报侧的交叉（D8）

启用时 `_run_two_stage_review`（dispatch_steps_mixins.py:509）组装 `spec_requirements` 处：若 `pre_result.feature_gate_anchor` 存在且清单可用，把条目 `description` 列表注入 `spec_requirements["acceptance_criteria"]`——review gate Stage 1 的 `_check_acceptance_criteria`（review_checkers.py:260，启发式文本证据检查）与 feature gate 执行矩阵核对**同一份清单**。关闭时该注入不发生（现状 `getattr` 恒 None 的行为保持，零扰动）。

## 9. 跨角色评审记录（阶段出口门）

- **Architect**：D1/D2/D5 成立——D1 补齐了 PRD 建议载体在现状下的不可达缺口（实测恒 None）；D5 时序先于 C19 是 W2 勘误教训的直接应用。风险：pre_result 增字段属管线接口面变更，实现须全量回归 pre-steps 消费方。
- **Security**：D11 命令面信任级裁定为"人写清单文件 = CI 配置同级"；三条硬边界——gate 永不执行 worker/LLM 产出文本；超时必设；输出截尾防 details 膨胀。shell=True 在该信任级下可接受（等同 CI shell 步骤）；审计链持久化双哈希提供事后证据。**通过，附实现期核查项：subprocess 调用处不得引入 env 注入面。**
- **Tester**：负向清单①-⑩覆盖 PRD §6.2 对应项；⑦ C19 时序测试直接针对 W2 勘误教训①（时序断链无红）；命令确定性纪律（python -c）规避 flaky。**通过。**
- 结论：设计冻结，进入实现。
