## 2. 教训（Lessons Learned）

- **L-V4511-001（契约先行侦察）**: 合并 `Worker.execute`/`aexecute` 前必须先读 `test_v459_worker_async.py` 与其消费方（`AsyncWorkerWrapper`/`EnhancedWorker`/测试子类桩）。第一版把 sync 后端桥接目标从 `self.execute` 改成 `_do_work`，绕过了"子类覆写 execute 必须在异步路径可见"（V4.5.9 AC-W3），全量回归 3 处失败。最终回退为：aexecute 对 sync 后端保留 `self.execute` 桥接（子类覆写可观察），async 后端走统一 `_do_work_async`——"统一内部实现"限定了正确的边界。
- **L-V4511-002（asyncio.run 递归不是异常分支能救的）**: 同步入口在活动 loop 内无论 fail-closed 还是 run_coroutine_threadsafe 都引入新语义；最终采用 `_run_coro_on_thread`（守护线程新 loop + join）保证"行为字节级等价 no-loop 路径"，代价是每次多一个线程创建——对单次任务可接受。
- **L-V4511-003（全局 LLM cache 跨测试污染再现）**: V4.5.9 L-V459-002 教训重现——v4511 worker 测试的 task description 必须唯一，否则第二次调用命中缓存导致"backend.calls == 0"的假通过/假失败。
- **L-V4511-004（删除兼容层的正确姿势）**: 删除 `_LegacyRiskStoreProxy` 前先 grep 全仓库引用（含 docs），把 4 份测试的 fixture 从 `_RISK_STORE.clear()` 改成 `FileRiskStore.transaction("default")["items"] = []`，再删类——顺序反了会出现半小时的 ImportError 雪崩。
- **L-V4511-005（PATCH 迭代的文档纪律）**: 即使是无新功能的清理迭代，CHANGELOG Breaking 段、VERSION_HISTORY 条目、RELEASE_NOTES 三件套仍需完整——Breaking 变更（`_RISK_STORE` 删除）没有发布说明会直接砸到下游。
- **L-V4511-006（输出格式是契约）**: `risks add` 从单行 JSON 改为 indent=2 多行后，v458 契约测试 `out.splitlines()[-1]` 解析立即炸——CLI 输出的"行结构"与"字段结构"都是契约；统一输出时只动字段序，不动行格式。
- **L-V4511-007（全量回归必须重跑到绿）**: 首轮全量回归 9491 passed / 3 failed，3 处失败全部定位为本迭代真实回归（非时序错位）——修复后须重跑受影响文件与相关套件确认，不得带着已知 failed 发布。
