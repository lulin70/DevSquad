### 4.2 `test_contains_all_7_rungs` 修改示例（参数化）

**修改前** (硬编码):
```python
def test_contains_all_7_rungs(self):
    rungs = ["YAGNI", "standard library", "native platform",
             "already-installed dependency", "one line",
             "minimum code"]
    for rung in rungs:
        self.assertIn(rung, PONYTAIL_RULES, f"Missing rung: {rung}")
```

**修改后** (参数化 lite/full):
```python
@pytest.mark.parametrize("mode, expected_rungs", [
    ("full", ["YAGNI", "standard library", "native platform",
              "already-installed dependency", "one line", "minimum code"]),
    ("lite", ["YAGNI", "standard library", "one line"]),
])
def test_contains_all_rungs(mode, expected_rungs):
    rules = PonytailRuleInjector({"quality_control": {
        "minimal_implementation": True, "ponytail_mode": mode
    }}).build_injection()
    for rung in expected_rungs:
        assert rung in rules, f"Missing rung in {mode} mode: {rung}"
```

**文件**: `tests/e2e/test_v43_user_journey.py::test_cache_pickle_migration_journey`

**用户故事**: 作为运维工程师，我希望遗留 pickle 缓存能被安全迁移到 JSON，不丢失数据也不引入 RCE 风险。

**步骤序列**:
1. **准备**: 在临时目录创建遗留 pickle 缓存文件（含合法 dict 数据）
2. **写入**: 调用 `CacheInterface.set(key, value, format="json")` 写入新数据

5. **验证**: 
   - 迁移后 pickle 文件已重命名为 `.json`
   - 数据内容一致（dict/list/str/int/float/bool/None）
   - pickle 文件已被删除（非保留）
6. **拒绝**: 构造恶意 pickle payload（`__reduce__` RCE），验证 `migrate_legacy_pickle()` 拒绝并抛出 `ValueError`
7. **断言**: 
   - `test_no_pickle_files_remaining_in_cache_dir()`
   - `test_migrated_data_intact()`
   - `test_malicious_pickle_rejected()`

### 5.3 场景 3: LoopKernel 回退全旅程

**文件**: `tests/e2e/test_v43_user_journey.py::test_loop_kernel_rollback_journey`

**用户故事**: 作为架构师，我希望 LoopKernel 在 D3 (Test Verification) 失败时能回退到 D2 (Test Verification) 重试，而非直接 STOP_FAILURE；累计上下文跨迭代传递。

**步骤序列**:
1. **执行**: 启动 `LoopKernel.run("build feature X")`，配置 `max_iterations=10, rollback_max_iterations=3`
2. **失败**: 注入 mock evaluator 使 D3 验证失败（`verification_passed=False`）
3. **回退**: `RollbackStrategy.determine_rollback_stage(D3)` 返回 `TEST_VERIFICATION`
4. **重试**: LoopKernel 进入第 2 次迭代，携带 `_accumulated_artifacts`（含 iter 0 的 discovery + handoff）
5. **再次失败**: D3 仍失败，回退再次触发（rollback_count=2）
6. **第三次失败**: D3 失败，rollback_count=3 达到 `rollback_max_iterations` 硬上限
7. **终止**: LoopKernel 返回 `STOP_FAILURE`，不再回退
8. **断言**:
   - `test_rollback_target_is_test_verification_for_d3()`
   - `test_accumulated_artifacts_passed_across_iterations()`
   - `test_rollback_max_iterations_hard_limit_3()`
   - `test_stop_failure_after_rollback_exhausted()`
   - `test_rollback_decision_latency_under_5ms()` (性能断言)

## 7. 安全测试

### 7.1 pickle payload 注入测试

**测试**: `tests/test_cache_interface.py::test_malicious_pickle_payload_rejected`

**目标**: 验证 `pickle.loads` 移除后，恶意 pickle 数据被拒绝（抛 `ValueError`，不执行 `__reduce__`）。

**核心断言**: 构造 RCE payload（`__reduce__` 调用 `os.system`），`with pytest.raises(ValueError, match="pickle format rejected"): cache.deserialize(malicious, format="json")`；并验证 `os.system` 未执行（无 RCE 输出）。

**维度**:
- Happy: 合法 JSON 数据反序列化成功
- Error: 恶意 pickle 数据抛 `ValueError`
- Boundary: 空数据 / 超大数据 / 损坏 JSON
- Security: RCE payload / `__reduce__` / `__import__` / 反序列化链

### 7.2 Redis 未授权访问测试

**测试**: `tests/test_cache_interface.py::test_redis_unauthorized_access_fallback_secure`

**目标**: 验证 P0-1 安全收紧 — Redis URL 无密码时，fallback 默认关闭（opt-in），不调用 pickle。

**核心断言**: `assert cache.fallback_enabled is False`；调用 `cache.get("key")` 返回 `None`（cache miss，不调用 pickle 反序列化）

### 7.3 todo_drift_monitor regex 绕过测试

**测试**: `tests/test_todo_drift_monitor.py::test_regex_bypass_variants`

**目标**: 验证 regex 大小写不敏感 + 扩展标记集，覆盖常见绕过变体。

### 11.1 测试骨架设计原则

4. **TDD 模式**: 模块实现前先写骨架，模块实现后让骨架 pass
