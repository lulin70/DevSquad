## 1. Test Pyramid Target (V4.5.2)

> **原则 (P7 测试计划阶段核心)**: 按 **测试金字塔** 严格配比 — 大量单元 → 中量集成 → 少量 E2E。任何绕过金字塔的"大而全 E2E"是反模式。

| 层 | 比例目标 | 当前 (V4.5.2 已交付) | 主要内容 | 失败影响 |
|----|---------|---------------------|---------|---------|
| **Unit (单元)** | 70% | **81 个** | 模块逻辑、数据结构、契约 | 单点回归 |
| **Integration (集成)** | 20% | **16 个** | PreDispatchPipeline 链路、模块协同 | 链式回归 |
| **E2E (端到端)** | 8% | **21 个** (含 FakeHostRunner 子进程) | 真实文件协议 + 真实用户旅程 | 发布阻断 |
| **Contract (契约)** | 2% | **5 个** | `backend.path` / `RoleDefinition.sequential_only` / PerfSnapshot 字段 | 跨模块契约 |
| **合计** | 100% | **123 个** | | |

> **一致性门**: 这些数字 MUST 与 `docs/reference/MODULE_REFERENCE.md` 一致，由 `scripts/check_doc_consistency.py` 在 CI 校验。

### 2.3 Testing Philosophy (User)

- 测试是质量闸门，**绝不修改测试迁就源码 bug**——修复源代码（Iron Rule 1）
- 使用真实组件而非 Mock（`httpx.MockTransport` 注入内部，不替换底层对象）
- **禁止 skip**；若需跳过说明设计有误，改为可执行的模拟宿主（Iron Rule 6）
- 按 URL 区分的 mock（token vs ASR/OCR 格式）才能覆盖真实 provider 路径
- 测试金字塔是质量门控的结构性纪律，不是"凑数"——每层职责清晰、互不替代
- **Iron Rule 6** (E2E 必须真实可执行)：所有 E2E 测试必须有真实可运行的宿主模拟（FakeHostRunner 子进程），不允许 `@pytest.mark.skip` 蒙混

### 2.4 6 Iron Rules (强制遵守)

| # | Rule | V4.5.2 应用 |
|---|------|-------------|
| 1 | **不修改测试迁就 bug** — 修复源代码 | FallbackBackend 错误信息从原始 exception 改为标准 RuntimeError，修复真实 bug 而非调整断言 |
| 2 | **薄切片探针** — 每模块先 5 行 mini probe 验证激活 | `test_anti_ghost_*` 每个新模块都有 5 行快速探针 |
| 3 | **Mock 质量门** — Mock P95 变化 <10% | PerfBaseline §6.5 CI 阈值 |
| 4 | **覆盖度渐进** — 不强求 100% | 目标 ≥ 80%，优先关键路径 |
| 5 | **真实优先** — 用真组件而非 mock | OpenAI/Anthropic/MOKA 用真实 SDK |
| 6 | **真实 E2E 可执行** — 禁止 skip | FakeHostRunner 子进程真实复现协议 |
