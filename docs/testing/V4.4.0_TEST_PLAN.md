## 1. 测试策略

### 1.1 测试金字塔

| 层级 | 数量 | 覆盖 |
|------|------|------|
| 单元测试 | ~20 | CalibrationGateResult / ProbeSliceReport / RoleSpecificMockBackend / 信号强度判定 |
| 集成测试 | ~5 | Gate 0 → Slice 1 链路 / 无 API key 降级 / 报告生成 |
| E2E | 3 | US-1 仪器校准门 / US-2 决策报告 / US-3 零回归 |
| **总新增** | **~28** | |

### 1.2 Iron Rules 遵循

- **Iron Rule 1**: 文档先行，不猜 API（先 Read 源码确认签名再写测试）
- **Iron Rule 2**: 失败报告，不改断言（失败时分析根因，不放宽阈值）
- **Iron Rule 3**: 维度完整（Happy ≥50% / Error ≥15% / Boundary ≥10% / Performance ≥5% / Config ≥5% / Integration ≥10%）

### 5.2 测试 Mock 策略

- **Gate 0 测试**: 不 Mock ConfidenceScorer/FiveAxisConsensusEngine（使用真实评分器验证排序）
- **Slice 1 测试**: 使用 MockBackend 作为 LLM 臂（避免真实 API 调用）
- **E2E 测试**: E1/E3 不需 API key；E2 可选 --no-llm 模式
