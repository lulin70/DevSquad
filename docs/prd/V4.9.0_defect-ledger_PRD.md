### 4.1 P2-W1 defects.json 全局台账 + 状态机 + `defect` 命令面（核心）

- **台账落点**：项目级单文件，建议 `.devsquad/defects.json`（`.devsquad/` 项目状态目录惯例已存在，锚点 [cli.py:674](../../scripts/cli.py#L674)）；最终落点与 schema 于设计文档锁定。
- **命令面**：`devsquad defect add / update / close / reopen / audit / list`（扩 [cli.py:423-680](../../scripts/cli.py#L423-L680) 子命令面；挂载形态——顶层子命令 vs lifecycle 子命令——设计文档裁定）。**不设 delete 命令**（封闭生命周期，closed 为终态，regressed 回炉；v1 无删除面）。
- **DEF-NNN 分配**：单调递增；以"历史全量已分配 ID"为分配基准（含已不在现存条目中的），已分配 ID 永不回收（§5 坑 2）。实现载体（全局分配记录 / 全局 history）设计文档锁定。
- **封闭状态机**（每转移强制字段，防口头关闭）：

  ```
  open  --(update --commit <sha> + fix_summary)-->  fixed
  fixed --(回归 run 关联用例全 PASS 核对)-->        closed
  closed --(reopen + 强制 reason，清空 fix/regression 字段)--> open   [regressed 路径]
  ```

  非法转移（跳态 / 逆序 / 缺强制字段）一律拒绝。
- **原子持久化 + history 唯一事实源**：见 §5 坑 1（PRD 阶段直写为实现要求）。
- **`defect audit` 自检**：状态-history 一致性、ID 唯一性（含 history 扫描）、孤儿引用（signal_ref 解析失败）、必填字段完整性；任何不一致 → 非零退出 + 明细输出（fail-closed，绝不静默修复）。
- **代码结构参照**：[tech_debt_manager.py](../../scripts/collaboration/tech_debt_manager.py)（TD-NNN + DebtStatus 枚举 + to_dict/from_dict JSON 模式，1067 LOC 先例）；新增模块走 size gate 意识性提交（P1 教训：scripts/*.py 增长前先过 `check_dispatcher_size.py --max-lines 800 --baseline`）。
- **主责**：Architect（设计）+ Coder（实现）。

### 4.2 P2-W2 信号类型映射与立案真实性

- **映射表（FailureClass / BV / ReviewFinding → 台账 signal_type）**：

  | 信号源 | 锚点 | 台账信号类型 | 登记闸强制（默认） |
  |---|---|---|---|
  | FailureClass.product_failed | [failure_taxonomy.py:47](../../scripts/collaboration/failure_taxonomy.py#L47) | `failure:product_failed` | 强制 |
  | FailureClass.environment_blocked | 同上 | **不立案**（环境阻断非缺陷，映射表显式排除） | — |
  | BV critical（BREAK-1/BREAK-5/VULN-1/VULN-4） | [review_taxonomy.py:24-42](../../scripts/collaboration/review_taxonomy.py#L24-L42)，BV_CRITICAL 四项 | `review:break-vuln:<ID>` | 强制 |
  | BV warning（其余五类） | 同上 | `review:break-vuln:<ID>` | 不强制（audit 输出未立案提示；config 可收紧，开放点①） |
  | Stage 1 规格发现（ReviewFinding） | [review_checkers.py:113-122](../../scripts/collaboration/review_checkers.py#L113-L122) | `review:spec:<类别>` | 同 BV warning |

- **立案真实性（禁凭空立案）**：`defect add --signal-ref <引用>` 强制；引用必须可解析到既有 run 产物（dispatch report / review findings / test 记录中的 run ID + finding 序号），解析失败 → 拒绝立案。可解析产物清单于设计文档锁定。
- **主责**：Coder。

### 4.3 P2-W3 登记闸（fail-closed 接线）

- **启用条件**：项目 config 显式开启台账（默认关闭 = 向后兼容，未启用时 dispatch/review 行为与 4.8.x 完全一致——负向测试保证）。
- **行为（启用后）**：dispatch/review finalize 时，凡属强制范围（§4.2 映射表"强制"行）的信号无对应 open 状态 DEF 工单 → **gate FAIL**。信号不许蒸发。
- **接线点**：两阶段 review gate（调用处 [dispatch_steps.py:636-638](../../scripts/collaboration/dispatch_steps.py#L636-L638)，实现 [two_stage_review_gate.py](../../scripts/collaboration/two_stage_review_gate.py)）+ review diff 通道（V4.8.0 R1 接线面）；fail-closed 语义经 Security 评审。
- **主责**：Coder + Security。

### 4.4 P2-W4 feature_gate：现算覆盖矩阵 + 清单 SHA256 锚定

- **现算而非自报**：finalize 从执行记录**现算**"验收清单 × PASS"关联矩阵，不信任执行侧自报覆盖（与 anti-ghost 同源：声明 ≠ 覆盖）。
- **清单载体（建议，设计文档锁定）**：spec 验收标准（acceptance criteria）——现有检查点 [review_checkers.py](../../scripts/collaboration/review_checkers.py) `_check_acceptance_criteria` 是 review 自报侧；feature_gate 从测试执行记录侧现算，双侧交叉。
- **豁免留痕**：未覆盖项 → 整体 FAIL，除非书面 `waive_reason`；summary 渲染 waived 溯源与缺口清单。
- **SHA256 锚定**：清单哈希写入 run 元数据；执行期篡改清单（移动球门）→ FAIL。
- **默认关闭**（同 W3 策略），启用后 fail-closed。
- **主责**：Architect + Coder。

## 5. 上游两坑 → 实现要求（执行计划 §6.1 指令：PRD 阶段直写）

### 坑 1：转移丢失（上游 v2.14 实际缺陷）

状态转移写入过程中断/半写导致状态与历史脱节。实现要求：

1. **写入原子性**：tempfile 写入 + `os.replace` 原子替换，杜绝半写文件。
2. **history 唯一事实源**：每次转移追加 history 记录（前/后状态、时间戳、强制字段值）；条目当前状态是 history 的派生视图。
3. **加载校验 fail-closed**：加载台账时校验每条目当前状态 = 其 history 最后一条转移的目标状态；不一致 → 命令拒绝执行 + 明细报错，**绝不静默修复**。
4. **reopen 信息不丢**：reopen 清空 fix/regression 字段前，旧值记入 history。

### 坑 2：ID 复用（上游 v2.14 实际缺陷）

ID 分配只扫现存条目，已删工单 ID 被回收复用，引用错乱。实现要求：

1. **两面扫描**：分配基准 = 现存条目 ∪ history 全量 add 记录。
2. **永不回收**：next_id = max(历史所有出现过的 ID) + 1。
3. **冲突拒绝**：手动指定 ID 撞历史已分配值 → 拒绝并报错（`defect audit` 同样检查此项）。

## 7. 测试要求（铁律，执行计划 §6.2 全量落实）

- **状态机全转移覆盖**：每条合法转移 + 每类非法转移（跳态/逆序/缺强制字段）被拒，逐一断言。
- **负向测试先行**：
  1. 无信号立案被拒（`--signal-ref` 指向不存在的产物 → add 失败）；
  2. 未立案发现打红 gate（启用台账 + 强制范围信号无 open 工单 → finalize FAIL）；
  3. 清单篡改打红 gate（SHA256 锚定后修改验收清单 → FAIL）；
  4. ID 复用被拒（撞历史已分配 ID → 拒绝）；
  5. 状态-history 不一致 fail-closed（人为构造脱节 → 命令拒绝 + 明细报错，无静默修复）；
  6. 向后兼容：未启用台账时全链路行为与 4.8.x 完全一致（dispatch/review 退出码与产物不变）。
- **全生命周期 e2e**：发现（run 产出 finding）→ 立案（挂信号）→ 修复（update --commit）→ 回归（全 PASS）→ 关闭 → regressed reopen（强制 reason），全链路在测试夹具项目真实执行，证据入 docs/e2e_evidence/。
- **FailureClass 映射测试**：product_failed → `failure:product_failed` 立案；environment_blocked 不立案。
- **无跳过项**：skip 仅限环境条件性并逐个留痕（既有纪律）。
- **发布前**：全量回归（keyless 等价）+ 干净 venv 模拟真实用户（`pip install devsquad` → `devsquad defect --help` → 夹具项目全生命周期演练）。
