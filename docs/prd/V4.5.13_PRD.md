# DevSquad V4.5.13 PRD — TRAE 联调采集工具 + 跨主机信号自动埋点 + /metrics 暴露

> 状态：P1 定稿（用户 2026-08-31 决策：技能缓存方案 A 单一来源收敛 / trace 一键采集脚本 / Prometheus 轻量验证）  
> 基线版本：V4.5.12（commit `9940ac6` / tag `v4.5.12`）

## 0. 不可变决策

1. **技能缓存单一来源收敛（环境治理，不入 repo）**：devsquad 技能唯一注册副本保留在 `~/trae_projects/.trae/skills/devsquad`；删除 `~/.trae-cn/skills/devsquad`、`~/.trae/skills/devsquad`、`DevSquad/.trae/skills/devsquad` 三处重复及全部 `.bak`。`~/.trae-cn/skills` 的第三方 pack 平铺污染问题登记 backlog 不动文件。版本一致性脚本改为校验单一缓存层。
2. **TRAE IDE 5 trace 一键采集脚本**：`scripts/collect_trae_traces.py` 按 trace_1~5 场景生成 v2 request/marker 到 `logs/host_llm_bridge/v2/`，等待 response（超时即记录 timeout，正是 trace_3 的 fuse 输入），将文件快照 + 时间戳写入 `docs/e2e_evidence/V4.5.12_trae_ide_real/collected/`。支持 `--trace N|--all --wait-seconds N --dry-run`。真实 IDE 监听方在线时 round-trip 成功；不在线时采集到的是 timeout 证据（如实归档，不伪造 PASS）。
3. **跨主机信号自动埋点**：`FileRiskStore` 初始化与 `_open_lock` 路径自动检测远程文件系统（`os.statvfs().f_flag & ST_REMOTE`，平台不支持时安全跳过）并在检测到时自动 `record_cross_host_signal()`；flock 失败且 errno 属远程语义（`ESTALE/EREMOTE/EBADRPC`）时同样自动记录。手动 `record_cross_host_signal()` 保留。
4. **Prometheus 轻量验证**：`prometheus_metrics.py` 注册 `devsquad_v4512_risk_store_*` 4 指标 + `record_risk_store_stats()` helper，使 `/metrics` endpoint 真实暴露该序列；验证方式为 prometheus_client 本地 exposition 断言 + FastAPI TestClient `/metrics` 冒烟，不部署 Prometheus 服务器（promtool/docker 验证登记 backlog）。
