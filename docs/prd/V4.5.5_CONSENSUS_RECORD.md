## 角色详细意见

### 🏛️ Architect (9.5/10)

**亮点**:
- ✅ Marker 7 字段化让宿主 LLM 决策无需读完整 request — 是上游架构师审查的核心改进
- ✅ DispatchTransaction 5 状态 FSM 复用 V4.5.4 ModuleFiber 的 ALLOWED_TRANSITIONS 表驱动设计
- ✅ `request_file` commonpath 校验在 security 与 ease-of-use 之间取得平衡
- ✅ LIFO revert (V4.5.3 lesson #9) 应用到事务边界，无新概念

**担忧**:
- ⚠️ Transaction 状态机引入 5 个状态 + 4 个迁移，需要测试覆盖更密集
- ⚠️ IntentWorkflowMapper 的 6 × 3 = 18 个工作流 lazy 加载需要 SDK 文件存在 (`workflows/intent_*.yaml`)
- ⚠️ DispatchLoopController 与现有 HostBridgeBackend.FUSE 是两层熔断，需要文档明确分工

**建议**:
- 状态机表驱动 + ALLOWED_TRANSITIONS dict (复用 V4.5.4 模式)
- IntentWorkflowMapper lazy 加载使用 try/except 兜底到 default workflow
- Loop Controller 文档明示：backend fuse (1 个 backend) vs loop fuse (整个 loop)

### 📋 PM (9.0/10)

**亮点**:
- ✅ US-1~5 覆盖完整：协议完整度 / 事务边界 / 意图驱动 / 熔断 / 诚实标注
- ✅ Wave 推进时间表清晰（5 Wave × 11 验收点）
- ✅ 风险评估表完整（5 项风险 + 概率 + 影响 + 缓解）
- ✅ 验收标准量化（ruff 0 / mypy 0 / 9196+ passed / 16/16 anti-ghost / 45/45 version check）

**担忧**:
- ⚠️ 5 Wave 总测试数 38 实际可能偏低（建议 target 50+，留 buffer）
- ⚠️ 9.1 共识目标 vs V4.5.4 8.9 提升有限，缺少"突破性"卖点

**建议**:
- 测试预算 50+（buffer for edge cases）
- 卖点："**协议级与上游对齐 + 事务边界 + Backlog 闭环**，3 in 1 复合迭代"

### 🔒 Security (9.0/10)

**亮点**:
- ✅ `request_file` commonpath 校验防越界读取 (上游 G3 修复)
- ✅ request_id 正则 `[a-zA-Z0-9_]{1,128}` 防路径遍历 (沿用 V4.5.2)
- ✅ Transaction 隔离：失败模块不污染主流程
- ✅ LIFO revert 防止敏感数据残留 (V4.5.3 lesson #9)

**担忧**:
- ⚠️ IntentWorkflowMapper 加载 YAML 工作流需要路径白名单，防止加载恶意 YAML
- ⚠️ DispatchLoopController `last_retriable_reason` 字段可能泄露内部错误细节给外部 LLM
- ⚠️ 事务日志如果包含 prompt 内容，可能触发 PII 风险

**建议**:
- IntentWorkflowMapper 加载路径白名单：`workflows/intent_*.yaml` + `projects/*/workflows/intent_*.yaml`
- `last_retriable_reason` 在外发前 sanitize (去除 file path / 密钥模式)
- 事务日志默认 redact prompt，opt-in 完整日志

### 🧪 Tester (9.0/10)

**亮点**:
- ✅ Wave 1-4 共 38 测试（11+16+6+5），覆盖完整
- ✅ Test Pyramid 目标 ≥ 18% integration / ≥ 7% contract 健康度高于 V4.5.4
- ✅ 5 验收测试覆盖 Wave 4 backlog 闭环

**担忧**:
- ⚠️ Transaction 状态机的边界条件 (FAILED → ROLLED_BACK? FAILED → COMMITTED?) 测试矩阵爆炸
- ⚠️ Loop Controller 连续 retriable 的 "相同 reason" 语义需要明确字符串比较 vs 模式匹配

**建议**:
- 状态机边界测试用 parametrize + ALLOWED_TRANSITIONS 表驱动
- Loop Controller 测试 reason 比较用 `str(exc_type) + str(exc_msg[:50])` 标准化哈希
- 集成测试用 FakeDispatcher (in-memory state) + Mock Loop
