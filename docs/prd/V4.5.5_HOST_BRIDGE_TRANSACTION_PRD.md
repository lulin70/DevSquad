## 1. 背景与问题

### 1.1 V4.5.4 现状（HostLLMBridge B-path 实施情况）

V4.5.2 P12.1 引入了 HostLLMBridge（B-path）和 B→A→C 解析顺序。V4.5.4 P12.3 在此基础上又叠加了 ModuleFiber + CoeffectResolver。**目前 B-path 在外部 shell 调用下不可用**（这是 V4.5.4 P11 已记录的 SC-13 边缘情况）。真实症状：

- 当前 `logs/host_llm_bridge/` 有 **35 个遗留 request 文件 + 当前 marker 但无监听方**（实测 2026-08-25）
- TRAE IDE 集成终端外调用 dispatcher → 必然 timeout 600s → FUSE 跳 B → 强制降级 A → 无 API key → C mock
- 这是 TRAE IDE 设计本身决定的，**不是 V4.5.4 的 bug**，但 V4.5.4 协议完整度落后于上游

### 1.2 上游 weiransoft/TraeMultiAgentSkill v2.8.4 已做的设计

通过对比上游 `host_llm_bridge.py` (215 行) + `HOST_LLM_BRIDGE_DESIGN.md` (350+ 行)，V4.5.4 有 6 个设计缺口（详见 [V4.5.4 retrospective § G1-G6](file:///Users/lin/trae_projects/DevSquad/docs/planning/V4.5.4_P12.3_RETROSPECTIVE.md)）：

| # | 缺口 | 严重度 | 上游做法 |
|---|------|-------|---------|
| G1 | marker 仅 2 字段 | P0 | marker 7 字段（agent_type/task/request_file/prompt_file/timeout_seconds/timestamp） |
| G2 | 无独立 prompt 文件 | P0 | `request_{id}.prompt` 与 metadata 分离，避免大 prompt 写进 JSON 浪费 token |
| G3 | 无 `request_file` 路径越界校验 | P1 | `os.path.commonpath([req_file, bridge_dir]) == bridge_dir` 防越界读取 |
| G4 | 缺 loop 级别熔断 | P1 | `WorkflowLoopController._consecutive_retriable_count ≥ 2 → fatal` |
| G5 | 缺 Task subagent_type 映射 | P2 | `architect→search`, 其他 → `general_purpose_task` |
| G6 | SKILL.md 缺诚实标注 | P2 | SKILL.md 顶部声明："提示词层 AI 由宿主 LLM 完成；脚本层确定性工具；无网络时降级 TFIDF/Hashing" |

### 1.3 V4.5.4 backlog

V4.5.2 遗留 `check_test_quality` 报 66 MAJOR findings（git blame 已溯源，V4.5.4 不阻塞未修）。同时 V4.5.3 lesson #4 命名统一 `_call_counter → _call_counter_er` 仅完成 50%（module_fiber 已统一，其他模块仍有 `_call_counter`）。

### 1.4 业务需求

在 DevSquad IDE 内嵌 dispatch（即 LLM 通过 `run_mcp` 调用我时），应能真实触发 TRAE 宿主 LLM 调度 Task 工具，让 7-role 共识不再只是 mock 输出，而是真实多 LLM 对话。V4.5.6 是 **V4.5.4 协议完整度追赶** + **事务边界主线** + **backlog 闭环** 的复合迭代。

### 2.2 Wave 2 — Dispatch Atomic Transactions（事务主线）

**目标**: 在 V4.5.4 ModuleFiber FSM + V4.5.3 Effect Protocol 之上叠加 transaction boundary，让模块依赖图具备 BEGIN/COMMIT/ROLLBACK 三态语义

**新增模块**:
- `scripts/collaboration/dispatcher_transaction.py` (~250 行)
  - `TxState` enum: `PENDING / ACTIVE / COMMITTED / ROLLED_BACK / FAILED`
  - `DispatchTransaction` dataclass（`__slots__` + `__init__` 双管齐下，V4.5.3 lesson #1）
  - `TransactionBoundary` Protocol（runtime_checkable）
  - `TransactionContext` (with statement 上下文管理器)
  - `TransactionRegistry` (thread-safe lock)
  - `_inc_call_counter_er()` + `get_call_counter_er()` (V4.5.3 lesson #4 命名统一)
- `scripts/collaboration/dispatcher_intent_mapper.py` (~180 行)
  - `IntentWorkflowMapper` (6 intent × 3 language, 复用 V4.3 IntentWorkflowMapper)
  - `_resolve_intent_workflow(intent, lang)`
  - `load_workflow(intent, role)` lazy 加载

**Dispatcher 集成**:
- `dispatcher.py` 新增 4 kwargs: `enable_transactions`, `enable_intent_workflow`, `tx_timeout`, `tx_rollback_on_partial_failure`
- `_init_transaction_registry()` 注册 5 模块: dispatcher_transaction, dispatcher_intent_mapper, host_llm_bridge_v2, host_bridge_adapter, dispatcher_loop_controller
- `_activate_v455_modules()` 三路径 best-effort 调用（V4.5.3 lesson #7）

**Transaction 生命周期**:
```
BEGIN → register modules → execute → COMMIT (all success)
                                ↓
                              any failure → ROLLBACK (LIFO revert, V4.5.3 lesson #9)
                                ↓
                              unrecoverable → FAILED (telemetry + SC-14 alert)
```
