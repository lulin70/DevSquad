## 1. 背景与来源

### 1.1 价值断层（方案文档 §3，本批主攻）

- **F2 一次性 dispatch vs 工程工作流（严重度：高）**：真实工程师的价值时刻是 PR 打开、CI 红、发布前。DevSquad 的确定性门禁族已具备这些时刻需要的检查能力，但只存在于"主动调用"形态。零件已全齐：4 字段 PR 评论协议（V4.6.0 P2-b，本仓 test.yml 实证）、`review --changeset/--diff-file` 输入面、`--preview` 零 LLM 定价、exit 0/1/2 契约（C19）、judge 三态隔离。缺的是面向外部仓库的分发包装。
- **F5 dogfooding 有实绩、无证据链（严重度：中）**：本仓是最完整的 DevSquad 用户（PR 评论、债务批次、跟踪纪律），但证据散落，未形成对外可引用的自证报告。

### 1.2 P0 批移交项（P0 复盘 §5）

- **acceptance 面一致性缺口**：`acceptance_local.sh` 只镜像 release final-gate 的 pytest 面，不镜像 CI lint job 的 dispatcher-size gate 面。P0-W1 事件（`check_version_consistency.py` 735→872 LOC 超 800 上限）证明该缺口会让本地验收假绿、CI 拦截。→ 本批 P1-W0 修复。

### 1.3 治理约束（D4）

- **扩张冻结**：P1/P2 期间禁止新增借鉴型大模块，冻结至 E1 消费者审计裁定完成。E1 全程并行。

## 4. 工作项明细

### 4.0 P1-W0 acceptance 面一致性（先行，独立小 PR）

- **范围**：`acceptance_local.sh` 增补 dispatcher-size gate 调用，命令与 CI `test.yml::lint` 完全一致（`check_dispatcher_size.py --max-lines 800 --baseline`），置于 pytest 面之前。
- **验收**：①本地运行 `acceptance_local.sh` 可见 size gate 输出与 PASS；②负向演示：临时降低 `--max-lines` → 脚本非零退出（演示后还原，演示记录入 PR 描述）。
- **主责**：Coder。无设计文档需求（机械追加）。

### 4.1 P1-R1 devsquad-gate GitHub Action（核心，第一波）

- **分发形态**：本仓新增 `.github/workflows/devsquad-gate.yml`（`workflow_call` 可复用工作流）；外部仓 wrapper 一行接入 `uses: lulin70/DevSquad/.github/workflows/devsquad-gate.yml@<ref>`（ref 建议主版本号 tag）。
- **行为链**：`pull_request` 触发 → 安装 pinned `devsquad`（PyPI，版本 pin 防漂移）→ 认证取 PR diff（REST pulls 端点，私有消费仓可用——T-3 试装修正）→ `devsquad review --diff-file <diff> --task <gate task>`（确定性侧：review_checkers + review_taxonomy + 四层规则链 + TestQualityGuard，**默认零 LLM 零 key**）→ 结构化 PR 评论 → fail-closed 退出。
- **评论协议 v1**：沿用 4 字段结构化协议（R1 设计文档定义适配 review 场景的字段集），附 run URL 与协议版本号；`gh pr comment --edit-last --create-if-none` 幂等；无自由 LLM 文本，无 secrets 回显。
- **权限最小集**：`contents: read` + `pull-requests: write`（评论所需），不申请其他。
- **secrets 边界**：默认零 secrets 可运行（确定性侧）。可选 judge LLM 语义断言走 `DEVSQUAD_JUDGE_*` 独立命名空间（三态 pass/fail/blocked，结构层先行）；secrets 缺失 → judge blocked 三态披露，不谎报；产品层发现仍 fail-closed。
- **`--preview` 定价输出**：workflow 日志/输出含 `review --preview` 摘要（零 LLM 调用），消费者接入前可定价。
- **验收**（方案文档 §5.2 R1 全表）：①外部 1 个真实仓库试装并跑通 e2e（PR 开→评论出现→重跑幂等更新）；②失败注入→Action 非零退出；③secrets 缺失时行为按文档（blocked 披露，不谎报）；④发布前按铁律完成模拟真实用户测试。
- **主责**：Architect（设计）+ Coder（实现）+ Security（secrets 边界评审）+ DevOps（workflow 入仓）。外部试装仓待用户选定（§8 开放点）。

### 4.2 P1-R2 persona 五分钟通道（R1 设计冻结后）

- **范围**：QUICKSTART.md 重构为三条最短路径——①IDE 用户（TRAE/Cursor，host 委托，零 key）→ 技能/MCP 即用；②CLI 用户 → `devsquad init` 向导按后端分流（key 有无分流：真实后端 / 演示路径）；③仓库维护者 → R1 Action 一行接入。`init` 五步向导（[cli.py:47-287](../../scripts/cli.py#L47-L287)）step2 后端选择处按所选后端给差异化收尾指引；`check_config_consistency` 扩展覆盖新文档命令一致性。
- **验收**：三 persona 各一条模拟真实用户 e2e（安装→看到第一份产出）；每条路径起点命令唯一；文档与实现一致（config consistency 门禁化，不留人治）。
- **主责**：PM（文档）+ Coder（init 增强 + 门禁扩展）。

### 4.3 P1-R3 dogfooding 自证链（R1 设计冻结后）

- **范围**：新增 `scripts/generate_dogfooding_report.py`——数字全部采集自本仓门禁/审计链真实输出（版本一致性项数、config 一致性、测试金字塔比例、Bandit/pip-audit、PR 评论协议覆盖、TD 债务进出），每个数字附可复现采集命令；首期季度报告入库。
- **验收**：首期报告产出；任一数字可按文档命令复现；无不可复现断言（TD-074 教训）。
- **主责**：Coder + PM。注意：新增 scripts/*.py 后 push 前本地跑 size gate（P0 教训 1）。

### 4.4 P1-R4 MCP 通道文档（R1 设计冻结后）

- **范围**：外部 IDE（Cursor 等）经 MCP 接入的安装步骤与工具清单文档（`multiagent_dispatch`/`quick`/`analyze`/`codegraph` 工具面；RBAC 与 fail-closed 行为写明，锚点 [mcp_server.py:236-406](../../scripts/mcp_server.py#L236-L406)）；落点：QUICKSTART/README×3 同步引用。
- **验收**：按文档在外部 IDE 完成连接的 e2e 证据（连接记录/截图入库）。
- **主责**：PM + Coder。

### 4.5 P1-E1 消费者审计（全程并行，治理件）

- **对象**（六项）：teach / prototype / live-browser / meta-skill-layering / impeccable 词表 / taste-dials。
- **方法**：逐项回答"谁在什么场景用"——调用链证据（anti-ghost counter 只证明被调用，不证明被需要）+ 测试依赖面 + 文档引用面 + 真实用户可达性。
- **产出**：keep / freeze / remove 三态清单，每项附证据与建议理由。
- **验收**：清单 + 用户裁定记录 → 执行计划 §10 留痕；裁定完成后解除扩张冻结。remove 项的实施属后续批次，本批不改代码。
- **主责**：PM + Architect。

## 6. 测试要求（铁律）

- **负向测试先行**（R1）：secrets 缺失 → judge blocked 三态披露（不谎报绿/红）；评论协议失败 → 判定不受影响但失败可见；重跑幂等（更新而非新增）。
- **外部试装 e2e**（R1 验收①）：真实仓库、真实 PR、真实评论，证据入 docs/e2e_evidence/。
- **三 persona e2e**（R2）：安装→第一份产出，全链路模拟真实用户。
- **无跳过项**：skip 仅限环境条件性并逐个留痕（P0 先例：6 skipped 全部定位披露）。
- **发布前**：全量回归（keyless 等价，`acceptance_local.sh` 含 W0 后的 size gate 面）+ 干净 venv 模拟真实用户（--version/--help/demo）。
