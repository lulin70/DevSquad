## 2. 背景与目标

### 2.1 背景

DevSquad 默认使用 MockBackend（无 API key 依赖），也支持 LLM 后端（OpenAI/Anthropic/MOKA AI）。一个核心问题长期未得到量化回答：**DevSquad 是否需要 LLM？** LLM 模式相对 Mock 模式的输出质量差距到底有多大？

V4.3.1 已建立 LLM 连通性基础（`benchmark_real_llm.py` + `test_real_llm_smoke.py` + MOKA AI 后端验证通过）。V4.4.0 的任务是**量化这个差距**，为后续产品决策提供数据支撑。

### 2.2 7-Role LLM 评审结论（2026-07-28）

7 个角色（架构师/PM/安全/测试/独立开发者/DevOps/UI）通过 MOKA AI claude-opus-5 进行真实 LLM 评审，**7/7 有条件通过**，5 大核心共识：

| # | 共识 | 影响 |
|---|------|------|
| C1 | Layer 1 heuristic 评分存在循环论证风险（评分器为 LLM 输出设计） | 必须前置仪器校准门 |
| C2 | 先做薄切片/探针，不要直接投入 1500 行 | Gate 0 + Slice 1 先行 |
| C3 | 砍掉 dispatch 集成和 Dashboard | 仅 scripts/ + Markdown 报告 |
| C4 | 统计设计不足（10×1 采样无法区分模式差距和噪声） | n=3 重复采样 |
| C5 | 冻结现有 MockBackend，三臂对照 | 不修改现有代码 |

### 2.3 核心目标

1. **Gate 0 仪器校准门**: 验证 ConfidenceScorer + FiveAxisConsensusEngine 能否正确区分已知质量等级的输出。**门不过则全部作废**。
2. **Slice 1 薄切片探针**: 3 任务 × 3 臂（冻结 Mock / RoleSpecificMock / LLM）× n=3 采样，产出 mean ± stddev 信号强度报告。
3. **决策点**: 基于信号强度决定后续扩建路径（不盲目投入完整 1500 行方案）。
4. **诚实记录**: 无论结果如何（LLM 优势显著/不显著/评分器失效），均产出决策报告。

### 2.4 版本策略

- **V4.4.0** (MINOR): Gate 0 + Slice 1 + 决策报告。MINOR 递增因为新增 `quality_calibration_gate.py` + `quality_probe_slice.py` 模块（向后兼容）。
- **不纳入 V4.4.0**（评审共识）: dispatch 集成 / Dashboard / RoleSpecificMockBackend 默认开启 / 修改现有 MockBackend
- **延后 V4.5.0**（如信号强度支持）: 完整 OutputQualityComparator + 10 任务集 + LLM-as-judge + 人工盲评 + Dashboard

## 4. 功能需求

### 4.1 P0: Gate 0 — 仪器校准门（~50 行）

**模块**: `scripts/collaboration/quality_calibration_gate.py`

**功能**:
- 构造 4 个已知质量等级的固定输出：
  1. `gold`: 手写高质量参考答案（~500 字，结构完整，内容具体）
  2. `llm`: 真实 LLM 输出（~500 字，缓存一份避免每次调用）
  3. `filler`: 通用填充文（正确格式但内容空洞，~500 字）
  4. `empty`: 空字符串
- 用 ConfidenceScorer + FiveAxisConsensusEngine.evaluate() 对 4 个输出评分
- 验证排序: `gold > llm > filler > empty`
- 验证间距: `gold_score - filler_score >= 0.2`
- 产出 `CalibrationGateResult`（含通过/失败 + 诊断信息）

**API**:
```python
def run_calibration_gate() -> CalibrationGateResult:
    """Run instrument calibration gate. Returns result with pass/fail + diagnostics."""

@dataclass
class CalibrationGateResult:
    passed: bool
    scores: dict[str, dict[str, float]]  # {output_id: {factor/axis: score}}
    ordering_correct: bool
    gap_gold_filler: float
    diagnostics: list[str]  # 失败原因列表
```

**门禁语义**:
- `passed=True` → 允许执行 Slice 1
- `passed=False` → Slice 1 不执行，产出诊断报告，直接进入决策点（结论：评分器无法区分）

### 4.2 P1: Slice 1 — 薄切片探针（~200 行）

**模块**: `scripts/collaboration/quality_probe_slice.py`

**功能**:
- 3 个固定任务（不依赖外部数据集）：
  1. `simple`: "写一个 Python 函数计算斐波那契数列"
  2. `medium`: "设计一个支持 JWT + Refresh Token 的认证系统"
  3. `complex`: "重构一个 800 行 God Class 为 SRP 合规的 3 个类"
- 3 臂对照：
  1. `frozen_mock`: 现有 MockBackend（冻结基线，不修改）
  2. `role_specific_mock`: 新增 RoleSpecificMockBackend（`role_specific=True`，独立类，默认关闭）
  3. `llm`: MOKA AI 后端（`anthropic/claude-opus-5`）
- n=3 重复采样（LLM 是随机过程，需要多次采样）
- 用 ConfidenceScorer + FiveAxisConsensusEngine.evaluate() 评分（Layer 1 heuristic）
- 产出 `ProbeSliceReport`（含 mean ± stddev + 信号强度判定）

**API**:
```python
def run_probe_slice(
    llm_backend: LLMBackend | None = None,
    n_samples: int = 3,
) -> ProbeSliceReport:
    """Run thin-slice probe. Returns report with mean±stddev + signal strength."""

@dataclass
class ProbeSliceReport:
    task_results: dict[str, dict[str, list[float]]]  # {task_id: {arm_id: [scores]}}
    mean_stddev: dict[str, dict[str, tuple[float, float]]]  # {task_id: {arm_id: (mean, stddev)}}
    signal_strength: str  # "significant" / "marginal" / "noise" / "calibration_failed"
    conclusion: str  # 人类可读结论
    to_markdown(self) -> str: ...
```

**信号强度判定**:
- `significant`: LLM 均值 > Mock 均值 + 0.15（在 0-1 scale 上）
- `marginal`: 0.05 < LLM 均值 - Mock 均值 ≤ 0.15
- `noise`: |LLM 均值 - Mock 均值| ≤ 0.05
- `calibration_failed`: Gate 0 未通过

### 4.3 P2: RoleSpecificMockBackend（~80 行，独立类）

**模块**: `scripts/collaboration/role_specific_mock_backend.py`

**功能**:
- 继承 `LLMBackend` 抽象类
- 7 个角色各有独立模板（含角色特定的术语/关注点/输出结构）
- 默认 `role_specific=False`（保持与 MockBackend 完全兼容）
- `role_specific=True` 时使用角色特定模板
- **不修改现有 MockBackend**

### 4.4 P3: 决策报告生成（~30 行）

**模块**: `scripts/generate_quality_decision_report.py`

**功能**:
- 调用 `run_calibration_gate()` + `run_probe_slice()`
- 生成 Markdown 决策报告
- 报告含：Gate 0 结果 + Slice 1 结果 + 信号强度 + 后续建议
- 输出到 `docs/analysis/YYYY-MM-DD_LLM_vs_Mock_Quality_Report.md`
