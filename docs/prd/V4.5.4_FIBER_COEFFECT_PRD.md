## 1. 背景 (Background)

V4.5.3 解决了"产出物 + 副作用可回滚"问题 (ArtifactStore + EffectRegistry + AuditCLI 3 模块 Anti-Ghost 11/11 PASS)。但用户真实使用中发现 5 个新痛点:

1. **模块状态不可见**: dispatcher 启动后, 哪些模块"已激活 / 激活中 / 失败"完全黑盒 — 用户必须看 log 才能猜。
2. **模块依赖隐式**: ArtifactStore 隐式依赖 EffectRegistry, audit CLI 隐式依赖 DispatchAuditLogger, 这种**耦合是隐式**的, 一旦顺序错就 ImportError。
3. **激活失败 = 全盘崩溃**: dispatch 启动时任何模块 `__init__` 抛异常, dispatcher 直接 crash, 但有些模块 (audit CLI / metrics) 是 **best-effort**, 不应阻塞主流程。
4. **无法 dry-run 依赖**: 测试时无法 mock "如果 artifact_store 加载失败会怎样" — 缺乏模块级的故障注入能力。
5. **运维无可视化**: 17 个 Prometheus 指标 + 10 个模块激活状态, 但**没有人类可读的全局视图** (graphviz / ASCII tree)。

V4.5.4 = **Module Fiber + Coeffect** 解决上述 5 个痛点。

## 4. 详细规格 (Detailed Specs)

### P12.3.1 — ModuleFiber 状态机

**职责**: 把每个模块的生命周期建模为**显式状态机**, 取代隐式的"init 成功 = 已激活"假设。

**5 状态**:

```
Inactive → Activating → Active → Deactivating → Inactive
                ↓              ↓
              Failed        Degraded (自愈后)
```

| 状态 | 含义 | 允许转移 |
|------|------|----------|
| **Inactive** | 模块已注册但未 init | → Activating |
| **Activating** | 正在执行 init / 拓扑解析中 | → Active / Failed / Degraded |
| **Active** | 正常可用 | → Deactivating |
| **Deactivating** | 正在关闭 (shutdown) | → Inactive |
| **Failed** | init 抛异常, 重试耗尽 | → Activating (retry) / Inactive |
| **Degraded** | 关键依赖失败但模块本身可用 (best-effort 模式) | → Active (修复后) / Inactive |

**API** (Python dataclass):

```python
class FiberState(str, Enum):
    INACTIVE = "inactive"
    ACTIVATING = "activating"
    ACTIVE = "active"
    DEACTIVATING = "deactivating"
    FAILED = "failed"
    DEGRADED = "degraded"


@dataclass(slots=True)
class ModuleFiber:
    """Lifecycle state machine for a single module.

    V4.5.3 lesson #1: __slots__ classes MUST add new fields to BOTH
    __slots__ tuple and __init__ together.
    """
    __slots__ = (
        "module_id", "state", "depends_on", "last_error",
        "retry_count", "activated_at",
    )

    module_id: str
    state: FiberState = FiberState.INACTIVE
    depends_on: tuple[str, ...] = ()
    last_error: str | None = None
    retry_count: int = 0
    activated_at: float | None = None

    def transition(self, target: FiberState, *, reason: str = "") -> bool: ...
    def is_usable(self) -> bool:
        return self.state in (FiberState.ACTIVE, FiberState.DEGRADED)
```

**自愈 (Self-Healing) 策略**:

- `Activating → Failed` 时自动 retry 1 次 (间隔 100ms)
- 仍失败 → 进入 `Degraded` 状态, 写 telemetry `devsquad_v454_fiber_degraded_total{module=...}`
- 重试耗尽后用户可通过 `devsquad modules retry <module_id>` 手动 retry

**Anti-Ghost**: 模块级 `_call_counter` 暴露 `get_call_counter()` (与 V4.5.3 lesson #4 一致 — V4.5.4 命名统一为 `get_call_counter_er`, 以 `_er` 后缀单数形式)。

### P12.3.2 — Coeffect 协议 + Resolver

**职责**: 把模块间依赖从"隐式 import 顺序"变为"显式 `depends_on(...)` 声明 + 拓扑解析"。

**Coeffect 协议**:

```python
class CoeffectProvider(Protocol):
    """Mix-in protocol for modules that declare dependencies."""

    def depends_on(self) -> tuple[str, ...]:
        """Return module_ids this module needs to be Active before init."""

    def get_fiber(self) -> ModuleFiber:
        """Return this module's current lifecycle state."""


def with_coeffect(
    module_id: str,
    *,
    depends_on: tuple[str, ...] = (),
) -> Callable[[type], type]:
    """Decorator: attach module_id + depends_on to a class.

    V4.5.3 lesson #5: cross-module private state MUST use public method,
    not type: ignore. This decorator adds public API without modifying
    the original class __init__ (zero-intrusion).
    """
```

**CoeffectResolver** (新模块):

```python
class CoeffectResolver:
    """Topological sort + cycle detection for module activation order."""

    def __init__(self) -> None:
        self._modules: dict[str, CoeffectProvider] = {}
        self._graph: dict[str, set[str]] = {}

    def register(self, provider: CoeffectProvider) -> None: ...
    def resolve_activation_order(self) -> list[str]:
        """Kahn's algorithm topological sort. Raises CycleError.""" ...

    def detect_cycle(self) -> list[str] | None:
        """DFS-based cycle detection. Returns cycle path or None."""

    def validate_dependencies(self) -> list[CoeffectError]:
        """Find dangling depends_on (referring to non-registered modules)."""
```

**失败降级 (Failure Degradation)**:

- 拓扑解析成功 → 按拓扑序激活, 失败模块降级为 Degraded 而非中断整链
- 拓扑环 (cycle) → 抛 `CoeffectCycleError`, 但 dispatcher **捕获并降级** (主流程继续, 该模块标记 Failed)
- 悬空依赖 (dangling) → 类似, 降级 + 警告日志

### P12.3.3 — 状态观测 CLI + 拓扑可视化

**职责**: 暴露 Fiber 状态 + 依赖图为人类可读 CLI。

### P12.3.4 — 激活失败处理 + 状态自愈

**集成点**:

- Dispatcher `__init__` 末尾调用 `_activate_v454_modules()`
- `_activate_v454_modules()` 内部:
  1. 实例化 ModuleFiber / CoeffectResolver / ModulesCLI 三个新模块 (counter 触发)
  2. 注册 8 个现有模块 + 3 个新模块到 resolver
  3. 调用 `resolver.resolve_activation_order()`
  4. 按拓扑序逐个 `_activate_v454_module(provider)`
  5. 每个 provider 用 try/except 包裹, 失败降级而非崩溃 (V4.5.3 lesson #7 best-effort 模式)

**契约**:

- 任意模块 init 失败 → 标记 Degraded, 不影响 dispatcher 启动
- 失败原因写入 `last_error` + Prometheus 指标
- 重试由 Fiber 状态机内部管理 (P12.3.1 自愈)

## 7. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| Fiber 状态机引入性能开销 | 中 | 低 | 状态转移是 in-memory dict, 单次 < 1µs |

| 失败降级掩盖真问题 | 中 | 中 | 失败模块必须 Degraded + last_error + Prometheus 指标 + log.warning |
| 自愈 retry 风暴 | 低 | 中 | 仅 retry 1 次, 仍失败用户手动 retry (非无限循环) |
