## 0. 命名澄清与不可变决策

**命名澄清**：本文"上游 trae v2.8.4"指 [weiransoft/TraeMultiAgentSkill](https://github.com/weiransoft/TraeMultiAgentSkill) 项目 v2.8.4（DevSquad HostLLMBridge v2 的协议参考来源）；本机真实联调对象是 **TRAE IDE 3.3.95 集成终端**。两者版本号独立。

本轮采用以下不可变决策（用户确认）：

1. **TRAE IDE 真实联调覆盖全部 v2 特性**：marker 7 字段严格 schema、独立 `request_{id}.prompt` 文件读取、`prompt_file` 路径越界校验、`commonpath` 安全边界、`subagent_type` 映射（`architect→search`，其他→`general_purpose_task`）、`fuse_threshold=2` 连续 retriable 熔断、`MAX_PROMPT_BYTES/MAX_REQUEST_JSON_BYTES/MAX_RESPONSE_JSON_BYTES` 资源上限。V4.5.10 落地的 FakeHostRunnerV2 仅覆盖部分路径——本轮用真实 TRAE IDE 监听方把剩余 5 项特性全部验证。
2. **SQLite 重立项条件采用 `stats + Prometheus alert` 双轨**：(a) 在 `FileRiskStore` 关键路径埋点 4 个轻量计数器（容量、并发写、远程共享信号、复杂查询信号），通过 `risks stats --format text|json` 暴露；(b) 新增 `devsquad_v4512_risk_store_stats` Prometheus metrics；(c) ALERT_RULES 新增 4 条阈值规则（容量 >10k / 并发锁竞争 >N/分钟 / 跨主机锁文件被占用 / 复杂查询 >50ms）；(d) RUNBOOK 新增 `V4.5.12-A/B/C/D` 处置章节。**仍维持 SQLite 重立项条件裁决不变**——仅当告警真正触发时启动重立项评估。
3. **`--severity` 直接删除**（Breaking，CHANGELOG 显式标注）：(a) 移除 `cli_risks.py` `_filter_risks` 中字符串模式分支与 WARNING；(c) `list/show/export` 子命令 argparse 删除 `--severity` 参数；(b) CLI 帮助文档与 README×3 同步删除；(d) 4 份测试 `_args()` 默认值删除 `severity=None`，相关 `test_*_severity_filter` 测试改为 `test_*_category_filter`；(e) API 路由 `scripts/api/routes/dispatch.py` 中"使用风险"决策无 `--severity` 依赖，可保留旧路径作为内部别名。

## 1. 背景与问题

### 1.1 HostLLMBridge v2 与真实 TRAE IDE 监听方尚未联调（V4.5.5 顺延项）

V4.5.10 PRD §3.3 落地的 `tests/fakes/fake_host_runner_v2.py` 仅模拟 v2 监听方子进程。下列 5 项 v2 特性在真实上游场景下行为未经验证：

- 真实 TRAE IDE 监听方是否仅看 marker 7 字段就完成路由（避免读 request JSON）
- 真实监听方对独立 `prompt_file` 路径的处理（是否要求 `request_{id}.prompt` 命名约定）
- `subagent_type` 映射（`architect→search`，其他→`general_purpose_task`）真实调度链路
- `fuse_threshold=2` 连续 retriable 熔断在真实上游反馈下的触发
- 资源上限（`MAX_PROMPT_BYTES=512KB`）在真实 prompt 场景下未触发过

若 V4.5.10 默认切到 v2 后真实 TRAE IDE 监听方未按上游 v2.8.4 协议消费 marker，会出现"有 marker 但无 response"超时挂起。

### 1.2 SQLite 重立项条件缺乏可观测性（V4.5.10 P2-1 顺延项）

V4.5.10 P2-1 正式裁决 SQLite risk store 为 JSON-only long-term，仅当满足 4 条触发条件（容量 >10k / 复杂查询 / 远程共享 / 多服务并发）时重新立项。当前 4 条触发条件均无信号采集机制——若容量首次突破 10k，运维在被动收到"磁盘告警"前不会触发重新立项评估。

### 1.3 `risks --severity` 双重语义与 `--category` 重叠（V4.5.10 顺延项）

`scripts/cli_risks.py:_filter_risks` 中 `--severity` 同时承担两种语义：

- 数字模式：`--severity 0.6` → 等价于 `--min-exposure 0.6`（按 exposure 阈值过滤）
- 字符串模式：`--severity security` → 退化为 `--category security`（按 category 过滤）并打印 `WARNING: --severity category mode is deprecated; use --category`

数字模式与 `--min-exposure` 完全重叠；字符串模式已被 `--category` 覆盖。双重语义导致 CLI 帮助文档臃肿、用户认知负担，且与 V4.5.8 统一暴露语义不一致。
