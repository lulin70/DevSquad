## 2. 产品概述

### 2.1 背景

V4.5.2 已发布真实执行三路径（Host Bridge / 直接 API / Mock）+ 规模分级 + 性能基线，但 **"接通"的最后一公里未完成**：

- **MOKA provider**：当前通过 `OpenAIBackend(api_key=MOKA_API_KEY)` 隐式支持，缺乏显式 backend 类
- **运维可观察入口**：8 个 V4.5.2 Prometheus 指标已发射，但用户没有 CLI 命令直接查看
- **Connector 单点**：当前只支持 GitHub，对国内用户（GitLab 主流）和企业用户不友好
- **provider 自检**：用户接错 API key / 模型名后只能看到 dispatch 失败，缺乏友好自检命令
- **backend 切换**：当前 `DEVSQUAD_LLM_BACKEND` 环境变量需手工 export，没有项目级配置文件

### 2.2 目标

让用户从「安装 → 5 分钟内从 mock 切换到真实 LLM」全程可视化、可验证、可一键操作。

### 2.3 非目标

- 不新增第三个真实 LLM provider（DeepSeek/Mistral 等留给 V4.5.6 或更后）
- 不修改 dispatch 核心逻辑
- 不破坏 V4.5.1 接口兼容

**用户故事**：作为开发者，希望通过 `devsquad backend set moka` 一键切换到 MOKA AI 而无需关心 OpenAI 协议细节。

**功能需求**：

| ID | 描述 | 验收 |
|----|------|------|
| MOKA-1 | `MokaAIBackend` 类独立实现，路径 `"A"`，识别 `MOKA_API_KEY` | 单元测试覆盖 |
| MOKA-2 | 默认 `base_url=https://api.moka.ai/v1`，默认 `model=moka-gpt-5.5` | 单元测试断言 |
| MOKA-3 | `create_backend("moka", api_key=...)` 工厂方法支持 | 集成测试 |
| MOKA-4 | `is_available()` 检测 `MOKA_API_KEY` 环境变量 | 单元测试 |
| MOKA-5 | `path` 属性返回 `"A"` | 单元测试 |
| MOKA-6 | 复用 `OpenAIBackend` 的请求协议（OpenAI-compatible） | 代码复用 |

**交付**：
- `scripts/collaboration/moka_backend.py`（新增，~80 行）

## 5. 风险与回退

| 风险 | 影响 | 缓解 |
|------|------|------|
| MOKA API 不稳定 | P12.1 体验打磨延期 | simulation 模式兜底 + 5s 超时 + 默认 timeout=10s |
| GitLab API 差异 | Connector 不工作 | 先 stub simulation 模式 + api/cli 模式留 TODO 注释 |
| 配置文件格式错误 | backend 切换失效 | 启动时 schema 校验 + 失败 fallback 环境变量 |
| metrics CLI 性能 | prometheus_client 慢 | 单次调用，不开启 `--watch` 时无开销 |
