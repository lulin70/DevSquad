## 2. 背景与调查结论（P1-P3）

### 2.1 skills-index.json 注册机制核实（P2 调查结论）

全盘唯一 `skills-index.json` 位于 `~/.trae-cn/skills/skills-index.json`，它只是
trae-multi-agent 技能包的自描述安装清单（version/triggers/roles/installation），
**不是 TRAE 的技能注册表**。TRAE 的真实注册链路：

| 层 | 路径 | 作用 |
|---|---|---|
| 内置层 | `~/.trae-cn/builtin/manifests/*.json` → CDN package.zip | 官方技能下发（name/version/url/sha256） |
| 用户全局层 | `~/.trae/skills/<skill>/SKILL.md` | pack 结构，已被证实实际读取 |
| 工作区层 | `<工作区根>/.trae/skills/<skill>/SKILL.md` | V4.5.13 后 devsquad 唯一注册点 |
| 启停 | `skill-config.json`（用户级 + 工作区级） | disabledSkills / builtinSkillStatus |

**注册单元 = SKILL.md frontmatter（YAML）**；`skill-manifest.yaml` 是 DevSquad 自有格式，TRAE 不消费；`skills-index.json` 与 devsquad 注册无关。backlog"skills-index.json 注册机制核实"以本结论关闭，无需修改该文件。

### 2.2 关键缺陷：SKILL.md frontmatter YAML 解析失败（本 PRD 修复）

`SKILL.md` description 块第 16 行（`V4.5.11 — ...`）顶格书写，破坏 YAML block
scalar；配合第 17 行的裸冒号，`yaml.safe_load` 抛 `ScannerError`。后果：
frontmatter 解析失败 → **devsquad 不被 TRAE 注册 → "/" 面板看不到 DevSquad**。
这是 V4.5.13"/"面板问题诊断的漏网根因（当时只治理了重复副本与索引，未验证
frontmatter 可解析性）。

### 2.3 Prometheus 现状

`DevSquadMetrics`（prometheus_client）已在 api_server `/metrics` 暴露
`devsquad_v4512_risk_store_*` 等序列；既有测试覆盖 registry/导出层，但
**Prometheus 本体从未真实抓取过** ——「exposition 格式是否被 Prometheus 接受、
TSDB 查询是否命中」无证据。本机无 prometheus/promtool/docker，需 brew 安装。
