> 状态：✅ 收官（2026-08-31，tag `v4.5.11`；P12 复盘见 `docs/planning/V4.5.11_P12_RETROSPECTIVE.md`。范围裁决：Worker 保留双入口仅统一内部实现——v459 契约优先于 PRD 原文"强合并"表述）  
> 基线版本：V4.5.10（commit `34c2dfb` / tag `v4.5.10`）

## 0. 评审反馈与不可变决策

V4.5.10 收官后存在 4 项明确顺延项，本轮采用以下不可变决策：

1. **bridge 日志保留策略（PRUNE_MAX_FILES）**：v1 与 v2 目录在创建/响应/cleanup 任何写入路径完成后立即按 mtime 排序裁剪到最新 `PRUNE_MAX_FILES`（默认 100，含 `request_*.json` / `request_*.prompt` / `response_*.json`），超过即删除最旧条目。**不**计算体积、不**压缩**、不**改动 marker**。空文件不计入。可通过 `DEVSQUAD_BRIDGE_PRUNE_MAX_FILES` 显式覆盖；`0` 视为"禁用裁剪"，不**删除已有文件**。该策略对 v1/v2 同时生效，互不影响，跨版本目录永不串读。
2. **彻底删除 `_LegacyRiskStoreProxy`**：V4.5.7 引入的"内存 dict 通过 MutableMapping 适配 FileRiskStore"中间层，到 V4.5.10 已经没有外部调用者（grep 全仓库只在 `cli_risks.py` 与四份内部测试中自引用），删除类本身并把 `_RISK_STORE` 移除；测试改用 `FileRiskStore(root=DEFAULT_ROOT).load("default")` + `transaction("default")` 的等价接口。该删改为 V4.5.11 **Breaking**，CHANGELOG 显式标注。
3. **`Worker.execute` / `aexecute` 合并路径**：(a) 删除 `Worker._ado_work`，把全部 sync/async 后端选择、cache、流式写入统一到 `_do_work` 的 async 实现 `_do_work_async`；(b) `execute()` 改为同步壳：在 `loop.run_in_executor` 不可用时退化为裸 `_do_work_async` + `asyncio.run` 包装；(c) `aexecute()` 改为 native await + `_do_work_async`；(d) 共享 `_finalize_finding` / `_failure_result` 保持不变。**前置条件**：`EnhancedWorker.execute` 不变，`async_coordinator.AsyncWorkerWrapper.execute` 直接 `await self.worker.aexecute(task)`，已经满足；`coordinator._aexecute_parallel` 的 `hasattr(worker, "aexecute")` 分支恒成立。**潜在风险**：调用方若在同步线程里 await `Worker.execute()` 会因 `asyncio.run()` 嵌套失败 — 用单元测试 `test_worker_execute_sync_thread.py` 显式锁定"同步入口不依赖外部 loop"。
4. **risks CLI 输出一致化**：list/show/clear/add/export 五个子命令统一走 `_render_risks(risks, fmt)` 一个 helper，输出字段顺序、字段名（snake_case）、JSON 顶层结构（list=`[risk_dict]`，单条=`risk_dict`）、Markdown 表头（`Risk ID | Exposure | Probability | Impact | Status | Category`）全部由 helper 决定；子命令只负责"调用 + 打印"。`add` 改用与 list 同结构的 JSON 单条返回，**不**重复 `_risk_to_dict`。

## 1. 背景与问题

### 1.1 `logs/host_llm_bridge/` 无限增长

V4.5.10 验证后发现本地工作树已堆积 60+ 个 `request_*.json` + 1 个 stale `protocol.marker`。bridge 协议本身没有保留策略；运行超过一段时间后目录会无界增长，CI 沙箱偶发因磁盘占用失败。

### 1.2 `_LegacyRiskStoreProxy` 已成纯维护负担

V4.5.7 引入的适配层为了让旧 `_RISK_STORE` 调用者继续可用。V4.5.8 落地 FileRiskStore 后已经没有真实调用者；现存引用全部是 `tests/` 内部使用，删除后改写测试即可。

### 1.3 `Worker.execute` / `aexecute` 双路径重复

V4.5.9 抽出了 `_finalize_finding` / `_failure_result` 但 `_do_work` 与 `_ado_work` 仍然各自维护 prompt 拼装、cache、streaming、backend 分支。后续任一修改都要双倍评估。

### 1.4 `risks` CLI 输出风格漂移

list/show/add/exports 各自维护格式化代码，字段命名不一致（`exposure` vs `Exposure`、Markdown 表头行宽差异）；add 的输出比 list 少字段。

## 3. Wave 划分

### 3.1 Wave 1：bridge 日志保留策略

- 在 `HostLLMBridge` 与 `HostLLMBridgeV2` 引入模块级 `PRUNE_MAX_FILES = 100`（默认）+ `_prune_old_files(bridge_dir, max_files)` helper
- `create_request` 写完 3 文件后调用；`write_response` 写完 response 后调用；`_cleanup_request_files` 完成后调用
- v1/v2 各自独立计数；跨版本隔离
- 新增 `tests/unit/test_v4511_bridge_prune.py`：默认 100、env override 0、跨版本隔离、marker/prompt/tmp 不计入
- `tests/e2e/test_host_bridge_v2_e2e.py` 与 `tests/e2e/test_host_bridge_e2e.py` 验证 E2E 路径不破坏

### 3.2 Wave 2：删除 `_LegacyRiskStoreProxy`

- `scripts/cli_risks.py` 移除 `_LegacyRiskStoreProxy` 类与 `_RISK_STORE` 模块变量
- `cmd_risks_clear` / `cmd_risks_add` / `cmd_risks_export` / `cmd_risks_list` / `cmd_risks_show` 全部直接用 `FileRiskStore`
- 测试替换 `_RISK_STORE.clear()` → `FileRiskStore(root=tmp_path).transaction("default")["items"] = []`
- CHANGELOG 标记 Breaking；文档加注历史条目

### 3.3 Wave 3：Worker.execute / aexecute 合并

- `scripts/collaboration/worker.py`：
  - 删除 `_ado_work`
  - 新增 `async def _do_work_async(self, context)` 合并 backend 分支 + cache + streaming
  - `execute()` 改为：`if asyncio.get_event_loop_policy()._local._loop is None: return asyncio.run(self._do_work_async(context))`（简化版；详细路径在 `_execute_sync_wrapper`）
  - `aexecute()` 改为 `await self._do_work_async(context)`
- `tests/unit/test_worker_execute_sync_thread.py` 新增：验证同步线程里 execute() 不依赖外部 loop
- `tests/unit/test_v459_worker_async.py` 必须零修改通过

### 3.4 Wave 4：risks CLI 输出统一

- `scripts/cli_risks.py`：
  - 删 `add_risk` 内部 `_risk_to_dict` 重复调用，统一 `print(json.dumps(render(risks)[0], ensure_ascii=False))`
  - 删 `_format_markdown` 与 `_format_json` 中的字段顺序漂移；统一 `_render_risks(risks, fmt)`
  - 删 `_format_markdown_risk` 改为 `_render_risk(risk, fmt)`
- `tests/unit/test_cli_risks.py` 增字段顺序测试
- `tests/e2e/test_risks_cli_e2e.py` 快照测试更新一次后稳定

### 3.5 不在本版范围

- SQLite risk store 重新立项（维持 V4.5.10 裁决 JSON-only long-term）
- `WorkerPool.acquire` 内部仍调用 `worker.execute`（同步语义已合并）
- 网络 listener / 端口暴露 / 远程信任模型

## 5. 安全与运行风险登记

| ID | 风险 | 概率 | 影响 | 缓解 |
|---|---|---:|---:|---|
| R-PR | PRUNE 误删当前进行中的请求文件 | 低 | 高 | 只剪裁超过上限的旧 mtime 文件；当前请求最新写入不会被剪 |
| R-PR2 | env override = 0 实际是禁用而非保留 | 低 | 中 | 文档明示 0 = 禁用；测试 lock 行为 |
| R-LP | 外部脚本仍引用 `_RISK_STORE` | 低 | 中 | grep 验证零引用；CHANGELOG 显式 Breaking |
| R-W | Worker.execute 同步线程内调 asyncio.run 嵌套失败 | 中 | 高 | 路径探测：检测已有 loop 时走 run_in_executor，否则直接 asyncio.run |
| R-W2 | EnhancedWorker 行为漂移 | 低 | 中 | 子类测试覆盖 execute 仍走 super |
| R-R | risks CLI JSON 输出字段顺序漂移影响下游解析 | 低 | 中 | 字段顺序用 OrderedDict 锁定 |
| R-DOC | 删除符号遗漏文档说明 | 中 | 低 | CHANGELOG + 版本历史 + V4.5.7 release notes 加注 |
