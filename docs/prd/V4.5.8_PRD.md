## 1. 背景与问题

### 1.1 V4.5.7 现状（3 项遗留缺口）

V4.5.7 P12_RETROSPECTIVE §8 backlog 4 项：
- ✅ P0 AsyncCoeffectResolver — 已完成
- ✅ P1 devsquad risks UX CLI — 已完成
- ⏭️ P0 dispatcher.py → asyncio.gather — **本次拆分推迟**：架构师评分 5.5/10，AsyncWorkerWrapper 仍走 `run_in_executor`，默认替换会破坏同步调用边界与 11-Phase 生命周期
- ⏭️ P1 _RISK_STORE 文件持久化 — **本次纳入**：跨进程风险共享、审批追溯、CI/CD 集成强需求
- ⏭️ P2 risks CLI 增量命令 — **本次纳入**：Python API 已存在 (`add/assess/mitigate/track`)，CLI 缺位形成 asymmetric UX
- ⏭️ P2 `--severity` 升级为 exposure 阈值 — **本次纳入**：当前 category 字符串匹配语义与 `UnifiedGateEngine._check_risk` 的 `r.exposure >= 0.36` 数值语义脱节

### 1.2 关键痛点

#### P1: 跨进程风险共享缺失

`scripts/cli_risks.py:115-128` 当前 `_RISK_STORE` 是模块级 dict, 仅进程内共享. 用户工作流 `devsquad risks add` 后 `devsquad risks list` 在新进程返回空, 因为 dict 被重置. `RiskRegister` 类文档注释自称为 "Persistent risk register", 但实际是纯内存字典——文档与实现脱节.

#### P2: CLI 与 Python API 不对称

Python API 已提供 `RiskRegister.add/assess/mitigate/track(risk_id, CLOSED)` 4 个写方法, 但 `cli_risks.py:249-290` 仅暴露 `list/show/clear/export` 4 个读命令——用户无法从 shell 写入/更新风险状态.

#### P2: `--severity` 语义错位

`cli_risks.py:163-165` 当前实现是 category 字符串匹配, 而 `UnifiedGateEngine._check_risk` (line 849-905) 用的是 `r.exposure >= 0.36` 数值阈值. 两套语义必须显式对齐.

### 1.3 不做项（明确 out-of-scope）

| 项 | 推迟到 | 原因 |
|---|---|---|
| `Coordinator._execute_parallel` 默认替换为 `asyncio.gather` | V4.5.9 | 7-Role 5.99/10 不通过门禁 |
| `Worker.execute` 改造为 `async def` | V4.5.10 | LLM HTTP 仍同步阻塞, 需切换至 `httpx.AsyncClient` |
| `_RISK_STORE` 改为 SQLite | V4.5.9+ | JSON 文件足以覆盖 ≤10000 风险条目场景 |
| 多用户风险协作（remote store） | 暂未规划 | 需要 server 化, 超出 Skill 边界 |

## 3. 范围与子任务

### 3.1 Wave 1：File-backed Risk Store（约 30 测试）

新模块 `scripts/collaboration/file_risk_store.py`：

```
class FileRiskStore:
    """跨进程文件持久化的 RiskRegister 后端.

    路径: .devsquad_data/risks/<register_id>.json
    锁:   fcntl.flock (Unix) / msvcrt (Windows) 跨进程排它锁
    写:   tmp file + os.replace() 原子替换
    并发: 整个 read-modify-write 在锁内
    """
```

`RiskRegister` 改造（`scripts/collaboration/risk_register.py`）：
- `add/assess/mitigate/track` 改为可选 `store` 参数
- 提供 `RiskRegister.from_store(store, register_id)` 工厂方法
- 保留纯内存模式（`store=None`）保证向后兼容

`cli_risks.py` 改造：
- `_get_register()` 改为 `_get_register(register_id="default")`
- 跨命令共享通过 `FileRiskStore.transaction(register_id)` 实现
- 删除模块级 `_RISK_STORE` dict

### 3.2 Wave 2：CLI 增量命令（约 25 测试）

新增子命令（`scripts/cli_risks.py`）：
- `cmd_risks_add`
- `cmd_risks_assess`
- `cmd_risks_mitigate`
- `cmd_risks_close`

参数规范：
```bash
devsquad risks add "data loss" --probability 0.7 --impact 0.9 --category technical
devsquad risks assess R-abc123 --votes '{"architect":[0.6,0.8]}'
devsquad risks mitigate R-abc123 --strategy mitigate --owner devops --plan "add backup"
devsquad risks close R-abc123 --require-approval
```

ApprovalGate 改造：
- `clear` 和 `close` 默认 `require_approval=True`
- 当 `approval_callback=None` 且用户显式 `--require-approval` 时, **fail-closed**（exit 2 + "approval unavailable"）
- `add` / `assess` / `mitigate` / `list` / `show` / `export` 不触发审批

### 3.3 Wave 3：exposure 阈值过滤（约 15 测试）

argparse 改造：
```python
p_list.add_argument("--min-exposure", type=float, help="Minimum exposure (0.0-1.0)")
p_list.add_argument("--severity", help="DEPRECATED: use --min-exposure or --category")
p_list.add_argument("--category", help="Filter by category (e.g. technical/security)")
```

过滤逻辑支持三种模式：
- `--min-exposure FLOAT`: 数值阈值 `r.exposure >= float`
- `--severity FLOAT`: 兼容数值模式
- `--severity P0/P1/P2/P3` / `--category STRING`: legacy 字符串模式（标 deprecation）

### 3.4 不在本版范围

- `Coordinator._execute_parallel` asyncio.gather 默认迁移
- `_RISK_STORE` SQLite 化
- 多用户 remote store
- `--severity` P0/P1/P2/P3 旧模式删除（保留 + 标 deprecated）
