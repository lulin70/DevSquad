## 1. 背景 (Background)

V4.5.2 解决了"用起来"问题——补完 LLM provider 矩阵 + 提供运维可观察入口 + 第二个 connector。但用户真实使用中发现 3 个痛点：

1. **产出物散落**：Worker 完成后产出的 PRD/补丁/测试/报告等"工件"目前只存在 Scratchpad 内存中，dispatch 失败/进程退出后丢失。
2. **副作用无回滚**：dispatch 失败时，已产生的 side effect（写入文件、创建 PR）无法撤销，导致 dispatch 处于半成品状态。
3. **审计日志不可触达**：DispatchAuditLogger 写入 SQLite，但用户无法直接查看，只能通过 dispatch 路径间接获取。

V4.5.3 = **Artifacts + Effect** 解决上述 3 个痛点。

## 4. 详细规格 (Detailed Specs)

### P12.2.1 — ArtifactStore

**职责**: 持久化 7 角色 worker 产出的所有"工件"到 `artifacts/{session_id}/{role}/{filename}` 命名空间。

**API**:
```python
class ArtifactStore:
    def write(self, session_id: str, role_id: str, filename: str, content: str | bytes, *, kind: str = "text") -> Artifact:
        """写入工件并返回 Artifact 描述符（含 SHA-256 + path + size）。"""

    def read(self, artifact_id: str) -> Artifact:
        """根据 artifact_id 读取工件内容。"""

    def list(self, session_id: str, *, role_id: str | None = None) -> list[Artifact]:
        """列出某 session 的所有工件，可按 role 过滤。"""

    def delete(self, artifact_id: str) -> bool:
        """删除工件（仅当同时删除关联 effect 时）。"""
```

**存储**:
- 位置: `artifacts/{session_id}/{role_id}/{filename}` (相对项目根)
- 清单: `artifacts/{session_id}/manifest.json` 记录所有工件
- 忽略: `.gitignore` 增加 `artifacts/**` (P12.2.1 验收前)
- 内容: 文本或二进制 (`kind` 字段标识)

**Anti-Ghost**: `_call_counter` 暴露 `get_call_counter()`。

### P12.2.2 — Worker 写 Artifact

**改动**: `scripts/collaboration/worker.py` 在 `execute()` 末尾 `write_finding()` 后调 `ArtifactStore.write()` 持久化产出。

**契约**:
- Worker 完成 finding → 同步写 artifact (session_id=task.session_id, role_id=self.role_id, filename=f"{task.task_id}.md")
- 写失败时不影响 Worker 成功状态（artifact 是 best-effort 持久化）
- Anti-Ghost: Worker.execute() 完成后 `artifact_store._call_counter` +1

**测试**: mock artifact_store，验证调用参数 + 失败场景不影响 WorkerResult。

### P12.2.3 — DispatchEffect Protocol

**职责**: 抽象"副作用可回滚"协议。

**协议**:
```python
class DispatchEffect(Protocol):
    def apply(self, ctx: EffectContext) -> EffectOutcome: ...
    def revert(self, ctx: EffectContext) -> EffectOutcome: ...
```

**P12.2 初始类型集合**（仅文件系统操作）:
- `WriteFileEffect` (创建/覆盖文件)
- `DeleteFileEffect` (删除文件，revert 恢复)
- `RenameFileEffect` (重命名)

**EffectContext** 字段:
- `effect_id: str`
- `effect_type: str`
- `payload: dict[str, Any]` (如 {path, content, original_path})
- `applied_at: float`

**EffectOutcome** 字段:
- `success: bool`
- `error: str | None`
- `side_data: dict[str, Any]` (如 SHA-256 hash)

**Anti-Ghost**: EffectRegistry 暴露 `get_call_count()`。

### P12.2.4 — EffectRegistry

**职责**: dispatch 失败时按 LIFO 自动回滚所有已应用 effect。

**API**:
```python
class EffectRegistry:
    def apply(self, effect: DispatchEffect, ctx: EffectContext) -> EffectOutcome:
        """应用 effect 并记录到 LIFO 栈。"""

    def revert_all(self) -> list[EffectOutcome]:
        """按 LIFO 顺序回滚所有 effect，幂等。"""

    def revert_last(self) -> EffectOutcome | None:
        """回滚最近一个 effect。"""

    def pending_count(self) -> int:
        """当前未回滚的 effect 数。"""
```

**回滚失败处理**:
- 记录 warning log 但不中断
- 提供 `force_revert()` 兜底，revert 失败也吞掉
- 暴露 Prometheus 指标 `devsquad_v453_effect_revert_failures_total`

**测试**: 模拟"dispatch 失败"场景，验证 LIFO 顺序 + 失败 effect 不阻塞其他 effect revert。

### P12.2.5 — Artifact↔Effect 绑定

**职责**: 每次 ArtifactStore 写入时记 effect，删除/重命名可回滚。

**实现**:
- `ArtifactStore.write()` 内部创建 `WriteFileEffect` 并注册到全局 `EffectRegistry`
- `ArtifactStore.delete()` 等价于"删除文件 effect"（自动注册）
- `ArtifactStore.rename(session_id, old, new)` = RenameFileEffect

**契约**:
- Effect payload 包含 artifact_id + path
- 失败时 revert 删除已写入文件

**测试**: 验证 dispatch 失败后，artifact 文件被自动删除。

### P12.2.6 — Audit CLI

**职责**: 暴露 dispatch 审计日志为可读 CLI。

**API**:
```bash
devsquad audit                  # 默认最近 20 条
devsquad audit --limit 100      # 指定条数
devsquad audit --format json    # JSON 输出
devsquad audit --event-type dispatch_start  # 按类型过滤
devsquad audit --verify         # 验证哈希链完整性
```

**Anti-Ghost**: `get_call_counter()`。

**测试**: mock DispatchAuditLogger，验证参数透传 + verify 模式检测篡改。
