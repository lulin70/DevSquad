## 三、P1-1 多语言角色 prompt

### 3.1 需求

**用户故事**: 作为非中文用户，当我用英文或日文提交任务时，希望角色（architect/security/tester 等）的 system prompt 也使用我的语言，以便 LLM 输出更自然。

**当前状态**:
- `ROLE_REGISTRY` 的 7 个角色 prompt 全部是中文（如 "你是系统架构师。负责：..."）
- `I18N` dict 已有 zh/en/ja 报告标签翻译
- `DispatchResult.lang` 字段存在但只影响报告标签，不影响角色 prompt
- `IntentWorkflowMapper` 已支持 6 意图 × 3 语言

**目标**: 角色能根据 `lang` 参数返回对应语言的 prompt 和 name。

### 3.2 设计

**方案**: 在 `RoleDefinition` 增加 `prompt_i18n: dict[str, str]` 和 `name_i18n: dict[str, str]` 字段，默认空 dict（向后兼容）。提供 `get_localized_prompt(lang)` 和 `get_localized_name(lang)` 方法。`zh` 回退到现有 `prompt`/`name` 字段。

**修改文件**:
1. `scripts/collaboration/models_dispatch.py` (~70 行)
   - `RoleDefinition` 增加 `prompt_i18n` 和 `name_i18n` 字段
   - 增加 `get_localized_prompt(lang)` 和 `get_localized_name(lang)` 方法
   - 为 7 个角色补全 EN/JP prompt 和 name
2. `scripts/collaboration/dispatch_models.py` (~15 行)
   - `ROLE_TEMPLATES` 增加 `prompt_i18n` 和 `name_i18n` 字段
   - `_format_worker_results` 使用 `lang` 本地化角色名
3. `scripts/collaboration/worker.py` (~10 行)
   - Worker 使用 `get_localized_prompt(lang)` 而非 `prompt`
4. `scripts/collaboration/prompt_assembler.py` (~15 行)
   - 组装 prompt 时使用本地化版本

**向后兼容**: `prompt_i18n` 默认空 dict，`get_localized_prompt("zh")` 回退到 `self.prompt`。现有测试零回归。

**防幽灵**: 模块级 `_call_counter` 验证 `get_localized_prompt` 被实际调用。

### 3.3 验收标准

| AC | 描述 | 验证方式 |
|----|------|---------|
| AC-1 | 7 角色 × 3 语言 prompt 全部存在 | 单元测试断言 `len(prompt_i18n) == 2` (en+ja, zh 是默认) |
| AC-2 | dispatch 中文任务 → 角色 prompt 是中文 | E2E 断言 worker 收到的 prompt 含 "架构师" |
| AC-3 | dispatch 英文任务 → 角色 prompt 是英文 | E2E 断言 worker 收到的 prompt 含 "Architect" |
| AC-4 | dispatch 日文任务 → 角色 prompt 是日文 | E2E 断言 worker 收到的 prompt 含 "アーキテクト" |
| AC-5 | 向后兼容：prompt_i18n 为空时回退到 prompt | 单元测试空 dict 回退 |
| AC-6 | 防幽灵：get_localized_prompt 被调用 | `_call_counter > 0` |

## 四、P1-2 Dashboard 可见性增强

### 4.1 需求

**用户故事**: 作为 Dashboard 用户，我希望 dispatch 结果能分章节展示（Worker Outputs / Consensus / Risk Management / Retrospective），而不是一个长 Markdown，方便快速定位信息。

**当前状态**: `render_dispatch_result()` 只显示 `result.summary or result.to_markdown()` 一个大 Markdown 块。

### 4.2 设计

**方案**: 在 `render_dispatch_result` 中增加 Tab 页，分章节展示。复用现有 `DispatchResult` 字段，不新增数据结构。

**修改文件**:
1. `scripts/dashboard/dispatch_views.py` (~80 行)
   - 增加 Tab: Worker Outputs / Consensus / Risk / Retrospective / Full Report
   - Worker Outputs: 遍历 `result.worker_results` 分卡片展示
   - Consensus: 展示 `result.consensus_records`
   - Risk: 展示 `result.risk_management_md`
   - Retrospective: 展示 `result.retrospective_report`

**向后兼容**: 原有 "Formatted Report" 和 "Raw Data" Tab 保留，新增 Tab 是追加。

### 4.3 验收标准

| AC | 描述 | 验证方式 |
|----|------|---------|
| AC-1 | Dashboard 有 5+ Tab 页 | 集成测试断言 Tab 数量 |
| AC-2 | Worker Outputs Tab 展示每个角色输出 | 集成测试断言渲染 |
| AC-3 | Risk Management Tab 展示 risk_management_md | 集成测试断言 |
| AC-4 | 原有 Formatted Report Tab 保留 | 回归测试 |
